[[actuator.metrics.getting-started]]
== Bắt đầu

Spring Boot auto-configure một composite javadoc:io.micrometer.core.instrument.MeterRegistry[] và thêm một registry vào composite cho mỗi implementation được hỗ trợ tìm thấy trên classpath.
Chỉ cần có dependency `micrometer-registry-\{system}` trên runtime classpath là đủ để Spring Boot configure registry.

Phần lớn registry có các feature chung.
Ví dụ, bạn có thể disable một registry cụ thể ngay cả khi implementation của Micrometer registry có trên classpath.
Ví dụ sau disable Datadog:

[configprops,yaml]
----
management:
  datadog:
    metrics:
      export:
        enabled: false
----

Bạn cũng có thể disable mọi registry, trừ khi registry-specific property quy định khác, như trong ví dụ sau:

[configprops,yaml]
----
management:
  defaults:
    metrics:
      export:
        enabled: false
----

Spring Boot cũng thêm mọi registry được auto-configure vào global static composite registry trên class javadoc:io.micrometer.core.instrument.Metrics[], trừ khi bạn explicit disable hành vi này:

[configprops,yaml]
----
management:
  metrics:
    use-global-registry: false
----

NOTE: Trong test dùng `spring-boot-micrometer-metrics-test`, global registry mặc định bị disable.
Nếu muốn dùng global registry trong test như vậy, hãy annotate test bằng javadoc:org.springframework.boot.micrometer.metrics.test.autoconfigure.AutoConfigureMetrics[format=annotation] với `useGlobalRegistry = true`, hoặc explicit set property configprop:management.metrics.use-global-registry[] thành `true`.

Bạn có thể register bất kỳ số lượng bean javadoc:org.springframework.boot.micrometer.metrics.autoconfigure.MeterRegistryCustomizer[] nào để configure thêm registry, chẳng hạn apply common tag, trước khi bất kỳ meter nào được register vào registry:

include-code::commontags/MyMeterRegistryConfiguration[]

Bạn có thể apply customization cho implementation cụ thể của registry bằng cách chỉ rõ generic type cụ thể hơn:

include-code::specifictype/MyMeterRegistryConfiguration[]

Spring Boot cũng xref:actuator/metrics.adoc#actuator.metrics.supported[configure built-in instrumentation] mà bạn có thể control thông qua configuration hoặc dedicated annotation marker.

[[actuator.metrics.export]]
== Monitoring System Được Hỗ Trợ

Phần này mô tả ngắn gọn từng monitoring system được hỗ trợ.

[[actuator.metrics.export.atlas]]
=== Atlas

Mặc định, metrics được export tới {url-micrometer-docs-implementations}/atlas[Atlas] đang chạy trên local machine.
Bạn có thể cung cấp location của https://github.com/Netflix/atlas[Atlas server]:

[configprops,yaml]
----
management:
  atlas:
    metrics:
      export:
        uri: "https://atlas.example.com:7101/api/v1/publish"
----

[[actuator.metrics.export.datadog]]
=== Datadog

Datadog registry định kỳ push metrics tới https://www.datadoghq.com[datadoghq].
Để export metrics tới {url-micrometer-docs-implementations}/datadog[Datadog], bạn phải cung cấp API key:

[configprops,yaml]
----
management:
  datadog:
    metrics:
      export:
        api-key: "YOUR_KEY"
----

Nếu cung cấp thêm application key (optional), metadata như meter description, type và base unit cũng sẽ được export:

[configprops,yaml]
----
management:
  datadog:
    metrics:
      export:
        api-key: "YOUR_API_KEY"
        application-key: "YOUR_APPLICATION_KEY"
----

Mặc định, metrics được gửi tới https://docs.datadoghq.com/getting_started/site[Datadog US site] (`https://api.datadoghq.com`).
Nếu Datadog project của bạn được host trên site khác hoặc bạn cần gửi metrics qua proxy, hãy configure URI tương ứng:

[configprops,yaml]
----
management:
  datadog:
    metrics:
      export:
        uri: "https://api.datadoghq.eu"
----

Bạn cũng có thể thay đổi interval gửi metrics tới Datadog:

[configprops,yaml]
----
management:
  datadog:
    metrics:
      export:
        step: "30s"
----

[[actuator.metrics.export.dynatrace]]
=== Dynatrace

Dynatrace cung cấp hai metrics ingest API, cả hai đều được implement cho {url-micrometer-docs-implementations}/dynatrace[Micrometer].
Bạn có thể xem Dynatrace documentation về Micrometer metrics ingest {url-dynatrace-docs-shortlink}/micrometer-metrics-ingest[tại đây].

Configuration property trong namespace `v1` chỉ áp dụng khi export tới {url-dynatrace-docs-shortlink}/api-metrics[Timeseries v1 API].
Support cho V1 API đã deprecated.

Configuration property trong namespace `v2` chỉ áp dụng khi export tới {url-dynatrace-docs-shortlink}/api-metrics-v2-post-datapoints[Metrics v2 API].

Integration chỉ có thể export tới `v1` hoặc `v2` tại một thời điểm; `v2` được khuyến nghị mạnh vì v1 đã deprecated.
Nếu `device-id` được set trong namespace `v1` (bắt buộc với v1 nhưng không được dùng ở v2), metrics sẽ được export tới endpoint `v1`.
Nếu không, `v2` được dùng mặc định.

[[actuator.metrics.export.dynatrace.v2-api]]
==== v2 API

Bạn có thể dùng v2 API theo hai cách.

[[actuator.metrics.export.dynatrace.v2-api.auto-config]]
===== Auto-configuration

Dynatrace auto-configuration có sẵn cho các host được OneAgent hoặc Dynatrace Operator for Kubernetes monitor.

**Local OneAgent:** Nếu OneAgent đang chạy trên host, metrics được tự động export tới {url-dynatrace-docs-shortlink}/local-api[local OneAgent ingest endpoint].
Ingest endpoint forward metrics tới Dynatrace backend.

**Dynatrace Kubernetes Operator:** Khi chạy Kubernetes với Dynatrace Operator đã được cài đặt, registry sẽ tự động lấy endpoint URI và API token từ operator.

Đây là behavior mặc định và không cần setup đặc biệt ngoài dependency `io.micrometer:micrometer-registry-dynatrace`.

[[actuator.metrics.export.dynatrace.v2-api.manual-config]]
===== Cấu hình thủ công

Nếu không có auto-configuration, cần endpoint của {url-dynatrace-docs-shortlink}/api-metrics-v2-post-datapoints[Metrics v2 API] và API token.
{url-dynatrace-docs-shortlink}/api-authentication[API token] phải có permission "`Ingest metrics`" (`metrics.ingest`).
Bạn nên giới hạn scope của token chỉ ở permission này.
Endpoint URI phải chứa path, ví dụ `/api/v2/metrics/ingest`.

URL của Metrics API v2 ingest endpoint khác nhau tùy deployment option:

* SaaS: `+https://{your-environment-id}.live.dynatrace.com/api/v2/metrics/ingest+`
* Managed deployments: `+https://{your-domain}/e/{your-environment-id}/api/v2/metrics/ingest+`

Ví dụ sau configure metrics export bằng environment id `example`:

[configprops,yaml]
----
management:
  dynatrace:
    metrics:
      export:
        uri: "https://example.live.dynatrace.com/api/v2/metrics/ingest"
        api-token: "YOUR_TOKEN"
----

Khi dùng Dynatrace v2 API, các optional feature sau có sẵn (xem thêm chi tiết trong {url-dynatrace-docs-shortlink}/micrometer-metrics-ingest#dt-configuration-properties[Dynatrace documentation]):

* Metric key prefix: Đặt prefix được prepend vào mọi exported metric key.
* Enrich with Dynatrace metadata: Nếu OneAgent hoặc Dynatrace operator đang chạy, enrich metrics bằng metadata bổ sung, chẳng hạn host, process hoặc pod.
* Default dimensions: Chỉ định các key-value pair được thêm vào mọi exported metric.
Nếu Micrometer chỉ định tag có cùng key, tag đó sẽ override default dimension.
* Use Dynatrace Summary instruments: Trong một số trường hợp, Micrometer Dynatrace registry tạo ra metrics bị reject.
Micrometer 1.9.x đã fix việc này bằng cách giới thiệu Dynatrace-specific summary instrument.
Set toggle này thành `false` sẽ buộc Micrometer fallback về behavior mặc định trước 1.9.x.
Chỉ nên dùng khi gặp vấn đề trong quá trình migrate từ Micrometer 1.8.x sang 1.9.x.
* Export meter metadata: Từ Micrometer 1.12.0, Dynatrace exporter cũng mặc định export meter metadata, chẳng hạn unit và description.
Dùng toggle `export-meter-metadata` để tắt feature này.

Bạn có thể không cần chỉ định URI và API token, như trong ví dụ sau.
Trong trường hợp này, endpoint được auto-configure sẽ được dùng:

[configprops,yaml]
----
management:
  dynatrace:
    metrics:
      export:
        # Chỉ định uri và api-token ở đây nếu không dùng local OneAgent endpoint.
        v2:
          metric-key-prefix: "your.key.prefix"
          enrich-with-dynatrace-metadata: true
          default-dimensions:
            key1: "value1"
            key2: "value2"
          use-dynatrace-summary-instruments: true # (default: true)
          export-meter-metadata: true             # (default: true)
----

[[actuator.metrics.export.dynatrace.v1-api]]
==== v1 API (Đã deprecated)

Dynatrace v1 API metrics registry định kỳ push metrics tới configured URI bằng {url-dynatrace-docs-shortlink}/api-metrics[Timeseries v1 API].
Để backward-compatible với các setup hiện có, khi `device-id` được set (bắt buộc với v1 nhưng không dùng ở v2), metrics sẽ được export tới Timeseries v1 endpoint.
Để export metrics tới {url-micrometer-docs-implementations}/dynatrace[Dynatrace], bạn phải cung cấp API token, device ID và URI:

[configprops%novalidate,yaml]
----
management:
  dynatrace:
    metrics:
      export:
        uri: "https://{your-environment-id}.live.dynatrace.com"
        api-token: "YOUR_TOKEN"
        v1:
          device-id: "YOUR_DEVICE_ID"
----

Với v1 API, bạn phải specify base environment URI không có path vì v1 endpoint path được thêm tự động.

[[actuator.metrics.export.dynatrace.version-independent-settings]]
==== Cài đặt không phụ thuộc version

Ngoài API endpoint và token, bạn cũng có thể thay đổi interval gửi metrics tới Dynatrace.
Default export interval là `60s`.
Ví dụ sau set export interval thành 30 giây:

[configprops,yaml]
----
management:
  dynatrace:
    metrics:
      export:
        step: "30s"
----

Xem thêm thông tin về cách setup Dynatrace exporter cho Micrometer trong {url-micrometer-docs-implementations}/dynatrace[Micrometer documentation] và {url-dynatrace-docs-shortlink}/micrometer-metrics-ingest[Dynatrace documentation].

[[actuator.metrics.export.otlp]]
=== OTLP

Mặc định, metrics được export qua {url-micrometer-docs-implementations}/otlp[OpenTelemetry protocol (OTLP)] tới consumer đang chạy trên local machine.
Để export tới location khác, hãy cung cấp https://opentelemetry.io/[OTLP metrics endpoint] bằng configprop:management.otlp.metrics.export.url[]:

[configprops,yaml]
----
management:
  otlp:
    metrics:
      export:
        url: "https://otlp.example.com:4318/v1/metrics"
----

Bạn cũng có thể cung cấp custom header, chẳng hạn header dùng cho authentication, bằng các property configprop:management.otlp.metrics.export.headers.*[].

Nếu bean `OtlpMetricsSender` available, bean này sẽ được configure trên `OtlpMeterRegistry` mà Spring Boot auto-configure.

https://opentelemetry.io/docs/specs/otel/metrics/data-model/#exemplars[OTLP Exemplars] cũng được hỗ trợ.
Để enable feature này, cần có bean javadoc:io.micrometer.registry.otlp.ExemplarContextProvider[].
Nếu dùng xref:actuator/tracing.adoc[Micrometer Tracing], bean này sẽ được auto-configure.
Mặc định, chỉ sampled trace được include làm exemplar.
Bạn có thể control behavior này bằng configprop:management.tracing.exemplars.include[].

[[actuator.metrics.export.prometheus]]
=== Prometheus

{url-micrometer-docs-implementations}/prometheus[Prometheus] dự kiến sẽ scrape hoặc poll từng application instance để lấy metrics.
Spring Boot cung cấp actuator endpoint `/actuator/prometheus` để present https://prometheus.io[Prometheus scrape] theo đúng format.

TIP: Mặc định endpoint không available và phải được expose. Xem xref:actuator/endpoints.adoc#actuator.endpoints.exposing[exposing endpoints] để biết thêm chi tiết.

Ví dụ sau thêm `scrape_config` vào `prometheus.yml`:

[source,yaml]
----
scrape_configs:
- job_name: "spring"
  metrics_path: "/actuator/prometheus"
  static_configs:
  - targets: ["HOST:PORT"]
----

https://prometheus.io/docs/prometheus/latest/feature_flags/#exemplars-storage[Prometheus Exemplars] cũng được hỗ trợ.
Để enable feature này, cần có bean javadoc:io.prometheus.metrics.tracer.common.SpanContext[].
Nếu dùng deprecated Prometheus simpleclient support và muốn enable feature này, cần có bean javadoc:io.prometheus.client.exemplars.tracer.common.SpanContextSupplier[].
Nếu dùng {url-micrometer-tracing-docs}[Micrometer Tracing], bean sẽ được auto-configure, nhưng bạn luôn có thể tự tạo bean nếu muốn.
Mặc định, chỉ sampled trace được include làm exemplar.
Bạn có thể control behavior này bằng configprop:management.tracing.exemplars.include[].
Prometheus không hỗ trợ value `all`.
Xem https://prometheus.io/docs/prometheus/latest/feature_flags/#exemplars-storage[Prometheus Docs], vì feature này cần được explicit enable ở phía Prometheus và chỉ hỗ trợ format https://github.com/OpenObservability/OpenMetrics/blob/v1.0.0/specification/OpenMetrics.md#exemplars[OpenMetrics].

Với ephemeral hoặc batch job có thể không tồn tại đủ lâu để được scrape, bạn có thể dùng https://github.com/prometheus/pushgateway[Prometheus Pushgateway] để expose metrics cho Prometheus.

Để enable Prometheus Pushgateway support, thêm dependency sau vào project:

[source,xml]
----
<dependency>
	<groupId>io.prometheus</groupId>
	<artifactId>prometheus-metrics-exporter-pushgateway</artifactId>
</dependency>
----

Khi Prometheus Pushgateway dependency có trên classpath và property configprop:management.prometheus.metrics.export.pushgateway.enabled[] được set thành `true`, bean javadoc:org.springframework.boot.micrometer.metrics.export.prometheus.PrometheusPushGatewayManager[] sẽ được auto-configure.
Bean này quản lý việc push metrics tới Prometheus Pushgateway.

Bạn có thể tune javadoc:org.springframework.boot.micrometer.metrics.export.prometheus.PrometheusPushGatewayManager[] bằng các property dưới `management.prometheus.metrics.export.pushgateway`.
Với advanced configuration, bạn cũng có thể cung cấp bean javadoc:org.springframework.boot.micrometer.metrics.export.prometheus.PrometheusPushGatewayManager[] của riêng mình.

[[actuator.metrics.export.simple]]
=== Simple

Micrometer có một simple in-memory backend được tự động dùng làm fallback nếu không có registry nào khác được configure.
Điều này cho phép xem các metrics được collect trong xref:actuator/metrics.adoc#actuator.metrics.endpoint[metrics endpoint].

In-memory backend tự disable ngay khi bạn dùng backend khác.
Bạn cũng có thể explicit disable backend này:

[configprops,yaml]

management:
  simple:
    metrics:
      export:
        enabled: false

management:

management:

Bạn có thể cung cấp host, port và protocol cần dùng bằng:

[configprops,yaml]

management:

management:

== Metrics và Meter Được Hỗ Trợ

Spring Boot cung cấp automatic meter registration cho nhiều technology.
Trong phần lớn trường hợp, default cung cấp các metrics hợp lý có thể được publish tới bất kỳ monitoring system nào được hỗ trợ.

[[actuator.metrics.supported.jvm]]

Auto-configuration enable JVM Metrics bằng core Micrometer class.
JVM metrics được publish dưới meter name `jvm.`.

Các JVM metrics sau được cung cấp:

* Nhiều detail về memory và buffer pool
* Statistics liên quan đến garbage collection
* Thread utilization
* https://docs.micrometer.io/micrometer/reference/reference/jvm.html#_java_21_metrics[Virtual threads statistics] (cần `io.micrometer:micrometer-java21` trên classpath)

* JIT compilation time

Auto-configuration enable system metrics bằng core Micrometer class.
System metrics được publish dưới các meter name `system.`, `process.` và `disk.`.

Các system metrics sau được cung cấp:

* CPU metrics
* File descriptor metrics
* Uptime metrics, gồm thời gian application đã chạy và fixed gauge của absolute start time
* Disk space available

[[actuator.metrics.supported.application-startup]]
=== Application Startup Metrics

Auto-configuration expose các application startup time metrics:

* `application.started.time`: thời gian cần để start application.
* `application.ready.time`: thời gian cần để application ready phục vụ request.

Metrics được tag bằng fully qualified name của application class.

[[actuator.metrics.supported.spring-mvc]]
=== Spring MVC Metrics

Auto-configuration enable instrumentation cho mọi request được Spring MVC controller và functional handler xử lý.
Mặc định, metrics được generate với name `http.server.requests`.
Nếu bạn xref:actuator/observability.adoc#actuator.observability.semantic-conventions[dùng semantic convention của Micrometer], hãy set property configprop:management.observations.http.server.requests.name[] để customize name.
Nếu dùng semantic convention của OpenTelemetry, name không thể được customize.

Xem {url-spring-framework-docs}/integration/observability.html#observability.http-server.servlet[Spring Framework reference documentation] để biết thêm về các observation được tạo.

Để thêm vào default tag, cung cấp một javadoc:org.springframework.context.annotation.Bean[format=annotation] extend javadoc:org.springframework.http.server.observation.DefaultServerRequestObservationConvention[] từ package `org.springframework.http.server.observation`.
Để replace default tag, cung cấp một javadoc:org.springframework.context.annotation.Bean[format=annotation] implement javadoc:org.springframework.http.server.observation.ServerRequestObservationConvention[].

TIP: Trong một số trường hợp, các exception được handle trong web controller không được record thành request metric tag.
Application có thể opt in và record exception bằng cách xref:web/servlet.adoc#web.servlet.spring-mvc.error-handling[set handled exception làm request attribute].

Mặc định, mọi request đều được handle.
Để customize filter, cung cấp một javadoc:org.springframework.context.annotation.Bean[format=annotation] implement `FilterRegistrationBean<ServerHttpObservationFilter>`.

Mặc định, metrics có name `http.server.requests`.

[[actuator.metrics.supported.jersey]]
=== Jersey Server Metrics

Auto-configuration enable instrumentation cho mọi request được xử lý bởi Jersey JAX-RS implementation.
Mặc định, metrics có name `http.server.requests`.
Customize name bằng property configprop:management.observations.http.server.requests.name[].

Mặc định, Jersey server metrics được tag bằng thông tin sau:

|===
| Tag | Mô tả

| `exception`
| Simple class name của exception được throw khi handle request.

| `method`
| Method của request, ví dụ `GET` hoặc `POST`.

| `outcome`
| Outcome của request, dựa trên status code của response.
  1xx là `INFORMATIONAL`, 2xx là `SUCCESS`, 3xx là `REDIRECTION`, 4xx là `CLIENT_ERROR` và 5xx là `SERVER_ERROR`.

| `status`
| HTTP status code của response, ví dụ `200` hoặc `500`.

| `uri`
| URI template của request trước khi variable substitution, nếu có thể, ví dụ `/api/person/\{id}`.
|===

Để customize tag, cung cấp một javadoc:org.springframework.context.annotation.Bean[format=annotation] implement javadoc:io.micrometer.core.instrument.binder.jersey.server.JerseyObservationConvention[].

[[actuator.metrics.supported.ssl]]
=== SSL Bundle Metrics

Spring Boot Actuator publish expiry metrics về SSL bundle.
Metric `ssl.chain.expiry` gauge expiry date của mỗi certificate chain trong key store và trust store theo giây.
Giá trị này âm nếu chain đã expire.
Metric này được tag bằng thông tin sau:

|===
| Tag | Mô tả

| `bundle`
| Tên bundle chứa certificate chain.

| `certificate`
| Serial number (hex format) của certificate sắp expire sớm nhất trong chain.

| `chain`
| Tên certificate chain.

| `source`
| Certificate chain đến từ key store (`keystore`) hay trust store (`truststore`).
|===

[[actuator.metrics.customizing.common-tags]]
=== Common Tags

Common tag thường được dùng để dimensional drill-down operating environment, chẳng hạn host, instance, region, stack và các thành phần khác.
Common tag được apply cho mọi meter và có thể được configure như trong ví dụ sau:

[configprops,yaml]
----
management:
  metrics:
    tags:
      region: "us-east-1"
      stack: "prod"
----

Ví dụ trên thêm tag `region` và `stack` vào mọi meter, lần lượt có value `us-east-1` và `prod`.

NOTE: Order của common tag quan trọng nếu dùng Graphite.
Vì cách này không guarantee order của common tag, Graphite user được khuyến nghị define custom javadoc:io.micrometer.core.instrument.config.MeterFilter[].

[[actuator.metrics.customizing.per-meter-properties]]
=== Per-meter Properties

Ngoài bean javadoc:io.micrometer.core.instrument.config.MeterFilter[], bạn có thể apply một limited set customization theo từng meter bằng property.
Per-meter customization được apply qua javadoc:org.springframework.boot.micrometer.metrics.autoconfigure.PropertiesMeterFilter[] tới mọi meter ID bắt đầu bằng name được cho.
Ví dụ sau filter mọi meter có ID bắt đầu bằng `example.remote`:

[configprops,yaml]
----
management:
  metrics:
    enable:
      example:
        remote: false
----

Các property sau hỗ trợ per-meter customization:

.Per-meter customizations
|===
| Property | Mô tả

| configprop:management.metrics.enable[]
| Có accept các meter với ID nhất định hay không.
  Các meter không được accept sẽ bị filter khỏi javadoc:io.micrometer.core.instrument.MeterRegistry[].

| configprop:management.metrics.distribution.percentiles-histogram[]
| Có publish histogram phù hợp để compute aggregable percentile approximation qua dimension hay không.

| configprop:management.metrics.distribution.minimum-expected-value[], configprop:management.metrics.distribution.maximum-expected-value[]
| Publish ít histogram bucket hơn bằng cách clamp range của expected value.

| configprop:management.metrics.distribution.percentiles[]
| Publish percentile value được compute trong application.

| configprop:management.metrics.distribution.expiry[], configprop:management.metrics.distribution.buffer-length[]
| Tăng trọng số recent sample bằng cách accumulate chúng trong ring buffer rotate sau configurable expiry, với configurable buffer length.

| configprop:management.metrics.distribution.slo[]
| Publish cumulative histogram với các bucket được định nghĩa bởi service-level objective.
|===

Để biết thêm về các concept phía sau `percentiles-histogram`, `percentiles` và `slo`, xem phần {url-micrometer-docs-concepts}/histogram-quantiles.html[Histograms and percentiles] trong Micrometer documentation.

[[actuator.metrics.endpoint]]
== Metrics Endpoint

Spring Boot cung cấp endpoint `metrics` để dùng cho mục đích diagnostic, giúp examine metrics mà application collect.
Endpoint mặc định không available và phải được expose.
Xem xref:actuator/endpoints.adoc#actuator.endpoints.exposing[exposing endpoints] để biết thêm chi tiết.

Đi tới `/actuator/metrics` sẽ hiển thị list available meter name.
Bạn có thể drill down để xem information của một meter cụ thể bằng cách cung cấp name của meter làm selector, ví dụ `/actuator/metrics/jvm.memory.max`.

[TIP]
====
Name bạn dùng ở đây phải match name được dùng trong code, không phải name sau khi được normalized theo naming convention của monitoring system nơi metric được ship.
Nói cách khác, nếu `jvm.memory.max` xuất hiện thành `jvm_memory_max` trong Prometheus do snake case naming convention, bạn vẫn phải dùng `jvm.memory.max` làm selector khi inspect meter trong endpoint `metrics`.
====

Bạn cũng có thể thêm bất kỳ số lượng query parameter `tag=KEY:VALUE` nào vào cuối URL để dimensional drill down trên một meter, ví dụ `/actuator/metrics/jvm.memory.max?tag=area:nonheap`.

[TIP]
====
Measurement được report là statistic _sum_ của mọi meter match với meter name và các tag đã apply.
Trong ví dụ trên, statistic `Value` trả về là tổng maximum memory footprint của các area `"`Code Cache`"`, `"`Compressed Class Space`"` và `"`Metaspace`"` trong heap.
Nếu chỉ muốn maximum size của `"`Metaspace`"`, hãy thêm `tag=id:Metaspace`, tức `/actuator/metrics/jvm.memory.max?tag=area:nonheap&tag=id:Metaspace`.
====
