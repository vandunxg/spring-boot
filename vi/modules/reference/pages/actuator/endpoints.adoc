[[actuator.endpoints]]
= Endpoints

Actuator endpoint cho phép monitor và tương tác với application.
Spring Boot có nhiều built-in endpoint và cho phép thêm endpoint riêng.
Ví dụ endpoint `health` cung cấp basic application health information.

Có thể xref:actuator/endpoints.adoc#actuator.endpoints.controlling-access[kiểm soát access] tới từng endpoint và xref:actuator/endpoints.adoc#actuator.endpoints.exposing[expose chúng (cho phép remote access) qua HTTP hoặc JMX].
Endpoint được xem là available khi access được permit và endpoint được expose.
Built-in endpoint chỉ được auto-configure khi available.
Phần lớn application chọn expose qua HTTP, trong đó endpoint ID cùng prefix `/actuator` được map thành URL.
Ví dụ mặc định endpoint `health` map tới `/actuator/health`.

TIP: Để tìm hiểu thêm về Actuator endpoint cùng request/response format, xem xref:api:rest/actuator/index.adoc[API documentation].

Các technology-agnostic endpoint sau available:

[cols="2,5"]
|===
| ID | Mô tả

| `auditevents`
| Expose audit event information cho current application.
  Cần bean javadoc:org.springframework.boot.actuate.audit.AuditEventRepository[].

| `beans`
| Hiển thị complete list mọi Spring bean trong application.

| `caches`
| Expose available cache.

| `conditions`
| Hiển thị condition được evaluate trên configuration và auto-configuration class cùng lý do match hoặc không match.

| `configprops`
| Hiển thị collated list của mọi javadoc:org.springframework.boot.context.properties.ConfigurationProperties[format=annotation].
Tuân theo xref:actuator/endpoints.adoc#actuator.endpoints.sanitization[sanitization].

| `env`
| Expose property từ javadoc:org.springframework.core.env.ConfigurableEnvironment[] của Spring.
Tuân theo xref:actuator/endpoints.adoc#actuator.endpoints.sanitization[sanitization].

| `flyway`
| Hiển thị Flyway database migration đã apply.
  Cần một hoặc nhiều bean javadoc:org.flywaydb.core.Flyway[].

| `health`
| Hiển thị application health information.

| `httpexchanges`
| Hiển thị HTTP exchange information, mặc định 100 HTTP request-response exchange gần nhất.
  Cần bean javadoc:org.springframework.boot.actuate.web.exchanges.HttpExchangeRepository[].

| `info`
| Hiển thị arbitrary application info.

| `integrationgraph`
| Hiển thị Spring Integration graph.
  Cần dependency `spring-integration-core`.

| `loggers`
| Hiển thị và modify logger configuration trong application.

| `liquibase`
| Hiển thị Liquibase database migration đã apply.
  Cần một hoặc nhiều bean javadoc:{url-liquibase-javadoc}/liquibase.Liquibase[].

| `metrics`
| Hiển thị "metrics" information cho current application để diagnose metric application đã record.

| `mappings`
| Hiển thị collated list mọi path javadoc:org.springframework.web.bind.annotation.RequestMapping[format=annotation].

|`quartz`
|Hiển thị information về Quartz Scheduler job.
Tuân theo xref:actuator/endpoints.adoc#actuator.endpoints.sanitization[sanitization].

| `scheduledtasks`
| Hiển thị scheduled task trong application.

| `sessions`
| Cho phép retrieve và delete user session từ Spring Session-backed session store.
  Cần servlet-based web application dùng Spring Session.

| `shutdown`
| Cho phép graceful shutdown application.
  Chỉ hoạt động với jar packaging.
  Mặc định disable.

| `startup`
| Hiển thị xref:features/spring-application.adoc#features.spring-application.startup-tracking[startup steps data] collect bởi javadoc:org.springframework.core.metrics.ApplicationStartup[].
  Cần javadoc:org.springframework.boot.SpringApplication[] được configure với javadoc:org.springframework.boot.context.metrics.buffering.BufferingApplicationStartup[].

| `threaddump`
| Thực hiện thread dump.
|===

Nếu application là web application (Spring MVC, Spring WebFlux hoặc Jersey), có thêm endpoint:

[cols="2,5"]
|===
| ID | Mô tả

| `heapdump`
| Trả heap dump file.
  Trên HotSpot JVM trả file format `HPROF`.
  Trên OpenJ9 JVM trả file format `PHD`.

| `logfile`
| Trả content logfile nếu property `logging.file.name` hoặc `logging.file.path` được set.
  Hỗ trợ HTTP header `Range` để retrieve một phần content log file.

| `prometheus`
| Expose metric ở format Prometheus server có thể scrape.
  Cần dependency `micrometer-registry-prometheus`.
|===

[[actuator.endpoints.controlling-access]]
== Kiểm soát Access tới Endpoint

Mặc định access tới mọi endpoint trừ `shutdown` và `heapdump` là unrestricted.
Để configure permitted access cho endpoint, dùng property `management.endpoint.<id>.access`.
Ví dụ cho phép unrestricted access tới `shutdown`:

[configprops,yaml]
----
management:
  endpoint:
    shutdown:
      access: unrestricted
----

Nếu muốn access theo opt-in thay vì opt-out, đặt configprop:management.endpoints.access.default[] thành `none` rồi dùng property `access` của từng endpoint để opt back in.
Ví dụ chỉ cho read-only access tới `loggers` và deny mọi endpoint khác:

[configprops,yaml]
----
management:
  endpoints:
    access:
      default: none
  endpoint:
    loggers:
      access: read-only
----

NOTE: Endpoint inaccessible bị remove hoàn toàn khỏi application context.
Nếu chỉ muốn đổi technology qua đó endpoint được expose, dùng xref:actuator/endpoints.adoc#actuator.endpoints.exposing[property `include` và `exclude`] thay thế.

[[actuator.endpoints.controlling-access.limiting]]
=== Giới hạn Access

Application-wide endpoint access có thể limit bằng configprop:management.endpoints.access.max-permitted[].
Property này có precedence hơn default access hoặc access level của endpoint riêng.
Đặt `none` để mọi endpoint inaccessible.
Đặt `read-only` để chỉ allow read access.

Với javadoc:org.springframework.boot.actuate.endpoint.annotation.Endpoint[format=annotation], javadoc:org.springframework.boot.actuate.endpoint.jmx.annotation.JmxEndpoint[format=annotation] và javadoc:org.springframework.boot.actuate.endpoint.web.annotation.WebEndpoint[format=annotation], read access tương ứng endpoint method annotate javadoc:org.springframework.boot.actuate.endpoint.annotation.ReadOperation[format=annotation].
Với javadoc:org.springframework.boot.actuate.endpoint.web.annotation.ControllerEndpoint[format=annotation] và javadoc:org.springframework.boot.actuate.endpoint.web.annotation.RestControllerEndpoint[format=annotation], read access tương ứng request mapping xử lý `GET` và `HEAD`.
Với javadoc:org.springframework.boot.actuate.endpoint.web.annotation.ServletEndpoint[format=annotation], read access tương ứng `GET` và `HEAD`.

[[actuator.endpoints.exposing]]
== Expose Endpoints

Mặc định chỉ endpoint health được expose qua HTTP và JMX.
Vì Endpoint có thể chứa sensitive information, cần cân nhắc kỹ khi expose.

Để đổi endpoint được expose, dùng property `include` và `exclude` theo technology:

[cols="3,1"]
|===
| Property | Default

| configprop:management.endpoints.jmx.exposure.exclude[]
|

| configprop:management.endpoints.jmx.exposure.include[]
| `health`

| configprop:management.endpoints.web.exposure.exclude[]
|

| configprop:management.endpoints.web.exposure.include[]
| `health`
|===

Property `include` liệt kê ID endpoint được expose.
Property `exclude` liệt kê endpoint không expose.
`exclude` có precedence hơn `include`.
Cả hai có thể cấu hình bằng list endpoint ID.

Ví dụ chỉ expose `health` và `info` qua JMX:

[configprops,yaml]
----
management:
  endpoints:
    jmx:
      exposure:
        include: "health,info"
----

`*` chọn mọi endpoint.
Ví dụ expose mọi thứ qua HTTP trừ `env` và `beans`:

[configprops,yaml]
----
management:
  endpoints:
    web:
      exposure:
        include: "*"
        exclude: "env,beans"
----

NOTE: `*` có meaning đặc biệt trong YAML, nên thêm quote nếu muốn include hoặc exclude toàn bộ endpoint.

NOTE: Nếu application expose public, khuyến nghị mạnh xref:actuator/endpoints.adoc#actuator.endpoints.security[secure endpoint].

TIP: Nếu muốn implement strategy riêng quyết định khi nào endpoint được expose, register bean javadoc:org.springframework.boot.actuate.endpoint.EndpointFilter[].

[[actuator.endpoints.security]]
== Security

Vì security, mặc định chỉ endpoint `/health` được expose qua HTTP.
Dùng configprop:management.endpoints.web.exposure.include[] để configure endpoint expose.

NOTE: Trước khi set `management.endpoints.web.exposure.include`, đảm bảo actuator được expose không chứa sensitive information, được protect sau firewall hoặc secure bằng Spring Security.

Nếu Spring Security trên classpath và không có bean javadoc:org.springframework.security.web.SecurityFilterChain[] khác, mọi actuator ngoài `/health` được Spring Boot auto-configuration secure.
Nếu define custom SecurityFilterChain bean, Spring Boot auto-configuration back off và bạn kiểm soát hoàn toàn actuator access rule.

Nếu muốn custom security cho HTTP endpoint, ví dụ chỉ role cụ thể được access, Spring Boot cung cấp convenient javadoc:org.springframework.security.web.util.matcher.RequestMatcher[] dùng với Spring Security.

[[actuator.endpoints.security.csrf]]
=== Cross Site Request Forgery Protection

Vì Spring Boot dựa trên default của Spring Security, CSRF protection mặc định bật.
Điều này nghĩa là actuator endpoint cần `POST` như shutdown và loggers, `PUT`, hoặc `DELETE` sẽ nhận 403 forbidden khi dùng default security configuration.

NOTE: Chỉ khuyến nghị disable hoàn toàn CSRF protection nếu tạo service dùng bởi non-browser client.

Xem thêm {url-spring-security-docs}/features/exploits/csrf.html[Spring Security Reference Guide].

[[actuator.endpoints.caching]]
== Configure Endpoints

Endpoint tự động cache response của read operation không nhận parameter.
Để cấu hình thời gian cache response, dùng property `cache.time-to-live`.
Ví dụ cache endpoint `beans` trong 10 giây:

[configprops,yaml]
----
management:
  endpoint:
    beans:
      cache:
        time-to-live: "10s"
----

NOTE: Prefix `management.endpoint.<name>` uniquely identify endpoint đang configure.

[[actuator.endpoints.sanitization]]
== Sanitize Sensitive Values

Information trả bởi endpoint `/env`, `/configprops` và `/quartz` có thể sensitive, nên mặc định value luôn fully sanitized, được replace bằng `+******+`.

Value chỉ có thể xem unsanitized khi:

- Property `show-values` được set khác `never`
- Không có custom xref:how-to:actuator.adoc#howto.actuator.customizing-sanitization[`SanitizingFunction`] bean áp dụng

Property `show-values` có thể cấu hình cho sanitizable endpoint:

- `never` - value luôn fully sanitized, replace bằng `+******+`
- `always` - value hiển thị cho mọi user miễn là không có bean javadoc:org.springframework.boot.actuate.endpoint.SanitizingFunction[] áp dụng

- `when-authorized` - value chỉ hiển thị cho authorized user, miễn là không có bean javadoc:org.springframework.boot.actuate.endpoint.SanitizingFunction[] áp dụng.

Với HTTP endpoint, user được xem là authorized nếu đã authenticate và có role được cấu hình bởi property `roles` của endpoint.
Mặc định mọi authenticated user đều authorized.

Với JMX endpoint, mọi user luôn authorized.

Ví dụ sau cho phép user có role `admin` xem original value từ endpoint `/env`.
Unauthorized user hoặc user không có role `admin` chỉ thấy sanitized value.

[configprops,yaml]
----
management:
  endpoint:
    env:
      show-values: when-authorized
      roles: "admin"
----

NOTE: Ví dụ này giả định không có bean xref:how-to:actuator.adoc#howto.actuator.customizing-sanitization[`SanitizingFunction`] được định nghĩa.

[[actuator.endpoints.hypermedia]]
== Hypermedia cho Actuator Web Endpoints

Một "discovery page" được thêm với link tới tất cả endpoint.
Mặc định discovery page available tại `/actuator`.

Để disable discovery page:

[configprops,yaml]
----
management:
  endpoints:
    web:
      discovery:
        enabled: false
----

Khi custom management context path được cấu hình, discovery page tự động move từ `/actuator` tới root của management context.
Ví dụ management context path là `/management`, discovery page available tại `/management`.
Khi management context path là `/`, discovery page bị disable để tránh clash với mapping khác.

[[actuator.endpoints.cors]]
== CORS Support

https://en.wikipedia.org/wiki/Cross-origin_resource_sharing[Cross-origin resource sharing] (CORS) là https://www.w3.org/TR/cors/[W3C specification] cho phép specify linh hoạt loại cross-domain request được authorize.
Nếu dùng Spring MVC hoặc Spring WebFlux, có thể configure web endpoint của Actuator hỗ trợ scenario này.

CORS support mặc định disable và chỉ enable sau khi set configprop:management.endpoints.web.cors.allowed-origins[].
Configuration sau cho phép `GET` và `POST` từ domain `example.com`:

[configprops,yaml]
----
management:
  endpoints:
    web:
      cors:
        allowed-origins: "https://example.com"
        allowed-methods: "GET,POST"
----

TIP: Xem javadoc:org.springframework.boot.actuate.autoconfigure.endpoint.web.CorsEndpointProperties[] để biết đầy đủ option.

[[actuator.endpoints.json]]
== JSON

Khi làm việc với JSON, Jackson được dùng cho serialization và deserialization.
Mặc định dùng isolated javadoc:tools.jackson.databind.json.JsonMapper[].
Isolation nghĩa là nó không share configuration với `JsonMapper` của application và không bị ảnh hưởng bởi property `spring.jackson.*`.
Để disable behavior này và dùng JsonMapper của application, đặt configprop:management.endpoints.jackson.isolated-json-mapper[] thành `false`.
Ngoài ra có thể define bean javadoc:org.springframework.boot.actuate.endpoint.jackson.EndpointJsonMapper[] riêng tạo JsonMapper phù hợp.
Actuator sẽ dùng nó cho JSON processing.

[[actuator.endpoints.implementing-custom.input]]
=== Nhận Input

Operation trên endpoint nhận input qua parameter.
Khi expose qua web, value parameter lấy từ URL query parameter và JSON request body.
Khi expose qua JMX, parameter map tới parameter của MBean operation.
Parameter mặc định required.
Có thể làm optional bằng annotation JSpecify javadoc:org.jspecify.annotations.Nullable[format=annotation].
Kotlin null safety cũng được hỗ trợ.

Có thể map mỗi root property trong JSON request body tới một endpoint parameter.
Ví dụ request body:

[source,json]
----
{
	"name": "test",
	"counter": 42
}
----

Có thể dùng để invoke write operation nhận parameter `String name` và `int counter`:

Parameter truyền vào endpoint operation method được tự động convert sang required type khi cần.

[[actuator.endpoints.implementing-custom.web]]
=== Custom Web Endpoints

Operation trên javadoc:org.springframework.boot.actuate.endpoint.annotation.Endpoint[format=annotation], javadoc:org.springframework.boot.actuate.endpoint.web.annotation.WebEndpoint[format=annotation] hoặc javadoc:org.springframework.boot.actuate.endpoint.web.annotation.EndpointWebExtension[format=annotation] tự động expose qua HTTP bằng Jersey, Spring MVC hoặc Spring WebFlux.
Nếu cả Jersey và Spring MVC có sẵn, Spring MVC được dùng.

[[actuator.endpoints.implementing-custom.web.request-predicates]]
==== Web Endpoint Request Predicates

Request predicate tự động generate cho mỗi operation trên web-exposed endpoint.

[[actuator.endpoints.implementing-custom.web.path-predicates]]
==== Path

Path của predicate được xác định bởi endpoint ID và base path của web-exposed endpoint.
Default base path là `/actuator`.
Ví dụ endpoint ID `sessions` dùng `/actuator/sessions` làm path trong predicate.

Có thể customize path thêm bằng cách annotate một hoặc nhiều parameter của operation method với javadoc:org.springframework.boot.actuate.endpoint.annotation.Selector[format=annotation].
Parameter này được thêm vào path predicate như path variable.
Value được truyền vào operation method khi endpoint operation invoke.
Nếu muốn capture mọi remaining path element, thêm `@Selector(Match=ALL_REMAINING)` vào parameter cuối và dùng type conversion-compatible với `String[]`.

[[actuator.endpoints.implementing-custom.web.method-predicates]]
==== HTTP Method

HTTP method của predicate được xác định bởi operation type:

[cols="3, 1"]
|===
| Operation | HTTP method

| javadoc:org.springframework.boot.actuate.endpoint.annotation.ReadOperation[format=annotation]
| `GET`

| javadoc:org.springframework.boot.actuate.endpoint.annotation.WriteOperation[format=annotation]
| `POST`

| javadoc:org.springframework.boot.actuate.endpoint.annotation.DeleteOperation[format=annotation]
| `DELETE`
|===

[[actuator.endpoints.implementing-custom.web.consumes-predicates]]
==== Consumes

Với javadoc:org.springframework.boot.actuate.endpoint.annotation.WriteOperation[format=annotation] (HTTP `POST`) dùng request body, clause `consumes` của predicate là `application/vnd.spring-boot.actuator.v2+json, application/json`.
Với mọi operation khác, clause `consumes` rỗng.

[[actuator.endpoints.implementing-custom.web.produces-predicates]]
==== Produces

Clause `produces` có thể được xác định bởi attribute `produces` của annotation DeleteOperation, ReadOperation và WriteOperation.
Attribute optional.
Nếu không dùng, `produces` được xác định tự động.

Nếu operation method trả `void` hoặc javadoc:java.lang.Void[], clause `produces` rỗng.
Nếu trả javadoc:org.springframework.core.io.Resource[], clause là `application/octet-stream`.
Với operation khác, clause là `application/vnd.spring-boot.actuator.v2+json, application/json`.

[[actuator.endpoints.implementing-custom.web.response-status]]
==== Web Endpoint Response Status

Default response status phụ thuộc operation type và value operation trả về.

Nếu ReadOperation trả value, response status 200 (OK).
Nếu không trả value, status 404 (Not Found).

Nếu WriteOperation hoặc DeleteOperation trả value, response status 200 (OK).
Nếu không trả value, status 204 (No Content).

Nếu operation invoke thiếu required parameter hoặc parameter không convert được sang required type, operation method không được gọi và response status 400 (Bad Request).

[[actuator.endpoints.implementing-custom.web.range-requests]]
==== Web Endpoint Range Requests

Có thể dùng HTTP range request để request một phần HTTP resource.
Khi dùng Spring MVC hoặc Spring WebFlux, operation trả javadoc:org.springframework.core.io.Resource[] tự động hỗ trợ range request.

NOTE: Range request không được hỗ trợ với Jersey.

[[actuator.endpoints.implementing-custom.web.security]]
==== Web Endpoint Security

Operation trên web endpoint hoặc web-specific endpoint extension có thể nhận current javadoc:java.security.Principal[] hoặc javadoc:org.springframework.boot.actuate.endpoint.SecurityContext[] làm method parameter.
Principal thường dùng cùng javadoc:org.jspecify.annotations.Nullable[format=annotation] để cung cấp behavior khác cho authenticated và unauthenticated user.
SecurityContext thường dùng để authorization check qua method `isUserInRole(String)`.

[[actuator.endpoints.health]]
== Health Information

Có thể dùng health information để check status của running application.
Monitoring software thường dùng để alert khi production system down.
Information expose bởi endpoint `health` phụ thuộc configprop:management.endpoint.health.show-details[] và configprop:management.endpoint.health.show-components[], với value:

[cols="1, 3"]
|===
| Name | Mô tả

| `never`
| Không bao giờ hiển thị detail.

| `when-authorized`
| Chỉ hiển thị detail cho authorized user.
  Authorized role configure bằng `management.endpoint.health.roles`.

| `always`
| Hiển thị detail cho mọi user.
|===

Default là `never`.
User authorized khi thuộc một hoặc nhiều role của endpoint.
Nếu endpoint không cấu hình role, mặc định mọi authenticated user authorized.
Configure role bằng configprop:management.endpoint.health.roles[].

NOTE: Nếu application đã secure và muốn dùng `always`, security configuration phải permit access health endpoint cho cả authenticated và unauthenticated user.

Health information được collect từ javadoc:org.springframework.boot.health.registry.HealthContributorRegistry[]; mặc định là mọi instance javadoc:org.springframework.boot.health.contributor.HealthContributor[] trong javadoc:org.springframework.context.ApplicationContext[].
Spring Boot có nhiều auto-configured HealthContributor bean, và bạn cũng có thể viết riêng.

HealthContributor có thể là javadoc:org.springframework.boot.health.contributor.HealthIndicator[] hoặc javadoc:org.springframework.boot.health.contributor.CompositeHealthContributor[].
HealthIndicator cung cấp actual health information gồm javadoc:org.springframework.boot.health.contributor.Status[].
CompositeHealthContributor cung cấp composite của HealthContributor khác.
Together, contributor tạo tree structure biểu diễn overall system health.

Mặc định final system health derive bởi javadoc:org.springframework.boot.health.actuate.endpoint.StatusAggregator[], sort status từ mỗi HealthIndicator dựa trên ordered list status.
Status đầu tiên trong sorted list được dùng làm overall health status.
Nếu không HealthIndicator nào trả status được StatusAggregator biết, dùng `UNKNOWN`.

TIP: Có thể dùng javadoc:org.springframework.boot.health.registry.HealthContributorRegistry[] để register/unregister health indicator runtime.

[[actuator.endpoints.health.writing-custom-health-indicators]]
=== Viết Custom HealthIndicators

Để cung cấp custom health information, register Spring bean implement interface javadoc:org.springframework.boot.health.contributor.HealthIndicator[].
Cần implement method `health()` và trả javadoc:org.springframework.boot.health.contributor.Health[].
Health response nên include status và optional additional detail.
Ví dụ:

include-code::MyHealthIndicator[]

NOTE: Identifier của HealthIndicator là bean name bỏ suffix `HealthIndicator` nếu có.
Trong ví dụ trên, health information available trong entry tên `my`.

TIP: Health indicator thường được gọi qua HTTP và cần response trước connection timeout.
Spring Boot log warning nếu health indicator mất hơn 10 giây.
Configure threshold bằng configprop:management.endpoint.health.logging.slow-indicator-threshold[].

Ngoài predefined javadoc:org.springframework.boot.health.contributor.Status[] type, Health có thể trả custom Status đại diện system state mới.
Khi đó cũng cần custom implementation javadoc:org.springframework.boot.health.actuate.endpoint.StatusAggregator[], hoặc configure default bằng configprop:management.endpoint.health.status.order[].

Ví dụ có Status code `FATAL`.
Configure severity order:

[configprops,yaml]
----
management:
  endpoint:
    health:
      status:
        order: "fatal,down,out-of-service,unknown,up"
----

HTTP status code trong response phản ánh overall health status.
Mặc định `OUT_OF_SERVICE` và `DOWN` map 503.
Health status không map, gồm `UP`, map 200.
Có thể register custom status mapping nếu access health endpoint qua HTTP.
Configure custom mapping sẽ disable default mapping của `DOWN` và `OUT_OF_SERVICE`.
Nếu muốn giữ default, cần explicit configure cùng custom mapping.
Ví dụ map `FATAL` thành 503 và giữ default mapping:

[configprops,yaml]
----
management:
  endpoint:
    health:
      status:
        http-mapping:
          down: 503
          fatal: 503
          out-of-service: 503
----

TIP: Nếu cần kiểm soát nhiều hơn, define bean javadoc:org.springframework.boot.health.actuate.endpoint.HttpCodeStatusMapper[] riêng.

Default status mapping:

[cols="1,3"]
|===
| Status | Mapping

| `DOWN`
| `SERVICE_UNAVAILABLE` (`503`)

| `OUT_OF_SERVICE`
| `SERVICE_UNAVAILABLE` (`503`)

| `UP`
| Mặc định không mapping, HTTP status `200`

| `UNKNOWN`
| Mặc định không mapping, HTTP status `200`
|===

[[actuator.endpoints.health.reactive-health-indicators]]
=== Reactive Health Indicators

Với reactive application như Spring WebFlux, javadoc:org.springframework.boot.health.contributor.ReactiveHealthContributor[] cung cấp non-blocking contract để lấy application health.
Tương tự regular HealthContributor, health information được collect từ javadoc:org.springframework.boot.health.registry.ReactiveHealthContributorRegistry[]; mặc định gồm mọi javadoc:org.springframework.boot.health.contributor.HealthContributor[] và javadoc:org.springframework.boot.health.contributor.ReactiveHealthContributor[] trong ApplicationContext.
Regular HealthContributor không check qua reactive API được execute trên elastic scheduler.

TIP: Trong reactive application, nên dùng javadoc:org.springframework.boot.health.registry.ReactiveHealthContributorRegistry[] để register/unregister health indicator runtime.
Nếu cần register regular HealthContributor, wrap bằng `ReactiveHealthContributor#adapt`.

Để cung cấp custom health information từ reactive API, register Spring bean implement javadoc:org.springframework.boot.health.contributor.ReactiveHealthIndicator[]:

TIP: Để tự động handle error, cân nhắc extend javadoc:org.springframework.boot.health.contributor.AbstractReactiveHealthIndicator[].

[[actuator.endpoints.health.groups]]
=== Health Groups

Đôi khi hữu ích khi organize health indicator thành group dùng cho mục đích khác nhau.

Để tạo health indicator group, dùng property `management.endpoint.health.group.<name>` và specify list health indicator ID trong `include` hoặc `exclude`.
Ví dụ group chỉ gồm database indicator:

[configprops,yaml]
----
management:
  endpoint:
    health:
      group:
        custom:
          include: "db"
----

Check result tại `http://localhost:8080/actuator/health/custom`.

Tương tự, để group exclude database indicator và include indicator khác:

[configprops,yaml]
----
management:
  endpoint:
    health:
      group:
        custom:
          exclude: "db"
----

Mặc định startup fail nếu health group include/exclude health indicator không tồn tại.
Disable behavior bằng configprop:management.endpoint.health.validate-group-membership[] = `false`.

Mặc định group inherit cùng javadoc:org.springframework.boot.health.actuate.endpoint.StatusAggregator[] và javadoc:org.springframework.boot.health.actuate.endpoint.HttpCodeStatusMapper[] như system health.
Tuy nhiên có thể define riêng theo group.
Cũng có thể override `show-details` và `roles`:

[configprops,yaml]
----
management:
  endpoint:
    health:
      group:
        custom:
          show-details: "when-authorized"
          roles: "admin"
          status:
            order: "fatal,up"
            http-mapping:
              fatal: 500
              out-of-service: 500
----

TIP: Dùng `@Qualifier("groupname")` nếu cần register custom StatusAggregator hoặc HttpCodeStatusMapper bean cho group.

Health group cũng có thể include/exclude javadoc:org.springframework.boot.health.contributor.CompositeHealthContributor[].
Có thể include/exclude chỉ component cụ thể của CompositeHealthContributor bằng fully qualified name:

[source,properties]
----
management.endpoint.health.group.custom.include="test/primary"
management.endpoint.health.group.custom.exclude="test/primary/b"
----

Trong ví dụ, group `custom` include HealthContributor tên `primary`, component của composite `test`.
`primary` cũng là composite và HealthContributor tên `b` bị exclude.

Health group có thể available tại additional path trên main hoặc management port.
Điều này hữu ích trong cloud environment như Kubernetes, nơi thường dùng separate management port cho actuator endpoint vì security.
Separate port có thể dẫn tới unreliable health check vì main application có thể hỏng dù health check success.
Configure additional path:

[source,properties]
----
management.endpoint.health.group.live.additional-path="server:/healthz"
----

Điều này expose group `live` trên main server port tại `/healthz`.
Prefix bắt buộc và phải là `server:` (main server port) hoặc `management:` (management port nếu configured).
Path có thể chứa một hoặc nhiều segment.

[[actuator.endpoints.health.datasource]]
=== DataSource Health

javadoc:javax.sql.DataSource[] health indicator hiển thị health của standard data source và routing data source bean.
Health của routing data source gồm health mỗi target data source.
Trong health endpoint response, mỗi target được đặt tên bằng routing key.
Nếu không muốn include routing data source trong output, set configprop:management.health.db.ignore-routing-data-sources[] = `true`.

[[actuator.endpoints.kubernetes-probes]]
== Kubernetes Probes

Application deploy trên Kubernetes có thể cung cấp internal state qua https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#container-probes[Container Probes].
Tùy https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/[Kubernetes configuration], kubelet gọi probe và react theo result.

Mặc định Spring Boot manage xref:features/spring-application.adoc#features.spring-application.application-availability[Application Availability] state.
Nếu deploy trong Kubernetes environment, actuator collect "Liveness" và "Readiness" từ javadoc:org.springframework.boot.availability.ApplicationAvailability[] và dùng trong dedicated xref:actuator/endpoints.adoc#actuator.endpoints.health.auto-configured-health-indicators[health indicator]: javadoc:org.springframework.boot.health.application.LivenessStateHealthIndicator[] và javadoc:org.springframework.boot.health.application.ReadinessStateHealthIndicator[].
Các indicator hiển thị trên global health endpoint (`"/actuator/health"`).
Chúng cũng expose thành separate HTTP Probe qua xref:actuator/endpoints.adoc#actuator.endpoints.health.groups[health group]: `"/actuator/health/liveness"` và `"/actuator/health/readiness"`.

Có thể configure Kubernetes infrastructure bằng endpoint information:

[source,yaml]
----
livenessProbe:
  httpGet:
    path: "/actuator/health/liveness"
