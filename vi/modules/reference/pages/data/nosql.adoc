[[data.nosql.redis]]
== Redis

https://redis.io/[Redis] là cache, message broker và key-value store giàu tính năng.
Spring Boot cung cấp basic auto-configuration cho các client https://github.com/redis/lettuce/[Lettuce] và https://github.com/redis/jedis/[Jedis], cùng các abstraction phía trên do https://github.com/spring-projects/spring-data-redis[Spring Data Redis] cung cấp.

Có starter `spring-boot-starter-data-redis` để tập hợp các dependency theo cách thuận tiện.
Mặc định nó dùng https://github.com/redis/lettuce/[Lettuce].
Starter này hỗ trợ cả traditional application và reactive application.

TIP: Chúng tôi cũng cung cấp starter `spring-boot-starter-data-redis-reactive` để nhất quán với các store khác có reactive support.

Listing sau minh họa một bean như vậy:

Mặc định instance sẽ cố kết nối tới Redis server tại `localhost:6379`.
Bạn có thể chỉ định connection detail tùy chỉnh bằng các property `spring.data.redis.*`, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  data:
    redis:
      host: "localhost"
      port: 6379
      database: 0
      username: "user"
      password: "secret"
----

Bạn cũng có thể chỉ định trực tiếp URL của Redis server.
Khi đặt URL, các property host, port, username và password sẽ bị bỏ qua.
Ví dụ sau minh họa cách này:

[configprops,yaml]
----
spring:
  data:
    redis:
      url: "redis://user:secret@localhost:6379"
      database: 0
----

TIP: Bạn cũng có thể register tùy ý số lượng bean triển khai javadoc:org.springframework.boot.data.redis.autoconfigure.LettuceClientConfigurationBuilderCustomizer[] để thực hiện các customization nâng cao.
javadoc:io.lettuce.core.resource.ClientResources[] cũng có thể được customize bằng javadoc:org.springframework.boot.data.redis.autoconfigure.ClientResourcesBuilderCustomizer[].
Nếu dùng Jedis, javadoc:org.springframework.boot.data.redis.autoconfigure.JedisClientConfigurationBuilderCustomizer[] cũng có sẵn.

Ngoài ra, bạn có thể register một bean kiểu javadoc:org.springframework.data.redis.connection.RedisStandaloneConfiguration[], javadoc:org.springframework.data.redis.connection.RedisSentinelConfiguration[], javadoc:org.springframework.data.redis.connection.RedisClusterConfiguration[] hoặc javadoc:org.springframework.data.redis.connection.RedisStaticMasterReplicaConfiguration[] để kiểm soát hoàn toàn configuration.

NOTE: Jedis không hỗ trợ master/replica.

Nếu thêm javadoc:org.springframework.context.annotation.Bean[format=annotation] riêng cho bất kỳ type nào được auto-configure, bean đó sẽ thay thế bean mặc định. Ngoại lệ là javadoc:org.springframework.data.redis.core.RedisTemplate[], trong trường hợp này exclusion dựa trên bean name `redisTemplate`, không phải type.

Mặc định, pooled connection factory được auto-configure nếu `commons-pool2` có trên classpath.

Auto-configured javadoc:org.springframework.data.redis.connection.RedisConnectionFactory[] có thể được cấu hình để dùng SSL khi giao tiếp với server bằng cách đặt các property như trong ví dụ sau:

[configprops,yaml]
----
spring:
  data:
    redis:
      ssl:
        enabled: true
----

Custom SSL trust material có thể được cấu hình trong xref:features/ssl.adoc[SSL bundle] và áp dụng cho javadoc:org.springframework.data.redis.connection.RedisConnectionFactory[] như trong ví dụ sau:

[configprops,yaml]
----
spring:
  data:
    redis:
      ssl:
        bundle: "example"
----

== MongoDB

https://www.mongodb.com/[MongoDB] là open-source NoSQL document database sử dụng schema giống JSON thay vì relational data dựa trên table truyền thống.
Spring Boot cung cấp một số tiện ích khi làm việc với MongoDB, gồm các starter `spring-boot-starter-data-mongodb` và `spring-boot-starter-data-mongodb-reactive`.

=== Kết nối tới MongoDB Database

Để access MongoDB database, bạn có thể inject javadoc:org.springframework.data.mongodb.MongoDatabaseFactory[] được auto-configure.
Mặc định instance sẽ cố kết nối tới MongoDB server tại `mongodb://localhost/test`.
Ví dụ sau minh họa cách kết nối tới MongoDB database:

include-code::MyBean[]

Nếu bạn tự định nghĩa javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[], nó sẽ được dùng để auto-configure javadoc:org.springframework.data.mongodb.MongoDatabaseFactory[] phù hợp.

Auto-configured javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[] được tạo bằng bean javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings[].
Nếu bạn tự định nghĩa javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings[], bean đó sẽ được dùng nguyên trạng và các property `spring.data.mongodb` sẽ bị bỏ qua.
Nếu không, javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings[] sẽ được auto-configure và các property `spring.data.mongodb` sẽ được áp dụng cho nó.
Trong cả hai trường hợp, bạn có thể khai báo một hoặc nhiều bean javadoc:org.springframework.boot.mongodb.autoconfigure.MongoClientSettingsBuilderCustomizer[] để fine-tune configuration của javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings[].
Mỗi bean sẽ được gọi theo thứ tự với javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings$Builder[] được dùng để build javadoc:{url-mongodb-driver-core-javadoc}/com.mongodb.MongoClientSettings[].

Có thể đặt configprop:spring.mongodb.uri[] để đổi URL và cấu hình thêm các setting như _replica set_, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  mongodb:
    uri: "mongodb://user:secret@mongoserver1.example.com:27017,mongoserver2.example.com:23456/test"
----

Hoặc bạn có thể chỉ định connection detail bằng các property riêng lẻ.
Ví dụ, bạn có thể khai báo các setting sau trong `application.properties`:

[configprops,yaml]
----
spring:
  mongodb:
    host: "mongoserver1.example.com"
    port: 27017
    additional-hosts:
    - "mongoserver2.example.com:23456"
    database: "test"
    username: "user"
    password: "secret"
----

Auto-configured javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[] có thể được cấu hình để dùng SSL khi giao tiếp với server bằng cách đặt các property như trong ví dụ sau:

[configprops,yaml]
----
spring:
  mongodb:
    uri: "mongodb://user:secret@mongoserver1.example.com:27017,mongoserver2.example.com:23456/test"
    ssl:
      enabled: true
----

Custom SSL trust material có thể được cấu hình trong xref:features/ssl.adoc[SSL bundle] và áp dụng cho javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[] như trong ví dụ sau:

[configprops,yaml]
----
spring:
  mongodb:
    uri: "mongodb://user:secret@mongoserver1.example.com:27017,mongoserver2.example.com:23456/test"
    ssl:
      bundle: "example"
----

[TIP]
====
Nếu configprop:spring.mongodb.port[] không được chỉ định, giá trị mặc định `27017` sẽ được dùng.
Bạn có thể xóa dòng này khỏi ví dụ trước.

Cũng có thể chỉ định port trong host address bằng syntax `host:port`.
Nên dùng format này nếu cần đổi port của một entry `additional-hosts`.
====

TIP: Nếu không dùng Spring Data MongoDB, bạn có thể inject bean javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[] thay vì dùng javadoc:org.springframework.data.mongodb.MongoDatabaseFactory[].
Nếu muốn kiểm soát hoàn toàn việc thiết lập MongoDB connection, bạn cũng có thể tự khai báo bean javadoc:org.springframework.data.mongodb.MongoDatabaseFactory[] hoặc javadoc:{url-mongodb-driver-sync-javadoc}/com.mongodb.client.MongoClient[].

NOTE: Nếu dùng reactive driver, Netty là bắt buộc cho SSL.
Auto-configuration sẽ tự cấu hình factory nếu Netty có sẵn và factory cần dùng chưa được customize.

[[data.nosql.elasticsearch]]
== Elasticsearch

https://www.elastic.co/products/elasticsearch[Elasticsearch] là open source, distributed, RESTful search và analytics engine.
Spring Boot cung cấp basic auto-configuration cho các Elasticsearch client.

Spring Boot hỗ trợ một số client:

* Official low-level REST client
* Official Java API client
* javadoc:org.springframework.data.elasticsearch.client.elc.ReactiveElasticsearchClient[] từ Spring Data Elasticsearch

Spring Boot cung cấp starter `spring-boot-starter-data-elasticsearch`.

[[data.nosql.elasticsearch.connecting-using-rest]]
=== Kết nối Elasticsearch bằng REST client

Elasticsearch cung cấp hai REST client khác nhau mà bạn có thể dùng để query một cluster: https://www.elastic.co/docs/reference/elasticsearch/clients/java/transport/rest5-client/[low-level client] và https://www.elastic.co/docs/reference/elasticsearch/clients/java[Java API client].
Java API client được cung cấp bởi module `co.elastic.clients:elasticsearch-java`, còn low-level client được cung cấp bởi module `co.elastic.clients:elasticsearch-rest5-client`.
Ngoài ra, Spring Boot cung cấp support cho reactive client từ module `org.springframework.data:spring-data-elasticsearch`.
Mặc định, các client sẽ target `http://localhost:9200`.
Bạn có thể dùng các property `spring.elasticsearch.*` để tinh chỉnh thêm cách cấu hình client, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  elasticsearch:
    uris: "https://search.example.com:9200"
    socket-timeout: "10s"
    username: "user"
    password: "secret"
----

[[data.nosql.elasticsearch.connecting-using-rest.restclient]]
==== Kết nối Elasticsearch bằng Rest5Client

Nếu `co.elastic.clients:elasticsearch-rest5-client` có trên classpath, Spring Boot sẽ auto-configure và register một bean javadoc:co.elastic.clients.transport.rest5_client.low_level.Rest5Client[].
Ngoài các property đã mô tả trước đó, để fine-tune javadoc:co.elastic.clients.transport.rest5_client.low_level.Rest5Client[], bạn có thể register tùy ý số lượng bean triển khai javadoc:org.springframework.boot.elasticsearch.autoconfigure.Rest5ClientBuilderCustomizer[] cho các customization nâng cao.
Để kiểm soát hoàn toàn client configuration, định nghĩa bean javadoc:co.elastic.clients.transport.rest5_client.low_level.Rest5ClientBuilder[].

javadoc:co.elastic.clients.transport.rest5_client.low_level.sniffer.Sniffer[] cũng có thể được auto-configure để tự động discover các node từ một Elasticsearch cluster đang chạy và set chúng lên bean javadoc:co.elastic.clients.transport.rest5_client.low_level.Rest5Client[].
Bạn có thể tinh chỉnh thêm cách cấu hình javadoc:co.elastic.clients.transport.rest5_client.low_level.sniffer.Sniffer[] như trong ví dụ sau:

[configprops,yaml]
----
spring:
  elasticsearch:
    restclient:
      sniffer:
        enabled: true
        interval: "10m"
        delay-after-failure: "30s"
----

[[data.nosql.elasticsearch.connecting-using-rest.javaapiclient]]
==== Kết nối Elasticsearch bằng ElasticsearchClient

Nếu dùng `spring-boot-starter-elasticsearch` hoặc đã thêm `co.elastic.clients:elasticsearch-java` vào classpath, Spring Boot sẽ auto-configure và register một bean javadoc:co.elastic.clients.elasticsearch.ElasticsearchClient[].

javadoc:co.elastic.clients.elasticsearch.ElasticsearchClient[] sử dụng một transport phụ thuộc vào javadoc:co.elastic.clients.transport.rest5_client.low_level.Rest5Client[] đã mô tả ở trên.
Do đó, các property đã mô tả trước đó có thể được dùng để cấu hình javadoc:co.elastic.clients.elasticsearch.ElasticsearchClient[].
Ngoài ra, bạn có thể định nghĩa một bean javadoc:co.elastic.clients.transport.rest5_client.Rest5ClientOptions[] để kiểm soát thêm behavior của transport.

=== Spring Data Elasticsearch Repositories

Spring Data bao gồm repository support cho Elasticsearch.
Giống các JPA repository đã thảo luận trước đó, nguyên tắc cơ bản là query được tự động construct dựa trên method name.

Thực tế, Spring Data JPA và Spring Data Elasticsearch dùng chung một common infrastructure.
Bạn có thể lấy ví dụ JPA trước đó và giả sử `City` hiện là một Elasticsearch javadoc:org.springframework.data.elasticsearch.annotations.Document[format=annotation] class thay vì JPA javadoc:jakarta.persistence.Entity[format=annotation]; nó sẽ hoạt động theo cách tương tự.

Repository và document được tìm thấy thông qua scanning.
Mặc định, xref:using/auto-configuration.adoc#using.auto-configuration.packages[auto-configuration package] được scan.
Bạn có thể customize location dùng để tìm repository và document bằng javadoc:org.springframework.data.elasticsearch.repository.config.EnableElasticsearchRepositories[format=annotation] và javadoc:org.springframework.boot.persistence.autoconfigure.EntityScan[format=annotation], tương ứng.

TIP: Để biết đầy đủ chi tiết về Spring Data Elasticsearch, xem {url-spring-data-elasticsearch-docs}[reference documentation].

Spring Boot hỗ trợ cả classic và reactive Elasticsearch repository, sử dụng bean javadoc:org.springframework.data.elasticsearch.client.elc.ElasticsearchTemplate[] hoặc javadoc:org.springframework.data.elasticsearch.client.elc.ReactiveElasticsearchTemplate[].
Nhiều khả năng các bean đó được Spring Boot auto-configure khi có đủ dependency cần thiết.

Nếu muốn dùng template riêng của mình để backing cho Elasticsearch repository, bạn có thể thêm javadoc:org.springframework.data.elasticsearch.client.elc.ElasticsearchTemplate[] hoặc javadoc:org.springframework.data.elasticsearch.core.ElasticsearchOperations[] của riêng mình cùng với javadoc:org.springframework.context.annotation.Bean[format=annotation], miễn là bean đó có tên `"elasticsearchTemplate"`.
Điều tương tự cũng áp dụng cho javadoc:org.springframework.data.elasticsearch.client.elc.ReactiveElasticsearchTemplate[] và javadoc:org.springframework.data.elasticsearch.core.ReactiveElasticsearchOperations[], với bean name `"reactiveElasticsearchTemplate"`.

Bạn có thể chọn disable repository support bằng property sau:

[configprops,yaml]
----
    spring:
      data:
        elasticsearch:
          repositories:
            enabled: false
----

== Cassandra

https://cassandra.apache.org/[Cassandra] là open source, distributed database management system được thiết kế để xử lý lượng data lớn trên nhiều commodity server.
Spring Boot cung cấp auto-configuration cho Cassandra và các abstraction phía trên nó do {url-spring-data-cassandra-site}[Spring Data Cassandra] cung cấp.
Có starter `spring-boot-starter-data-cassandra` để tập hợp các dependency theo cách thuận tiện.

[[data.nosql.cassandra.connecting]]
=== Kết nối Cassandra

Bạn có thể inject javadoc:org.springframework.data.cassandra.core.cql.CqlTemplate[], javadoc:org.springframework.data.cassandra.core.CassandraTemplate[] được auto-configure hoặc một Cassandra `CqlSession` instance, như với bất kỳ Spring Bean nào khác.
Các property `spring.cassandra.*` có thể được dùng để customize connection.
Thông thường, bạn cung cấp `keyspace-name`, `contact-points` cũng như tên local datacenter, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  cassandra:
    keyspace-name: "mykeyspace"
    contact-points: "cassandrahost1:9042,cassandrahost2:9042"
    local-datacenter: "datacenter1"
----

Nếu port giống nhau cho mọi contact point, bạn có thể dùng shortcut và chỉ chỉ định hostname, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  cassandra:
    keyspace-name: "mykeyspace"
    contact-points: "cassandrahost1,cassandrahost2"
    local-datacenter: "datacenter1"
----

TIP: Hai ví dụ trên tương đương vì port mặc định là `9042`.
Nếu cần đổi port, dùng `spring.cassandra.port`.

Auto-configured `CqlSession` có thể được cấu hình để dùng SSL khi giao tiếp với server bằng cách đặt các property như trong ví dụ sau:

[configprops,yaml]
----
spring:
  cassandra:
    keyspace-name: "mykeyspace"
    contact-points: "cassandrahost1,cassandrahost2"
    local-datacenter: "datacenter1"
    ssl:
      enabled: true
----

Custom SSL trust material có thể được cấu hình trong xref:features/ssl.adoc[SSL bundle] và áp dụng cho `CqlSession` như trong ví dụ sau:

[configprops,yaml]
----
spring:
  cassandra:
    keyspace-name: "mykeyspace"
    contact-points: "cassandrahost1,cassandrahost2"
    local-datacenter: "datacenter1"
    ssl:
      bundle: "example"
----

[NOTE]
====
Cassandra driver có configuration infrastructure riêng, infrastructure này load `application.conf` ở root của classpath.

Spring Boot mặc định không tìm file này nhưng có thể load file bằng `spring.cassandra.config`.
Nếu một property xuất hiện cả trong `+spring.cassandra.*+` và configuration file, giá trị trong `+spring.cassandra.*+` sẽ được ưu tiên.

Để thực hiện các driver customization nâng cao, bạn có thể register tùy ý số lượng bean triển khai javadoc:org.springframework.boot.cassandra.autoconfigure.DriverConfigLoaderBuilderCustomizer[].
`CqlSession` có thể được customize bằng bean kiểu javadoc:org.springframework.boot.cassandra.autoconfigure.CqlSessionBuilderCustomizer[].
====

NOTE: Nếu dùng `CqlSessionBuilder` để tạo nhiều `CqlSession` bean, hãy nhớ rằng builder là mutable, vì vậy cần inject một fresh copy cho mỗi session.

== Couchbase

https://www.couchbase.com/[Couchbase] là open-source, distributed, multi-model NoSQL document-oriented database được tối ưu cho interactive application.
Spring Boot cung cấp auto-configuration cho Couchbase và các abstraction phía trên nó do https://github.com/spring-projects/spring-data-couchbase[Spring Data Couchbase] cung cấp.
Có các starter `spring-boot-starter-data-couchbase` và `spring-boot-starter-data-couchbase-reactive` để tập hợp các dependency theo cách thuận tiện.

[[data.nosql.couchbase.connecting]]
=== Kết nối Couchbase

Bạn có thể lấy javadoc:com.couchbase.client.java.Cluster[] bằng cách thêm Couchbase SDK và một số configuration.
Các property `spring.couchbase.*` có thể được dùng để customize connection.
Thông thường, bạn cung cấp https://docs.couchbase.com/dotnet-sdk/current/howtos/managing-connections.html[connection string] và credential để authentication. Basic authentication với username và password có thể được cấu hình như trong ví dụ sau:

[configprops,yaml]
----
spring:
  couchbase:
    connection-string: "couchbase://192.168.1.123"
    username: "user"
    password: "secret"
----

https://docs.couchbase.com/server/current/manage/manage-security/configure-client-certificates.html[Client certificates] có thể được dùng để authentication thay cho username và password.
Location và password của Java KeyStore chứa client certificates có thể được cấu hình như trong ví dụ sau:

[configprops,yaml]
----
spring:
  couchbase:
    connection-string: "couchbase://192.168.1.123"
    env:
      ssl:
        enabled: true
    authentication:
      jks:
        location: "classpath:client.p12"
        password: "secret"
----

PEM-encoded certificates và private key có thể được cấu hình như trong ví dụ sau:

[configprops,yaml]
----
spring:
  couchbase:
    connection-string: "couchbase://192.168.1.123"
    env:
      ssl:
        enabled: true
    authentication:
      pem:
        certificates: "classpath:client.crt"
        private-key: "classpath:client.key"
----

Cũng có thể customize một số setting của javadoc:com.couchbase.client.java.env.ClusterEnvironment[].
Ví dụ, configuration sau thay đổi timeout để mở một javadoc:com.couchbase.client.java.Bucket[] mới và bật SSL support bằng reference tới một xref:features/ssl.adoc[SSL bundle] đã cấu hình:

[configprops,yaml]
----
spring:
  couchbase:
    env:
      timeouts:
        connect: "3s"
      ssl:
        bundle: "example"
----

TIP: Kiểm tra các property `spring.couchbase.env.*` để biết thêm chi tiết.
Để kiểm soát nhiều hơn, có thể dùng một hoặc nhiều bean javadoc:org.springframework.boot.couchbase.autoconfigure.ClusterEnvironmentBuilderCustomizer[].

[[data.nosql.ldap]]
== LDAP

https://en.wikipedia.org/wiki/Lightweight_Directory_Access_Protocol[LDAP] (Lightweight Directory Access Protocol) là open, vendor-neutral, industry-standard application protocol để truy cập và duy trì distributed directory information service qua IP network.
Spring Boot cung cấp auto-configuration cho mọi compliant LDAP server, cũng như support cho embedded in-memory LDAP server từ https://ldap.com/unboundid-ldap-sdk-for-java/[UnboundID].

LDAP abstraction được cung cấp bởi https://github.com/spring-projects/spring-data-ldap[Spring Data LDAP].
Có starter `spring-boot-starter-data-ldap` để tập hợp các dependency theo cách thuận tiện.

[[data.nosql.ldap.connecting]]
=== Kết nối tới LDAP Server

Để kết nối tới LDAP server, hãy khai báo dependency trên starter `spring-boot-starter-data-ldap` hoặc `spring-ldap-core`, sau đó khai báo URL của server trong `application.properties` của application, như trong ví dụ sau:

[configprops,yaml]
----
spring:
  ldap:
    urls: "ldap://myserver:1235"
    username: "admin"
    password: "secret"
----

Nếu cần customize connection setting, bạn có thể dùng các property `spring.ldap.base` và `spring.ldap.base-environment`.

javadoc:org.springframework.ldap.core.support.LdapContextSource[] được auto-configure dựa trên các setting này.
Nếu bean javadoc:org.springframework.ldap.core.support.DirContextAuthenticationStrategy[] có sẵn, nó được liên kết với javadoc:org.springframework.ldap.core.support.LdapContextSource[].
Nếu cần customize, ví dụ dùng javadoc:org.springframework.ldap.pool2.factory.PooledContextSource[], vẫn có thể inject auto-configured javadoc:org.springframework.ldap.core.support.LdapContextSource[].
Hãy đánh dấu custom javadoc:org.springframework.ldap.core.ContextSource[] là javadoc:org.springframework.context.annotation.Primary[format=annotation] để auto-configured javadoc:org.springframework.ldap.core.LdapTemplate[] sử dụng nó.

[[data.nosql.ldap.ssl]]
=== SSL

Để kết nối bằng LDAPS, cấu hình xref:features/ssl.adoc[SSL bundle] cần dùng qua property configprop:spring.ldap.ssl.bundle[], và dùng URL `ldaps://` trong property configprop:spring.ldap.urls[], như ví dụ sau:

[configprops,yaml]
----
spring:
  ldap:
    urls: "ldaps://myserver:636"
    ssl:
      bundle: "example"
----

Việc đặt configprop:spring.ldap.ssl.bundle[] cũng chuyển URL mặc định thành `ldaps://localhost:636`, vì vậy configprop:spring.ldap.urls[] chỉ cần được set khi kết nối tới host hoặc port khác.

NOTE: SSL chỉ được hỗ trợ khi kết nối qua `ldaps://`. Bật SSL trong khi bất kỳ URL nào đã cấu hình sử dụng scheme `ldap://` sẽ dẫn tới startup failure.

Các property này không cấu hình StartTLS. StartTLS nâng cấp một connection `ldap://` thường thay vì dùng LDAPS, do đó không thể kết hợp với SSL bundle.
Để dùng StartTLS, hãy định nghĩa bean javadoc:org.springframework.ldap.core.support.DirContextAuthenticationStrategy[] như javadoc:org.springframework.ldap.core.support.DefaultTlsDirContextAuthenticationStrategy[] và đặt SSL socket factory cần dùng trên bean đó.

Nếu cần SSL support mà không customize trust và key material, hãy đặt property configprop:spring.ldap.ssl.enabled[] thành `true` thay vì cung cấp bundle.
Cách này sử dụng trust và key material mặc định của platform.

WARNING: Các property này chỉ áp dụng cho auto-configured javadoc:org.springframework.ldap.core.support.LdapContextSource[].
Nếu bạn tự định nghĩa context source, phải tự cấu hình SSL cho nó.
Nếu bạn tự định nghĩa bean javadoc:org.springframework.boot.ldap.autoconfigure.LdapConnectionDetails[], kể cả bean do một `@ServiceConnection` đóng góp, auto-configured context source sẽ dùng SSL bundle mà bean đó cung cấp.
Một connection `ldaps://` chưa được cung cấp key hoặc trust material sẽ âm thầm dùng giá trị mặc định của platform thay vì fail.

TIP: Các property này cấu hình LDAP client và bị bỏ qua khi dùng embedded LDAP server.
Để bật SSL cho xref:data/nosql.adoc#data.nosql.ldap.embedded.ssl[embedded LDAP server], hãy dùng property riêng configprop:spring.ldap.embedded.ssl.bundle[]. Property này cung cấp certificate và private key của server cũng như trust material của client.

[[data.nosql.ldap.embedded]]
=== Embedded In-memory LDAP Server

Để phục vụ mục đích testing, Spring Boot hỗ trợ auto-configuration cho in-memory LDAP server từ https://ldap.com/unboundid-ldap-sdk-for-java/[UnboundID].
Để cấu hình server, thêm dependency `com.unboundid:unboundid-ldapsdk` và khai báo property configprop:spring.ldap.embedded.base-dn[] như sau:

[configprops,yaml]
----
spring:
  ldap:
    embedded:
      base-dn: "dc=spring,dc=io"
----

[NOTE]
====
Bạn có thể định nghĩa nhiều giá trị base-dn. Tuy nhiên, vì distinguished name thường chứa dấu phẩy nên phải định nghĩa chúng bằng notation đúng.

Trong YAML, bạn có thể dùng list notation. Trong properties file, phải include index như một phần của property name:

[configprops,yaml]
----
spring.ldap.embedded.base-dn:
- "dc=spring,dc=io"
- "dc=vmware,dc=com"
----
====

Mặc định, server start trên một random port và trigger regular LDAP support.

Nếu có file `schema.ldif` trên classpath, file đó sẽ được dùng để initialize server.
Nếu muốn load initialization script từ một resource khác, bạn cũng có thể dùng property configprop:spring.ldap.embedded.ldif[].

Mặc định, một standard schema được dùng để validate các file `LDIF`.
Bạn có thể tắt hoàn toàn validation bằng cách đặt property configprop:spring.ldap.embedded.validation.enabled[].
Nếu có custom attribute, bạn có thể dùng configprop:spring.ldap.embedded.validation.schema[] để định nghĩa custom attribute type hoặc object class.

Các property `spring.ldap.embedded` cấu hình server, trong khi các property `spring.ldap` còn lại cấu hình client kết nối tới server, như mô tả trong xref:data/nosql.adoc#data.nosql.ldap[LDAP].
Mọi thứ mô tả chính connection đều được lấy từ server, vì chỉ server mới xác định được connection tới nó sẽ trông như thế nào:

* Client kết nối tới port và scheme mà server đang listen, vì vậy configprop:spring.ldap.urls[] bị bỏ qua.
* Client dùng credential từ configprop:spring.ldap.embedded.credential.username[] và configprop:spring.ldap.embedded.credential.password[], vì vậy configprop:spring.ldap.username[] và configprop:spring.ldap.password[] bị bỏ qua.
* Client dùng SSL bundle từ configprop:spring.ldap.embedded.ssl.bundle[], vì vậy `spring.ldap.ssl.*` bị bỏ qua.

Do đó, `spring.ldap` configuration dành cho production server không cần phải unset để chạy test với embedded server.
Các property còn lại, như configprop:spring.ldap.base[], configprop:spring.ldap.referral[] và `spring.ldap.base-environment.*`, vẫn được áp dụng như thường lệ.

TIP: Để cấu hình client theo cách khác, hãy định nghĩa bean javadoc:org.springframework.boot.ldap.autoconfigure.LdapConnectionDetails[] của riêng bạn.
Khi đó, auto-configured client sẽ dùng bean này và bỏ qua URL, credential cũng như SSL bundle của embedded server.

[[data.nosql.ldap.embedded.ssl]]
==== SSL

In-memory LDAP server hỗ trợ SSL (LDAPS).
Để bật SSL, hãy cấu hình xref:features/ssl.adoc[SSL bundle] cần dùng bằng cách đặt property configprop:spring.ldap.embedded.ssl.bundle[] như trong ví dụ sau:

[configprops,yaml]
----
spring:
  ldap:
    embedded:
      ssl:
        bundle: "example"
----

Bundle phải cung cấp certificate và private key của server.

NOTE: LDAPS yêu cầu SSL bundle. Đặt configprop:spring.ldap.embedded.ssl.enabled[] mà không có configprop:spring.ldap.embedded.ssl.bundle[] sẽ dẫn tới startup failure.

Auto-configured client kết nối tới server qua `ldaps://` bằng cùng bundle, vì vậy trust material của bundle phải trust certificate của server.

NOTE: Server quyết định có dùng TLS hay không và bundle nào bảo vệ connection.
Để client có SSL configuration riêng, hãy định nghĩa bean javadoc:org.springframework.boot.ldap.autoconfigure.LdapConnectionDetails[].
