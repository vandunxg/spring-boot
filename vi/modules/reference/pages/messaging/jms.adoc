[[messaging.jms]]
= JMS

Interface javadoc:jakarta.jms.ConnectionFactory[] cung cấp method chuẩn để tạo javadoc:jakarta.jms.Connection[] nhằm tương tác với JMS broker.
Mặc dù Spring cần javadoc:jakarta.jms.ConnectionFactory[] để làm việc với JMS, nhìn chung bạn không cần tự mình sử dụng trực tiếp interface này mà có thể dựa vào các messaging abstraction cấp cao hơn.
(Xem {url-spring-framework-docs}/integration/jms.html[phần liên quan] trong tài liệu reference của Spring Framework để biết chi tiết.)
Spring Boot cũng auto-configure infrastructure cần thiết để send và receive message.

[[messaging.jms.activemq]]
== Hỗ trợ ActiveMQ "Classic"

Khi https://activemq.apache.org/components/classic[ActiveMQ "Classic"] có trên classpath, Spring Boot có thể cấu hình javadoc:jakarta.jms.ConnectionFactory[].
Nếu broker có mặt, embedded broker sẽ tự động được start và configure, với điều kiện không có broker URL nào được chỉ định thông qua configuration và embedded broker không bị disable trong configuration.

NOTE: Nếu dùng `spring-boot-starter-activemq`, các dependency cần thiết để kết nối tới một instance ActiveMQ "Classic" được cung cấp, cũng như Spring infrastructure để tích hợp với JMS.
Thêm `org.apache.activemq:activemq-broker` vào application cho phép dùng embedded broker.

Configuration của ActiveMQ "Classic" được điều khiển bởi các external configuration properties trong `+spring.activemq.*+`.

Nếu `activemq-broker` có trên classpath, ActiveMQ "Classic" được auto-configure dùng https://activemq.apache.org/vm-transport-reference.html[VM transport], khởi động broker embedded trong cùng JVM.

Có thể disable embedded broker bằng cách cấu hình configprop:spring.activemq.embedded.enabled[] property, như ví dụ sau:

[configprops,yaml]
----
spring:
  activemq:
    embedded:
      enabled: false
----

Embedded broker cũng sẽ bị disable nếu bạn cấu hình broker URL, như ví dụ sau:

[configprops,yaml]
----
spring:
  activemq:
    broker-url: "tcp://192.168.1.210:9876"
    user: "admin"
    password: "secret"
----

Nếu muốn kiểm soát hoàn toàn embedded broker, xem https://activemq.apache.org/how-do-i-embed-a-broker-inside-a-connection.html[tài liệu ActiveMQ "Classic"] để biết thêm thông tin.

Mặc định, javadoc:org.springframework.jms.connection.CachingConnectionFactory[] wrap native javadoc:jakarta.jms.ConnectionFactory[] với các setting hợp lý mà bạn có thể control bằng external configuration property trong `+spring.jms.*+`:

[configprops,yaml]
----
spring:
  jms:
    cache:
      session-cache-size: 5
----

Nếu muốn dùng native pooling, bạn có thể thêm dependency `org.messaginghub:pooled-jms` và cấu hình javadoc:org.messaginghub.pooled.jms.JmsPoolConnectionFactory[] tương ứng, như ví dụ sau:

[configprops,yaml]
----
spring:
  activemq:
    pool:
      enabled: true
      max-connections: 50
----

TIP: Xem javadoc:org.springframework.boot.activemq.autoconfigure.ActiveMQProperties[] để biết thêm các option được hỗ trợ.
Bạn cũng có thể register số lượng tùy ý bean implement javadoc:org.springframework.boot.activemq.autoconfigure.ActiveMQConnectionFactoryCustomizer[] để thực hiện các customization nâng cao.

Mặc định, ActiveMQ "Classic" tạo destination nếu destination đó chưa tồn tại, vì vậy các destination được resolve dựa trên name đã cung cấp.

[[messaging.jms.artemis]]
== Hỗ trợ ActiveMQ Artemis

Spring Boot có thể auto-configure javadoc:jakarta.jms.ConnectionFactory[] khi phát hiện https://activemq.apache.org/components/artemis/[ActiveMQ Artemis] trên classpath.
Nếu broker có mặt, embedded broker sẽ tự động được start và configure, trừ khi mode property đã được set rõ ràng.
Các mode được hỗ trợ là `embedded` (để nêu rõ rằng cần có embedded broker và sẽ phát sinh error nếu broker không available trên classpath) và `native` (để connect tới broker bằng `netty` transport protocol).
Khi mode `native` được configure, Spring Boot sẽ cấu hình javadoc:jakarta.jms.ConnectionFactory[] kết nối tới broker đang chạy trên local machine bằng các setting mặc định.

NOTE: Nếu dùng `spring-boot-starter-artemis`, các dependency cần thiết để kết nối tới một instance ActiveMQ Artemis hiện có được cung cấp, cũng như Spring infrastructure để tích hợp với JMS.
Thêm `org.apache.activemq:artemis-jakarta-server` vào application để dùng embedded mode.

Configuration của ActiveMQ Artemis được điều khiển bởi các external configuration properties trong `+spring.artemis.*+`.
Ví dụ, bạn có thể khai báo section sau trong `application.properties`:

[configprops,yaml]
----
spring:
  artemis:
    mode: native
    broker-url: "tcp://192.168.1.210:9876"
    user: "admin"
    password: "secret"
----

Khi embed broker, bạn có thể chọn bật persistence và liệt kê các destination cần được cung cấp.
Có thể chỉ định các destination này dưới dạng comma-separated list để tạo chúng với các option mặc định, hoặc định nghĩa bean(s) có type javadoc:org.apache.activemq.artemis.jms.server.config.JMSQueueConfiguration[] hoặc javadoc:org.apache.activemq.artemis.jms.server.config.TopicConfiguration[] để có advanced queue và topic configuration tương ứng.

Mặc định, javadoc:org.springframework.jms.connection.CachingConnectionFactory[] wrap native javadoc:jakarta.jms.ConnectionFactory[] với các setting hợp lý mà bạn có thể control bằng external configuration property trong `+spring.jms.*+`:

[configprops,yaml]
----
spring:
  jms:
    cache:
      session-cache-size: 5
----

Nếu muốn dùng native pooling, bạn có thể thêm dependency `org.messaginghub:pooled-jms` và cấu hình javadoc:org.messaginghub.pooled.jms.JmsPoolConnectionFactory[] tương ứng, như ví dụ sau:

[configprops,yaml]
----
spring:
  artemis:
    pool:
      enabled: true
      max-connections: 50
----

Xem javadoc:org.springframework.boot.artemis.autoconfigure.ArtemisProperties[] để biết thêm các option được hỗ trợ.

Không có JNDI lookup, và các destination được resolve dựa trên name của chúng, sử dụng một trong hai nguồn: attribute `name` trong ActiveMQ Artemis configuration hoặc các name được cung cấp thông qua configuration.

[[messaging.jms.jndi]]
== Sử dụng JNDI ConnectionFactory

Nếu application chạy trong application server, Spring Boot sẽ thử locate JMS javadoc:jakarta.jms.ConnectionFactory[] bằng JNDI.
Mặc định, các location `java:/JmsXA` và `java:/XAConnectionFactory` sẽ được kiểm tra.
Có thể dùng configprop:spring.jms.jndi-name[] property nếu cần chỉ định location khác, như ví dụ sau:

[configprops,yaml]
----
spring:
  jms:
    jndi-name: "java:/MyConnectionFactory"
----

[[messaging.jms.receiving]]
== Nhận Message

Khi JMS infrastructure có mặt, bean có thể annotate javadoc:org.springframework.jms.annotation.JmsListener[format=annotation] để tạo listener endpoint.
Nếu chưa định nghĩa javadoc:org.springframework.jms.config.JmsListenerContainerFactory[], default factory được cấu hình tự động.
Nếu có bean javadoc:org.springframework.jms.support.destination.DestinationResolver[], javadoc:org.springframework.jms.support.converter.MessageConverter[] hoặc javadoc:jakarta.jms.ExceptionListener[], chúng tự động liên kết với default factory.

Trong hầu hết scenario, message listener container nên được cấu hình với native javadoc:jakarta.jms.ConnectionFactory[].
Theo cách này, mỗi listener container có connection riêng và tự chịu hoàn toàn trách nhiệm về local recovery.
Auto-configuration dùng javadoc:org.springframework.boot.jms.ConnectionFactoryUnwrapper[] để unwrap native connection factory từ auto-configured factory.

NOTE: Auto-configuration chỉ unwrap `CachedConnectionFactory`.

Mặc định default factory là transactional.
Nếu application chạy trên infrastructure có javadoc:org.springframework.transaction.jta.JtaTransactionManager[], transaction manager này mặc định được liên kết với listener container.
Nếu không, flag `sessionTransacted` được bật.
Trong trường hợp không có JtaTransactionManager, bạn có thể liên kết local data store transaction với việc xử lý incoming message bằng cách thêm javadoc:org.springframework.transaction.annotation.Transactional[format=annotation] vào listener method (hoặc một delegate của method đó).
Điều này đảm bảo incoming message được acknowledged sau khi local transaction hoàn tất.
Điều này cũng bao gồm việc gửi response message trên cùng JMS session.
