= Giới thiệu GraalVM Native Images

GraalVM Native Images cung cấp một cách mới để deploy và chạy Java application.
So với Java Virtual Machine, native image có thể chạy với memory footprint nhỏ hơn và startup time nhanh hơn nhiều.

Chúng phù hợp với application được deploy bằng container image và đặc biệt đáng chú ý khi kết hợp các platform "Function as a service" (FaaS).

Khác với các application truyền thống được viết cho JVM, GraalVM Native Image application cần ahead-of-time processing để tạo executable.
Quá trình ahead-of-time này bao gồm việc statically analyze application code bắt đầu từ main entry point.

Một GraalVM Native Image là một executable hoàn chỉnh, platform-specific.
Không cần ship Java Virtual Machine để chạy native image.

TIP: Nếu chỉ muốn bắt đầu và thử GraalVM, có thể chuyển tới xref:how-to:native-image/developing-your-first-application.adoc[] rồi quay lại phần này sau.

[[packaging.native-image.introducing-graalvm-native-images.key-differences-with-jvm-deployments]]
== Khác biệt chính với JVM Deployment

Việc GraalVM Native Images được tạo ahead-of-time dẫn đến một số khác biệt quan trọng giữa native application và application dựa trên JVM.
Các khác biệt chính là:

* Static analysis của application được thực hiện ở build-time từ entry point `main`.
* Code không reachable khi native image được tạo sẽ bị remove và không nằm trong executable.
* GraalVM không trực tiếp nhận biết các dynamic element trong code và phải được cung cấp thông tin về reflection, resource, serialization và dynamic proxy.
* Application classpath cố định ở build time và không thể thay đổi.
* Không có lazy class loading; mọi thứ ship trong executable sẽ load vào memory khi startup.
* Có một số limitation đối với một số aspect của Java application chưa được hỗ trợ đầy đủ.

Ngoài các khác biệt đó, Spring dùng process gọi là xref:packaging/native-image/introducing-graalvm-native-images.adoc#packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing[Spring Ahead-of-Time processing], tạo thêm hạn chế.
Hãy đọc ít nhất phần đầu của section tiếp theo để tìm hiểu về các limitation đó.

TIP: Phần {url-graal-docs-native-image}/metadata/Compatibility/[Native Image Compatibility Guide] trong GraalVM reference documentation mô tả chi tiết hơn về limitation của GraalVM.

[[packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing]]
== Hiểu Spring Ahead-of-Time Processing

Spring Boot application điển hình khá dynamic và configuration diễn ra tại runtime.
Thực tế, concept Spring Boot auto-configuration phụ thuộc nhiều vào việc phản ứng với runtime state để configure chính xác.

Có thể nói cho GraalVM biết các dynamic aspect này, nhưng như vậy sẽ làm mất phần lớn lợi ích static analysis.
Vì vậy khi dùng Spring Boot tạo native image, closed-world assumption được áp dụng và dynamic aspect bị hạn chế.

Ngoài xref:packaging/native-image/introducing-graalvm-native-images.adoc#packaging.native-image.introducing-graalvm-native-images.key-differences-with-jvm-deployments[các limitation do chính GraalVM tạo ra], closed-world assumption dẫn đến các restriction sau:

* Các bean được định nghĩa trong application không thể thay đổi tại runtime, nghĩa là:
- Annotation Spring javadoc:org.springframework.context.annotation.Profile[format=annotation] và profile-specific configuration xref:how-to:aot.adoc#howto.aot.conditions[có hạn chế].
- Các property quyết định bean có được tạo hay không không được hỗ trợ, ví dụ javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnProperty[format=annotation] và các property `.enabled`.

Khi các restriction này được áp dụng, Spring có thể perform ahead-of-time processing ở build-time và generate asset bổ sung để GraalVM dùng.
Spring AOT processed application thường generate:

* Java source code
* Bytecode (cho dynamic proxies, v.v.)
* GraalVM JSON hint files trong `+META-INF/native-image/{groupId}/{artifactId}/+`:
  - Resource hints (`resource-config.json`)
  - Reflection hints (`reflect-config.json`)
  - Serialization hints (`serialization-config.json`)
  - Java Proxy hints (`proxy-config.json`)
  - JNI hints (`jni-config.json`)

Nếu các generated hints chưa đủ, có thể xref:packaging/native-image/advanced-topics.adoc#packaging.native-image.advanced.custom-hints[cung cấp hint riêng].

[[packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing.source-code-generation]]
=== Source Code Generation

Spring application được cấu thành từ các Spring Bean.
Bên trong, Spring Framework dùng hai concept khác nhau để manage bean.
Bean instance là các instance thực tế đã được tạo và có thể inject vào các bean khác.
Bean definition được dùng để define attribute của bean và cách instance của nó được tạo.

Nếu lấy một javadoc:org.springframework.context.annotation.Configuration[format=annotation] class điển hình:

include-code::MyConfiguration[]

Bean definition được tạo bằng cách parse class javadoc:org.springframework.context.annotation.Configuration[format=annotation] và tìm các method javadoc:org.springframework.context.annotation.Bean[format=annotation].
Trong ví dụ trên, một javadoc:org.springframework.beans.factory.config.BeanDefinition[] được định nghĩa cho singleton bean tên `myBean`.
Chúng ta cũng tạo một javadoc:org.springframework.beans.factory.config.BeanDefinition[] cho chính class `MyConfiguration`.

Khi cần instance `myBean`, Spring biết phải invoke method `myBean()` và dùng result.
Khi chạy trên JVM, việc parse javadoc:org.springframework.context.annotation.Configuration[format=annotation] class diễn ra lúc application start và các javadoc:org.springframework.context.annotation.Bean[format=annotation] method được invoke bằng reflection.

Khi tạo native image, Spring hoạt động theo cách khác.
Thay vì parse các javadoc:org.springframework.context.annotation.Configuration[format=annotation] class và generate bean definition tại runtime, Spring thực hiện việc đó ở build-time.
Sau khi bean definition được discover, chúng được process và convert thành source code GraalVM compiler có thể analyze.

Spring AOT process sẽ convert configuration class ở trên thành code như sau:

include-code::MyConfiguration__BeanDefinitions[]

NOTE: Exact generated code có thể khác tùy bản chất bean definition.

Bạn có thể thấy ở trên rằng generated code tạo các bean definition tương đương với javadoc:org.springframework.context.annotation.Configuration[format=annotation] class, nhưng theo cách trực tiếp mà GraalVM có thể hiểu được.

Có một bean definition cho bean `myConfiguration` và một bean definition cho `myBean`.
Khi cần instance `myBean`, javadoc:org.springframework.beans.factory.aot.BeanInstanceSupplier[] được gọi.
Supplier này sẽ invoke method `myBean()` trên bean `myConfiguration`.

NOTE: Trong Spring AOT processing, application được start tới thời điểm bean definition available.
Bean instance không được tạo trong AOT processing phase.

Spring AOT sẽ generate code như vậy cho mọi bean definition.
Nó cũng sẽ generate code khi cần bean post-processing, ví dụ để gọi các method javadoc:org.springframework.beans.factory.annotation.Autowired[format=annotation].
Một javadoc:org.springframework.context.ApplicationContextInitializer[] cũng sẽ được generate và Spring Boot sẽ dùng nó để initialize javadoc:org.springframework.context.ApplicationContext[] khi AOT processed application thực sự chạy.

TIP: Dù AOT generated source code có thể verbose, nó khá readable và hữu ích khi debug.
Generated source files nằm ở `target/spring-aot/main/sources` khi dùng Maven và `build/generated/aotSources` với Gradle.

[[packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing.hint-file-generation]]
=== Hint File Generation

Ngoài việc generate source files, Spring AOT engine còn generate hint files cho GraalVM.
Hint files chứa JSON data mô tả cách GraalVM nên xử lý những thứ không thể hiểu bằng cách inspect code trực tiếp.

Ví dụ, application có thể dùng Spring annotation trên một private method.
Spring sẽ cần reflection để invoke private method, kể cả trên GraalVM.
Khi xảy ra tình huống như vậy, Spring có thể ghi reflection hint để GraalVM biết rằng private method vẫn phải available trong native image dù không được gọi trực tiếp.

Các hint files được generate dưới `META-INF/native-image`, nơi GraalVM tự động pick up.

TIP: Các generated hint files nằm ở `target/spring-aot/main/resources` với Maven và `build/generated/aotResources` với Gradle.

[[packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing.proxy-class-generation]]
=== Proxy Class Generation

Spring đôi khi cần generate các proxy class để enhance code bạn viết với các feature bổ sung.
Nó dùng library cglib để generate bytecode trực tiếp.

Khi application chạy trên JVM, các proxy class được generate dynamically trong lúc application chạy.
Khi tạo native image, các proxy này phải được tạo ở build-time để GraalVM có thể include chúng.

NOTE: Khác với source code generation, generated bytecode không đặc biệt hữu ích khi debug application.
Tuy nhiên, nếu cần inspect content của các file `.class` bằng tool như `javap`, bạn có thể tìm thấy chúng ở `target/spring-aot/main/classes` với Maven và `build/generated/aotClasses` với Gradle.
