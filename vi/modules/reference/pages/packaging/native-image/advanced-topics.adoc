[[packaging.native-image.advanced.converting-executable-jars]]
== Chuyển đổi Spring Boot Executable Jar

Có thể chuyển đổi Spring Boot xref:specification:executable-jar/index.adoc[executable jar] thành native image miễn là jar chứa các asset được AOT generate.
Điều này hữu ích vì:

* Bạn có thể giữ regular JVM pipeline và chuyển đổi JVM application thành native image trên CI/CD platform.
* Vì `native-image` https://github.com/oracle/graal/issues/407[không hỗ trợ cross-compilation], bạn có thể giữ OS-neutral deployment artifact rồi chuyển đổi sau sang các OS architecture khác nhau.

Có thể chuyển đổi Spring Boot executable jar thành native image bằng Cloud Native Buildpacks hoặc tool `native-image` đi kèm GraalVM.

NOTE: Executable jar phải include các asset được AOT generate, như generated class và JSON hint file.



[[packaging.native-image.advanced.converting-executable-jars.buildpacks]]
=== Sử dụng Buildpacks

Spring Boot application thường dùng Cloud Native Buildpacks thông qua integration của Maven (`mvn spring-boot:build-image`) hoặc Gradle (`gradle bootBuildImage`).
Tuy nhiên, bạn cũng có thể dùng {url-buildpacks-docs}/for-platform-operators/how-to/integrate-ci/pack/[`pack`] để chuyển AOT-processed Spring Boot executable jar thành native container image.

NOTE: Bạn phải build application bằng ít nhất JDK 25, vì Buildpacks dùng cùng GraalVM native-image version với Java version được dùng để compile.

Trước tiên, hãy đảm bảo Docker daemon available (xem https://docs.docker.com/installation/#installation[Cài đặt Docker] để biết thêm chi tiết).
Nếu dùng Linux, hãy https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user[cấu hình Docker để non-root user có thể sử dụng].

Bạn cũng cần install `pack` theo {url-buildpacks-docs}/for-platform-operators/how-to/integrate-ci/pack/#install[hướng dẫn cài đặt trên buildpacks.io].

Giả sử AOT-processed Spring Boot executable jar có tên `myproject-0.0.1-SNAPSHOT.jar` nằm trong thư mục `target`, hãy chạy:

[source,shell]
----
$ pack build --builder paketobuildpacks/builder-noble-java-tiny \
    --path target/myproject-0.0.1-SNAPSHOT.jar \
    --env 'BP_NATIVE_IMAGE=true' \
    my-application:0.0.1-SNAPSHOT
----

NOTE: Bạn không cần local GraalVM installation để generate image theo cách này.

Sau khi `pack` hoàn tất, bạn có thể launch application bằng `docker run`:

[source,shell]
----
$ docker run --rm -p 8080:8080 docker.io/library/myproject:0.0.1-SNAPSHOT
----



[[packaging.native-image.advanced.converting-executable-jars.native-image]]
=== Sử dụng GraalVM native-image

Một lựa chọn khác để chuyển AOT-processed Spring Boot executable jar thành native executable là dùng tool `native-image` của GraalVM.
Để thực hiện việc này, bạn cần một GraalVM distribution trên machine.
Bạn có thể download thủ công từ {url-download-liberica-nik}[trang Liberica Native Image Kit] hoặc dùng download manager như SDKMAN!.

Giả sử AOT-processed Spring Boot executable jar có tên `myproject-0.0.1-SNAPSHOT.jar` nằm trong thư mục `target`, hãy chạy:

[source,shell]
----
$ rm -rf target/native
$ mkdir -p target/native
$ cd target/native
$ jar -xvf ../myproject-0.0.1-SNAPSHOT.jar
$ native-image -H:Name=myproject @META-INF/native-image/argfile -cp .:BOOT-INF/classes:`find BOOT-INF/lib | tr '\n' ':'`
$ mv myproject ../
----

NOTE: Các command này hoạt động trên Linux hoặc macOS, nhưng bạn cần adapt chúng cho Windows.

TIP: `@META-INF/native-image/argfile` có thể không được package trong jar.
File này chỉ được include khi cần reachability metadata override.

WARNING: Flag `-cp` của `native-image` không accept wildcard.
Bạn phải đảm bảo mọi jar đều được liệt kê (command trên dùng `find` và `tr` để thực hiện việc này).



[[packaging.native-image.advanced.using-the-tracing-agent]]
== Sử dụng Tracing Agent

GraalVM native image {url-graal-docs-native-image}/metadata/AutomaticMetadataCollection[tracing agent] cho phép intercept việc sử dụng reflection, resources hoặc proxy trên JVM để generate các hint tương ứng.
Spring sẽ tự động generate phần lớn các hint này, nhưng tracing agent có thể được dùng để nhanh chóng identify các entry còn thiếu.

Khi dùng agent để generate hint cho native image, có một vài cách tiếp cận:

* Launch application trực tiếp và exercise application.
* Chạy application test để exercise application.

Lựa chọn đầu tiên hữu ích để identify các hint còn thiếu khi Spring không nhận biết một library hoặc pattern.

Lựa chọn thứ hai hấp dẫn hơn cho repeatable setup, nhưng theo mặc định generated hint sẽ include mọi thứ mà test infrastructure cần.
Một số trong đó không cần thiết khi application chạy thực tế.
Để giải quyết vấn đề này, agent hỗ trợ access-filter file, khiến một số data nhất định bị loại khỏi generated output.



[[packaging.native-image.advanced.using-the-tracing-agent.launch]]
=== Khởi chạy Application trực tiếp

Dùng command sau để launch application với native image tracing agent:

[source,shell,subs="verbatim,attributes"]
----
$ java -Dspring.aot.enabled=true \
    -agentlib:native-image-agent=config-output-dir=/path/to/config-dir/ \
    -jar target/myproject-0.0.1-SNAPSHOT.jar
----

Bạn có thể exercise các code path cần hint, sau đó stop application bằng `ctrl-c`.

Khi application shutdown, tracing agent sẽ ghi các hint file vào config output directory.
Bạn có thể inspect thủ công các file này hoặc dùng chúng làm input cho native image build.
Để dùng làm input, hãy copy chúng vào `src/main/resources/META-INF/native-image/`.
Ở lần build native image tiếp theo, GraalVM sẽ tính đến các file này.

Tracing agent còn có các advanced option, ví dụ filter các hint đã ghi theo caller class.
Để biết thêm thông tin, hãy xem {url-graal-docs-native-image}/metadata/AutomaticMetadataCollection[tài liệu chính thức].

== Hints tùy chỉnh

Nếu cần cung cấp hint riêng cho reflection, resources, serialization, proxy usage, v.v., bạn có thể dùng API javadoc:org.springframework.aot.hint.RuntimeHintsRegistrar[].
Tạo một class implement interface javadoc:org.springframework.aot.hint.RuntimeHintsRegistrar[] và sau đó gọi các method phù hợp trên instance javadoc:org.springframework.aot.hint.RuntimeHints[] được cung cấp:

include-code::MyRuntimeHints[]

Sau đó, bạn có thể dùng javadoc:org.springframework.context.annotation.ImportRuntimeHints[format=annotation] trên bất kỳ class nào có annotation javadoc:org.springframework.context.annotation.Configuration[format=annotation] (ví dụ application class có annotation javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation]) để activate các hint đó.

Nếu có class cần binding, chủ yếu khi serialize hoặc deserialize JSON, bạn có thể dùng {url-spring-framework-docs}/core/aot.html#aot.hints.register-reflection[`@RegisterReflectionForBinding`] trên bất kỳ bean nào.
Phần lớn hint được infer tự động, ví dụ khi nhận hoặc trả data từ một method javadoc:org.springframework.web.bind.annotation.RestController[format=annotation].
Tuy nhiên, khi làm việc trực tiếp với javadoc:org.springframework.web.reactive.function.client.WebClient[] hoặc javadoc:org.springframework.web.client.RestClient[], bạn có thể cần dùng javadoc:org.springframework.aot.hint.annotation.RegisterReflectionForBinding[format=annotation].

[[packaging.native-image.advanced.custom-hints.static]]
=== Cung cấp Hints tĩnh
Nếu muốn, custom hints có thể được cung cấp statically trong một hoặc nhiều GraalVM JSON hint file.
Các file này nên được đặt trong `src/main/resources/` bên trong một directory `+META-INF/native-image/*/*/+`.
Các xref:packaging/native-image/introducing-graalvm-native-images.adoc#packaging.native-image.introducing-graalvm-native-images.understanding-aot-processing[hint được generate trong AOT processing] được ghi vào directory `+META-INF/native-image/{groupId}/{artifactId}/+`.
Đặt static hint file trong một directory không conflict với vị trí này, chẳng hạn `+META-INF/native-image/{groupId}/{artifactId}-additional-hints/+`.



[[packaging.native-image.advanced.known-limitations]]
== Các giới hạn đã biết

GraalVM native images là một technology đang phát triển và không phải library nào cũng support.
GraalVM community đang hỗ trợ bằng cách cung cấp https://github.com/oracle/graalvm-reachability-metadata[reachability metadata] cho các project chưa tự ship metadata.
Bản thân Spring không chứa hints cho third-party libraries mà thay vào đó dựa vào reachability metadata project.

Nếu gặp vấn đề khi generate native image cho Spring Boot application, hãy xem trang {url-github-wiki}/Spring-Boot-with-GraalVM[Spring Boot with GraalVM] trên Spring Boot wiki.
Bạn cũng có thể contribute issues cho project https://github.com/spring-projects/spring-aot-smoke-tests[spring-aot-smoke-tests] trên GitHub; project này được dùng để xác nhận các common application types hoạt động như mong đợi.

Nếu tìm thấy library không hoạt động với GraalVM, hãy tạo issue trên https://github.com/oracle/graalvm-reachability-metadata[reachability metadata project].
