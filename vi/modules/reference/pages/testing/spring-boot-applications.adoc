[[testing.spring-boot-applications]]
= Testing Spring Boot Applications

Spring Boot application là Spring javadoc:org.springframework.context.ApplicationContext[], vì vậy ngoài những gì thường làm với vanilla Spring context thì không cần gì quá đặc biệt để test.

NOTE: External property, logging và các feature khác của Spring Boot mặc định chỉ được install vào context nếu dùng javadoc:org.springframework.boot.SpringApplication[] để tạo context.

Spring Boot cung cấp annotation javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation], có thể dùng thay standard `spring-test` javadoc:org.springframework.test.context.ContextConfiguration[format=annotation] khi cần Spring Boot feature.
Annotation hoạt động bằng cách xref:testing/spring-boot-applications.adoc#testing.spring-boot-applications.detecting-configuration[tạo javadoc:org.springframework.context.ApplicationContext[] dùng trong test thông qua javadoc:org.springframework.boot.SpringApplication[]].
Ngoài javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation], còn có nhiều annotation khác để xref:testing/spring-boot-applications.adoc#testing.spring-boot-applications.autoconfigured-tests[test các slice cụ thể hơn] của application.

TIP: Nếu dùng JUnit 4, đừng quên thêm `@RunWith(SpringRunner.class)` vào test, nếu không annotation sẽ bị ignore.
Nếu dùng JUnit 6, không cần thêm `@ExtendWith(SpringExtension.class)` vì javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation] và các annotation `@...Test` khác đã annotate sẵn.

Mặc định javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation] không start server.
Có thể dùng attribute `webEnvironment` để điều chỉnh cách test chạy:

* `MOCK` (default): Load web javadoc:org.springframework.context.ApplicationContext[] và cung cấp mock web environment.
  Embedded server không start.
  Nếu classpath không có web environment, mode này tự fallback sang regular non-web javadoc:org.springframework.context.ApplicationContext[].
  Có thể dùng cùng xref:testing/spring-boot-applications.adoc#testing.spring-boot-applications.with-mock-environment[`@AutoConfigureMockMvc`, javadoc:org.springframework.boot.resttestclient.autoconfigure.AutoConfigureRestTestClient[format=annotation], hoặc javadoc:org.springframework.boot.webtestclient.autoconfigure.AutoConfigureWebTestClient[format=annotation]] để test web application dựa trên mock.
* `RANDOM_PORT`: Load javadoc:org.springframework.boot.web.server.context.WebServerApplicationContext[] và cung cấp real web environment.
  Embedded server start và listen random port.
* `DEFINED_PORT`: Load javadoc:org.springframework.boot.web.server.context.WebServerApplicationContext[] và cung cấp real web environment.
  Embedded server start và listen port được định nghĩa trong `application.properties` hoặc default `8080`.
* `NONE`: Load javadoc:org.springframework.context.ApplicationContext[] bằng javadoc:org.springframework.boot.SpringApplication[] nhưng không cung cấp web environment nào, kể cả mock.

NOTE: Nếu test annotate javadoc:org.springframework.transaction.annotation.Transactional[format=annotation], mặc định transaction rollback ở cuối mỗi test method.
Tuy nhiên với `RANDOM_PORT` hoặc `DEFINED_PORT`, real servlet environment được cung cấp ngầm, HTTP client và server chạy ở thread khác nhau nên transaction cũng khác nhau.
Transaction được tạo phía server sẽ không rollback trong trường hợp này.

NOTE: javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation] với `webEnvironment = WebEnvironment.RANDOM_PORT` cũng start management server trên random port riêng nếu application dùng management server port khác.

[[testing.spring-boot-applications.detecting-configuration]]
== Detect Test Configuration

Nếu quen Spring Test Framework, bạn có thể thường dùng `@ContextConfiguration(classes=...)` để chỉ định Spring javadoc:org.springframework.context.annotation.Configuration[format=annotation] cần load.
Hoặc có thể dùng nested javadoc:org.springframework.context.annotation.Configuration[format=annotation] class trong test.

Khi test Spring Boot application, điều này thường không cần thiết.
Các annotation `@*Test` của Spring Boot tự động tìm primary configuration nếu bạn không explicit define.

Search algorithm đi từ package chứa test lên trên cho tới khi tìm class annotate javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] hoặc javadoc:org.springframework.boot.SpringBootConfiguration[format=annotation].
Miễn là xref:using/structuring-your-code.adoc[code được structure hợp lý], main configuration thường được tìm thấy.

[NOTE]
====
Nếu dùng xref:testing/spring-boot-applications.adoc#testing.spring-boot-applications.autoconfigured-tests[test annotation để test slice cụ thể hơn], nên tránh đặt configuration setting đặc thù cho một area trên xref:testing/spring-boot-applications.adoc#testing.spring-boot-applications.user-configuration-and-slicing[application class chứa main method].

Underlying component scan configuration của javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] định nghĩa exclude filter để slicing hoạt động đúng.
Nếu dùng explicit javadoc:org.springframework.context.annotation.ComponentScan[format=annotation] trên class annotate javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation], các filter đó bị disable.
Nếu dùng slicing, cần định nghĩa lại chúng.
====

Nếu muốn customize primary configuration, dùng nested class javadoc:org.springframework.boot.test.context.TestConfiguration[format=annotation].
Khác nested javadoc:org.springframework.context.annotation.Configuration[format=annotation] dùng thay primary configuration của application, nested javadoc:org.springframework.boot.test.context.TestConfiguration[format=annotation] được dùng bổ sung cùng primary configuration.

NOTE: Spring test framework cache application context giữa các test.
Do đó miễn là test share cùng configuration, bất kể được discover theo cách nào, quá trình load context tốn thời gian chỉ diễn ra một lần.

[[testing.spring-boot-applications.autoconfigured-tests]]
== Auto-configured Tests

Auto-configuration system của Spring Boot phù hợp cho application nhưng đôi khi quá nhiều cho test.
Thường hữu ích khi chỉ load phần configuration cần để test một "`slice`".
Ví dụ có thể muốn test Spring MVC controller map URL đúng mà không gọi database, hoặc test JPA entity mà không quan tâm web layer.

Khi kết hợp với `spring-boot-test-autoconfigure`, xref:reference:testing/test-modules.adoc[test module] của Spring Boot cung cấp nhiều annotation để auto-configure các "`slice`".
Mỗi annotation hoạt động tương tự: cung cấp `@...Test` load javadoc:org.springframework.context.ApplicationContext[] và một hoặc nhiều `@AutoConfigure...` customize auto-configuration setting.

NOTE: Mỗi slice giới hạn component scan vào component phù hợp và load rất ít auto-configuration class.
Nếu cần exclude một class, phần lớn `@...Test` có attribute `excludeAutoConfiguration`.
Ngoài ra dùng `@ImportAutoConfiguration#exclude`.

NOTE: Không hỗ trợ include nhiều "`slice`" bằng nhiều `@...Test` trên cùng test.
Nếu cần nhiều slice, chọn một `@...Test` rồi thêm thủ công `@AutoConfigure...` từ slice khác.

TIP: Cũng có thể dùng `@AutoConfigure...` cùng standard javadoc:org.springframework.boot.test.context.SpringBootTest[format=annotation].
Dùng combination này nếu không cần slicing application nhưng muốn một số auto-configured test bean.

Ngoài ra có thể thêm auto-configuration cho mọi usage của slice annotation bằng file trong `META-INF/spring`:
