[[io.rest-client]]
= Gọi REST Service

Spring Boot cung cấp nhiều cách thuận tiện để gọi remote REST service.
Nếu đang phát triển reactive application non-blocking và sử dụng Spring WebFlux, bạn có thể dùng javadoc:org.springframework.web.reactive.function.client.WebClient[].
Nếu thích imperative API, bạn có thể dùng javadoc:org.springframework.web.client.RestClient[].



[[io.rest-client.webclient]]
== WebClient

Nếu có Spring WebFlux trên classpath, chúng tôi khuyến nghị dùng javadoc:org.springframework.web.reactive.function.client.WebClient[] để gọi remote REST service.
Interface javadoc:org.springframework.web.reactive.function.client.WebClient[] cung cấp API theo functional style và hoàn toàn reactive.
Bạn có thể tìm hiểu thêm về javadoc:org.springframework.web.reactive.function.client.WebClient[] trong {url-spring-framework-docs}/web/webflux-webclient.html[section tương ứng trong tài liệu Spring Framework].

TIP: Nếu không viết reactive Spring WebFlux application, bạn có thể dùng xref:io/rest-client.adoc#io.rest-client.restclient[`RestClient`] thay cho javadoc:org.springframework.web.reactive.function.client.WebClient[].
API này cung cấp functional API tương tự, nhưng là imperative thay vì reactive.

Spring Boot tạo và pre-configure một prototype javadoc:org.springframework.web.reactive.function.client.WebClient$Builder[] bean cho bạn.
Bạn nên inject bean này vào các component và dùng nó để tạo các instance javadoc:org.springframework.web.reactive.function.client.WebClient[].
Spring Boot cấu hình builder này để share HTTP resources và phản ánh thiết lập codecs theo cùng cách với phía server (xem xref:web/reactive.adoc#web.reactive.webflux.httpcodecs[auto-configuration cho WebFlux HTTP codecs]), cùng các thiết lập khác.

[[io.rest-client.webclient.runtime]]
=== Runtime của WebClient

Spring Boot sẽ tự động phát hiện javadoc:org.springframework.http.client.reactive.ClientHttpConnector[] cần dùng để vận hành javadoc:org.springframework.web.reactive.function.client.WebClient[], dựa trên các library có trên application classpath.
Các client được hỗ trợ theo thứ tự ưu tiên sau:

. Reactor Netty
. Jetty RS client
. Apache HttpClient
. JDK HttpClient

Nếu có nhiều client trên classpath, client có mức ưu tiên cao nhất sẽ được dùng.

Starter `spring-boot-starter-webflux` mặc định phụ thuộc vào `io.projectreactor.netty:reactor-netty`, dependency này cung cấp cả implementation cho server và client.
Nếu chọn dùng Jetty làm reactive server, bạn nên thêm dependency `org.eclipse.jetty:jetty-reactive-httpclient` cho Jetty Reactive HTTP client.
Dùng cùng một technology cho server và client có những ưu điểm riêng, vì HTTP resources sẽ được tự động share giữa client và server.

Developer có thể override resource configuration cho Jetty và Reactor Netty bằng cách cung cấp custom bean javadoc:org.springframework.http.client.ReactorResourceFactory[] hoặc javadoc:org.springframework.http.client.reactive.JettyResourceFactory[]; cấu hình này sẽ được áp dụng cho cả client và server.

Nếu muốn override lựa chọn đó cho client, bạn có thể định nghĩa bean javadoc:org.springframework.http.client.reactive.ClientHttpConnector[] riêng và toàn quyền kiểm soát client configuration.

Bạn có thể tìm hiểu thêm về {url-spring-framework-docs}/web/webflux-webclient/client-builder.html[các tùy chọn configuration của `WebClient` trong tài liệu tham chiếu Spring Framework].



[[io.rest-client.webclient.configuration]]
=== Cấu hình HTTP Connector toàn cục

Nếu javadoc:org.springframework.http.client.reactive.ClientHttpConnector[] được auto-detect không đáp ứng nhu cầu, bạn có thể dùng property configprop:spring.http.clients.reactive.connector[] để chọn connector cụ thể.
Ví dụ, nếu có Reactor Netty trên classpath nhưng thích javadoc:org.eclipse.jetty.client.HttpClient[] của Jetty hơn, bạn có thể thêm cấu hình sau:

[configprops,yaml]
----
spring:
  http:
    clients:
      reactive:
        connector: jetty
----

TIP: Bạn cũng có thể dùng xref:io/rest-client.adoc#io.rest-client.global-configuration[các global configuration property] áp dụng cho mọi HTTP client.

[[io.rest-client.webclient.customization]]
=== Customization cho WebClient

Có ba cách tiếp cận chính để customize javadoc:org.springframework.web.reactive.function.client.WebClient[], tùy thuộc vào phạm vi bạn muốn áp dụng customization.

Để scope của mọi customization hẹp nhất có thể, hãy inject javadoc:org.springframework.web.reactive.function.client.WebClient$Builder[] đã được auto-configure, sau đó gọi các method cần thiết.
Các instance javadoc:org.springframework.web.reactive.function.client.WebClient$Builder[] là stateful: Mọi thay đổi trên builder đều được phản ánh trong tất cả client được tạo sau đó bằng builder này.
Nếu muốn tạo nhiều client với cùng một builder, bạn cũng có thể cân nhắc clone builder bằng `WebClient.Builder other = builder.clone();`.

Để thực hiện additive customization trên toàn application cho tất cả instance javadoc:org.springframework.web.reactive.function.client.WebClient$Builder[], bạn có thể khai báo các bean javadoc:org.springframework.boot.webclient.WebClientCustomizer[] và thay đổi javadoc:org.springframework.web.reactive.function.client.WebClient$Builder[] cục bộ tại injection point.

Cuối cùng, bạn có thể quay lại API gốc và dùng `WebClient.create()`.
Trong trường hợp đó, không có auto-configuration hoặc javadoc:org.springframework.boot.webclient.WebClientCustomizer[] nào được áp dụng.

[[io.rest-client.apiversioning]]
== Versioning API

Cả `WebClient` và `RestClient` đều hỗ trợ thực hiện các remote HTTP call có version, để API có thể được evolve theo thời gian.
Thông thường, việc này bao gồm gửi một HTTP header, query parameter hoặc URL path segment cho biết version API cần sử dụng.

Bạn có thể cấu hình API versioning bằng các method trên `WebClient.Builder` hoặc `RestClient.Builder`.

TIP: API versioning cũng được hỗ trợ ở server-side.
Xem các section xref:web/servlet.adoc#web.servlet.spring-mvc.api-versioning[Spring MVC] và xref:web/reactive.adoc#web.reactive.webflux.api-versioning[Spring WebFlux] để biết chi tiết.

NOTE: Cấu hình API versioning ở server-side không được dùng để auto-configure client.
Các client cần sử dụng một API versioning strategy, thường là để testing, phải tự cấu hình strategy đó một cách rõ ràng.

[[io.rest-client.httpservice.groups]]
=== Group của Service Client

Hard-code absolute URL trong annotation javadoc:org.springframework.web.service.annotation.HttpExchange[format=annotation] thường không lý tưởng trong production application.
Thay vào đó, thông thường bạn sẽ muốn gán cho HTTP Service client một logical name trong code, sau đó lookup một URL từ property dựa trên name đó.

HTTP Service client cho phép bạn thực hiện việc này bằng cách đăng ký chúng vào các named group.
HTTP Service group là một collection các HTTP Service interface cùng share các common feature.

Ví dụ, ta có thể muốn định nghĩa một group "`echo`" để dùng cho HTTP Service client gọi đến `\https://echo.zuplo.io`.

NOTE: HTTP Service group có thể được dùng để định nghĩa nhiều thứ không chỉ URL.
Ví dụ, group của bạn có thể định nghĩa connection timeout và SSL settings.
Bạn cũng có thể liên kết logic client customization với một group, chẳng hạn thêm code để chèn các authorization header bắt buộc.

Để liên kết một HTTP Service interface với một group khi sử dụng javadoc:org.springframework.web.service.registry.ImportHttpServices[format=annotation], bạn có thể dùng attribute `group`.

[[io.rest-client.httpservice.properties]]
=== Configuration Properties

Configuration properties cho HTTP Services có thể được chỉ định dưới `spring.http.serviceclient.<group-name>`:

Bạn có thể dùng properties để cấu hình các khía cạnh như:

* Base URL.
* Bất kỳ default header nào cần được gửi.
* Cấu hình API versioning.
* Redirect settings.
* Cookie handling settings.
* Connection và read timeouts.
* SSL bundles cần sử dụng.

TIP: Bạn cũng có thể dùng xref:io/rest-client.adoc#io.rest-client.global-configuration[các global configuration property] áp dụng cho mọi HTTP client.

Ví dụ, các properties bên dưới sẽ:

* Cấu hình tất cả HTTP client sử dụng connect timeout một giây, trừ khi bị override.
* Cấu hình HTTP Service client trong group "`echo`" để:
** Dùng một base URL cụ thể.
** Có connect timeout một giây.
** Có read timeout hai giây.

[configprops,yaml]
----
spring:
  http:
    clients:
      connect-timeout: 1s
    serviceclient:
      echo:
        base-url: "https://echo.zuplo.io"
        connect-timeout: 2s
        read-timeout: 2s
----

[[io.rest-client.global-configuration]]
== Áp dụng Global Configuration cho mọi HTTP Client

Bất kể đang sử dụng underlying technology nào, mọi HTTP client đều có các common setting có thể cấu hình.

Các setting này gồm:

* Connection timeouts.
* Read timeouts.
* Cách xử lý HTTP redirect.
* Cách xử lý HTTP cookie.
* SSL bundle nào sẽ được dùng khi kết nối.

Các common setting này được biểu diễn bởi class javadoc:org.springframework.boot.http.client.HttpClientSettings[], có thể truyền vào các method `build(...)` của javadoc:org.springframework.boot.http.client.reactive.ClientHttpConnectorBuilder[] và javadoc:org.springframework.boot.http.client.ClientHttpRequestFactoryBuilder[].

Nếu muốn áp dụng cùng configuration cho tất cả client được auto-configure, bạn có thể dùng các property `spring.http.clients`:

[configprops,yaml]
----
spring:
  http:
    clients:
      connect-timeout: 2s
      read-timeout: 1s
      redirects: dont-follow
      cookie-handling: disable
----

Khi chưa đặt `spring.http.clients.cookie-handling`, default cookie handling của underlying HTTP client library sẽ được sử dụng.
Các default này khác nhau: ví dụ, Apache HttpComponents và Jetty clients lưu cookie rồi gửi chúng cùng các request tiếp theo, trong khi JDK client bỏ qua cookie.
Khi cookie handling được enable, mỗi underlying HTTP client instance sử dụng cookie store riêng.
Reactor Netty và `simple` request factory không hỗ trợ cookie handling, vì vậy `enable` sẽ fail với các client đó còn `enable-when-possible` sẽ giữ nguyên chúng.



[[io.rest-client.global-configuration.inetaddress-filtering]]
=== InetAddress Filtering và SSRF Protection

Đôi khi cần giới hạn các remote address mà HTTP client được phép gọi.
Kỹ thuật này đặc biệt hữu ích khi harden application để chống các cuộc tấn công Server-Side Request Forgery (SSRF).

Để giới hạn address mà client có thể gọi, bạn có thể dùng javadoc:org.springframework.boot.http.client.InetAddressFilter[], chỉ cho phép các outgoing call đến những address khớp với filter.
Filter là một functional interface; bạn có thể tự tạo implementation hoặc dùng một trong các factory method thuận tiện.

Filter có thể được áp dụng vào javadoc:org.springframework.boot.http.client.HttpClientSettings[] mà bạn sử dụng khi build client:

include-code::MyService[]

Hoặc bạn cũng có thể định nghĩa một filter dưới dạng javadoc:org.springframework.context.annotation.Bean[format=annotation] nếu muốn áp dụng nó cho tất cả HTTP client builder được auto-configure:

include-code::MyHttpClientConfiguration[]
