[[features.developing-auto-configuration]]
= Tạo Auto-configuration riêng

Nếu bạn làm việc trong một công ty phát triển shared library, hoặc làm việc với một open-source hay commercial library, bạn có thể muốn phát triển auto-configuration riêng.
Các class auto-configuration có thể được đóng gói trong external jar và vẫn được Spring Boot phát hiện.

Auto-configuration có thể được gắn với một "`starter`" cung cấp code auto-configuration cũng như các library điển hình mà bạn sẽ dùng cùng nó.
Trước tiên, chúng tôi trình bày những gì bạn cần biết để xây dựng auto-configuration riêng, sau đó chuyển sang xref:features/developing-auto-configuration.adoc#features.developing-auto-configuration.custom-starter[các bước điển hình cần thiết để tạo custom starter].



[[features.developing-auto-configuration.understanding-auto-configured-beans]]
== Hiểu các bean được Auto-configure

Các class triển khai auto-configuration được annotate bằng javadoc:org.springframework.boot.autoconfigure.AutoConfiguration[format=annotation].
Annotation này bản thân cũng được meta-annotate bằng javadoc:org.springframework.context.annotation.Configuration[format=annotation], khiến auto-configuration trở thành các class javadoc:org.springframework.context.annotation.Configuration[format=annotation] tiêu chuẩn.
Các annotation javadoc:org.springframework.context.annotation.Conditional[format=annotation] bổ sung được dùng để giới hạn khi nào auto-configuration nên được áp dụng.
Thông thường, các class auto-configuration dùng annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnClass[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean[format=annotation].
Điều này đảm bảo auto-configuration chỉ được áp dụng khi tìm thấy các class liên quan và khi bạn chưa tự khai báo javadoc:org.springframework.context.annotation.Configuration[format=annotation].

Bạn có thể duyệt source code của {code-spring-boot-autoconfigure-src}[`spring-boot-autoconfigure`] để xem các class javadoc:org.springframework.boot.autoconfigure.AutoConfiguration[format=annotation] cốt lõi mà Spring cung cấp (xem file {code-spring-boot}/core/spring-boot-autoconfigure/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports[`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`]).
Bạn cũng có thể xem file tương đương trong các module khác để thấy các auto-configuration mà chúng cung cấp.



[[features.developing-auto-configuration.locating-auto-configuration-candidates]]
== Xác định ứng viên Auto-configuration

Spring Boot kiểm tra sự tồn tại của file `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` trong jar đã publish.
File này nên liệt kê các configuration class, mỗi dòng một class name, như ví dụ sau:

[source]
----
com.mycorp.libx.autoconfigure.LibXAutoConfiguration
com.mycorp.libx.autoconfigure.LibXWebAutoConfiguration
----

TIP: Bạn có thể thêm comment vào file imports bằng ký tự `#`.

TIP: Trong trường hợp hiếm khi một auto-configuration class không phải top-level class, class name nên dùng `$` để phân tách khỏi containing class, ví dụ `com.example.Outer$NestedAutoConfiguration`.

NOTE: Auto-configuration phải được load _chỉ_ bằng cách được khai báo trong file imports.
Hãy đảm bảo chúng được định nghĩa trong package riêng biệt và không bao giờ là target của component scanning.
Ngoài ra, class auto-configuration không nên bật component scanning để tìm thêm component.
Thay vào đó nên dùng annotation javadoc:org.springframework.context.annotation.Import[format=annotation] cụ thể.

Nếu configuration cần được áp dụng theo thứ tự cụ thể, bạn có thể dùng attribute `before`, `beforeName`, `after` và `afterName` trên annotation javadoc:org.springframework.boot.autoconfigure.AutoConfiguration[format=annotation], hoặc các annotation chuyên dụng javadoc:org.springframework.boot.autoconfigure.AutoConfigureBefore[format=annotation] và javadoc:org.springframework.boot.autoconfigure.AutoConfigureAfter[format=annotation].
Ví dụ, nếu cung cấp web-specific configuration, class có thể cần được áp dụng sau javadoc:org.springframework.boot.webmvc.autoconfigure.WebMvcAutoConfiguration[].

Nếu muốn sắp thứ tự một số auto-configuration mà không nên biết trực tiếp về nhau, bạn cũng có thể dùng javadoc:org.springframework.boot.autoconfigure.AutoConfigureOrder[format=annotation].
Annotation này có cùng semantic với annotation javadoc:org.springframework.core.annotation.Order[format=annotation] thông thường nhưng cung cấp thứ tự riêng cho class auto-configuration.

Tương tự class javadoc:org.springframework.context.annotation.Configuration[format=annotation] tiêu chuẩn, thứ tự áp dụng class auto-configuration chỉ ảnh hưởng tới thứ tự bean được định nghĩa.
Thứ tự các bean đó được tạo sau này không bị ảnh hưởng và được xác định bởi dependency của từng bean cùng các quan hệ javadoc:org.springframework.context.annotation.DependsOn[format=annotation].



[[features.developing-auto-configuration.locating-auto-configuration-candidates.deprecating]]
=== Deprecate và thay thế class Auto-configuration

Đôi khi bạn có thể cần deprecate class auto-configuration và cung cấp lựa chọn thay thế.
Ví dụ, bạn có thể muốn đổi package name nơi class auto-configuration được đặt.

Vì class auto-configuration có thể được tham chiếu trong thứ tự `before`/`after` và trong `excludes`, bạn cần thêm một file để cho Spring Boot biết cách xử lý replacement.
Để định nghĩa replacement, tạo file `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.replacements` chỉ ra liên kết giữa class cũ và class mới.

Ví dụ:

[source]
----
com.mycorp.libx.autoconfigure.LibXAutoConfiguration=com.mycorp.libx.autoconfigure.core.LibXAutoConfiguration
----

NOTE: File `AutoConfiguration.imports` cũng nên được cập nhật để _chỉ_ tham chiếu replacement class.

[[features.developing-auto-configuration.condition-annotations.class-conditions]]
=== Class Condition

Các annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnClass[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingClass[format=annotation] cho phép class javadoc:org.springframework.context.annotation.Configuration[format=annotation] được include dựa trên sự tồn tại hoặc không tồn tại của các class cụ thể.
Vì annotation metadata được parse bằng https://asm.ow2.io/[ASM], bạn có thể dùng attribute `value` để tham chiếu tới class thật dù class đó có thể không thực sự xuất hiện trên runtime classpath của ứng dụng.
Bạn cũng có thể dùng attribute `name` nếu muốn chỉ định class name bằng giá trị javadoc:java.lang.String[].

Cơ chế này không áp dụng giống như vậy cho method javadoc:org.springframework.context.annotation.Bean[format=annotation], nơi return type thường là target của condition: trước khi condition trên method được áp dụng, JVM đã load class và có thể đã xử lý method reference, điều này sẽ fail nếu class không tồn tại.

Để xử lý trường hợp này, có thể dùng một class javadoc:org.springframework.context.annotation.Configuration[format=annotation] riêng để cô lập condition, như ví dụ sau:

TIP: Nếu dùng javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnClass[format=annotation] hoặc javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingClass[format=annotation] như một phần của meta-annotation để tạo composed annotation riêng, bạn phải dùng `name`, vì việc tham chiếu trực tiếp class trong trường hợp này không được xử lý.

=== Bean Condition

Các annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnBean[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean[format=annotation] cho phép một bean được include dựa trên sự tồn tại hoặc không tồn tại của bean cụ thể.
Bạn có thể dùng attribute `value` để chỉ định bean theo type hoặc `name` để chỉ định bean theo tên.
Attribute `search` cho phép giới hạn hierarchy javadoc:org.springframework.context.ApplicationContext[] được xem xét khi tìm bean.

Khi đặt trên method javadoc:org.springframework.context.annotation.Bean[format=annotation], target type mặc định là return type của method, như ví dụ sau:

include-code::MyAutoConfiguration[]

Trong ví dụ trên, bean `someService` sẽ được tạo nếu chưa có bean type `SomeService` trong javadoc:org.springframework.context.ApplicationContext[].

TIP: Bạn cần đặc biệt cẩn thận với thứ tự bean definition được thêm vào, vì các condition này được evaluate dựa trên những gì đã được xử lý tới thời điểm đó.
Vì lý do này, chúng tôi khuyến nghị chỉ dùng annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnBean[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean[format=annotation] trên class auto-configuration, vì chúng được đảm bảo load sau khi mọi bean definition do user định nghĩa đã được thêm.

NOTE: javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnBean[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean[format=annotation] không ngăn class javadoc:org.springframework.context.annotation.Configuration[format=annotation] được tạo.
Khác biệt duy nhất giữa việc dùng condition ở class level và đánh dấu từng method javadoc:org.springframework.context.annotation.Bean[format=annotation] bên trong là cách trước ngăn class javadoc:org.springframework.context.annotation.Configuration[format=annotation] được register thành bean nếu condition không match.

TIP: Khi khai báo method javadoc:org.springframework.context.annotation.Bean[format=annotation], hãy cung cấp càng nhiều type information càng tốt trong return type của method.
Ví dụ, nếu concrete class của bean implement interface, return type của bean method nên là concrete class chứ không phải interface.
Việc cung cấp càng nhiều type information càng tốt đặc biệt quan trọng khi dùng javadoc:org.springframework.context.annotation.Bean[format=annotation] condition, vì quá trình evaluate chỉ có thể dựa vào type information có sẵn trong method signature.



[[features.developing-auto-configuration.condition-annotations.property-conditions]]
=== Property Condition

Annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnProperty[format=annotation] cho phép configuration được include dựa trên một Spring Environment property.
Dùng attribute `prefix` và `name` để chỉ định property cần kiểm tra.
Mặc định, mọi property tồn tại và không bằng `false` đều match.
Ngoài ra còn có annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnBooleanProperty[format=annotation] dành riêng cho boolean property.
Với cả hai annotation, bạn cũng có thể tạo kiểm tra nâng cao bằng attribute `havingValue` và `matchIfMissing`.

Nếu attribute `name` có nhiều tên, tất cả property đều phải vượt qua kiểm tra để condition match.



[[features.developing-auto-configuration.condition-annotations.resource-conditions]]
=== Resource Condition

Annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnResource[format=annotation] cho phép configuration chỉ được include khi một resource cụ thể tồn tại.
Resource có thể được chỉ định theo convention thông thường của Spring, ví dụ: `file:/home/user/test.dat`.



[[features.developing-auto-configuration.condition-annotations.web-application-conditions]]
=== Web Application Condition

Các annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnWebApplication[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnNotWebApplication[format=annotation] cho phép configuration được include tùy theo ứng dụng có phải web application hay không.
Một servlet-based web application là ứng dụng dùng Spring javadoc:org.springframework.web.context.WebApplicationContext[], định nghĩa scope `session`, hoặc có javadoc:org.springframework.web.context.ConfigurableWebEnvironment[].
Một reactive web application là ứng dụng dùng javadoc:org.springframework.boot.web.context.reactive.ReactiveWebApplicationContext[], hoặc có javadoc:org.springframework.boot.web.context.reactive.ConfigurableReactiveWebEnvironment[].

Các annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnWarDeployment[format=annotation] và javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnNotWarDeployment[format=annotation] cho phép configuration được include tùy theo ứng dụng có phải traditional WAR application được deploy tới servlet container hay không.
Condition này sẽ không match với ứng dụng chạy bằng embedded web server.



[[features.developing-auto-configuration.condition-annotations.spel-conditions]]
=== SpEL Expression Condition

Annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnExpression[format=annotation] cho phép configuration được include dựa trên kết quả của một {url-spring-framework-docs}/core/expressions.html[SpEL expression].

NOTE: Tham chiếu bean trong expression sẽ khiến bean đó được initialize rất sớm trong quá trình context refresh.
Do đó, bean sẽ không đủ điều kiện để post-processing, chẳng hạn configuration properties binding, và state của nó có thể chưa hoàn chỉnh.

[[features.developing-auto-configuration.custom-starter]]
== Tạo Starter riêng

Một Spring Boot starter điển hình chứa code để auto-configure và customize infrastructure của một công nghệ cụ thể, giả sử gọi là "acme".
Để dễ extensible, một số configuration key trong namespace riêng có thể được expose ra environment.
Cuối cùng, một dependency "starter" duy nhất được cung cấp để giúp user bắt đầu dễ dàng nhất có thể.

Cụ thể, custom starter có thể gồm:

* Module `acme-spring-boot` chứa code auto-configuration cho "acme" cũng như mọi API để dùng feature.
* Module `acme-spring-boot-starter` cung cấp dependency tới các starter khác mà "acme" yêu cầu, `acme-spring-boot`, và có thể thêm dependency khác thường hữu ích.
Nói ngắn gọn, việc thêm starter nên cung cấp mọi thứ cần thiết để bắt đầu dùng library.

Việc tách thành hai module hoàn toàn không bắt buộc.
Nếu "acme" có nhiều biến thể, option hoặc optional feature, thì tách auto-configuration sẽ tốt hơn vì bạn có thể biểu đạt rõ rằng một số feature là optional.
Ngoài ra, bạn có thể tạo starter đưa ra lựa chọn mặc định về optional dependency đó.
Đồng thời, người khác có thể chỉ dựa vào `acme-spring-boot` và tự tạo starter riêng với lựa chọn khác.

Nếu auto-configuration tương đối đơn giản và không có optional feature, merge hai module vào starter chắc chắn là một lựa chọn.

Nếu "acme" có một tập dependency cơ bản bắt buộc để hoạt động nhưng bạn muốn biểu đạt một opinionated view rõ hơn, thì có starter riêng là lựa chọn tốt.

Khi test các feature của "acme", bạn có thể cần auto-configuration dành riêng cho test.
Ví dụ, bạn có thể cung cấp cách thay external dependency bằng lựa chọn in-memory.
Có thể tạo một test-scoped starter riêng cho mục đích này theo cùng các nguyên tắc.


[[features.developing-auto-configuration.custom-starter.naming]]
=== Naming

Bạn nên đảm bảo starter có namespace phù hợp.
Không bắt đầu module name bằng `spring-boot`, kể cả khi dùng Maven `groupId` khác.
Trong tương lai chúng tôi có thể cung cấp official support cho công nghệ bạn đang auto-configure.

Theo nguyên tắc chung, bạn nên đặt tên combined module theo starter.
Ví dụ, giả sử tạo starter cho "acme", đặt auto-configure module là `acme-spring-boot` và starter là `acme-spring-boot-starter`.
Nếu chỉ có một module kết hợp cả hai, đặt tên là `acme-spring-boot-starter`.

Nếu "acme" cũng có test-scoped starter, đặt tên là `acme-spring-boot-starter-test`.


[[features.developing-auto-configuration.custom-starter.configuration-keys]]
=== Configuration key

Nếu starter cung cấp configuration key, hãy dùng namespace duy nhất cho chúng.
Đặc biệt, không đưa key vào các namespace Spring Boot sử dụng, như `server`, `management`, `spring`, v.v.
Nếu dùng cùng namespace, trong tương lai chúng tôi có thể thay đổi namespace theo cách làm hỏng module của bạn.
Theo nguyên tắc chung, prefix mọi key bằng namespace mà bạn sở hữu, ví dụ `acme`.

Nếu dùng javadoc:org.springframework.boot.context.properties.ConfigurationProperties[format=annotation] với record class thì description của record component nên được cung cấp qua class-level Javadoc tag `@param`, vì record class không có explicit instance field để đặt field-level Javadoc thông thường.

Dưới đây là một số rule chúng tôi dùng nội bộ để đảm bảo description nhất quán:

* Không bắt đầu description bằng "The" hoặc "A".
* Với type `boolean`, bắt đầu description bằng "Whether" hoặc "Enable".
* Với collection-based type, bắt đầu description bằng "Comma-separated list".
* Dùng javadoc:java.time.Duration[] thay vì `long` và mô tả default unit nếu khác milliseconds, ví dụ "If a duration suffix is not specified, seconds will be used".
* Không đưa default value vào description trừ khi nó phải được xác định ở runtime.

Hãy đảm bảo xref:specification:configuration-metadata/annotation-processor.adoc[kích hoạt generate metadata] để IDE assistance cũng có sẵn cho key của bạn.
Bạn có thể muốn review metadata được generate (`META-INF/spring-configuration-metadata.json`) để đảm bảo key được document đúng.
Dùng starter của bạn trong IDE tương thích cũng là cách tốt để validate chất lượng metadata.



[[features.developing-auto-configuration.custom-starter.autoconfigure-module]]
=== Module "`autoconfigure`"

Module `autoconfigure` chứa mọi thứ cần thiết để bắt đầu với library.
Nó cũng có thể chứa definition của configuration key, như javadoc:org.springframework.boot.context.properties.ConfigurationProperties[format=annotation], và callback interface dùng để customize thêm cách component được initialize.

TIP: Bạn nên đánh dấu dependency tới library là optional để có thể include module `autoconfigure` vào project dễ dàng hơn.
Nếu làm vậy, library sẽ không được cung cấp và mặc định Spring Boot sẽ back off.

Spring Boot dùng annotation processor để thu thập condition trên auto-configuration vào metadata file (`META-INF/spring-autoconfigure-metadata.properties`).
Nếu file đó tồn tại, nó được dùng để lọc sớm các auto-configuration không match, giúp cải thiện startup time.

Khi build bằng Maven, cấu hình compiler plugin (3.12.0 trở lên) để thêm `spring-boot-autoconfigure-processor` vào annotation processor path:

[source,xml]
----
<project>
	<build>
		<plugins>
			<plugin>
				<groupId>org.apache.maven.plugins</groupId>
				<artifactId>maven-compiler-plugin</artifactId>
				<configuration>
					<annotationProcessorPaths>
						<path>
							<groupId>org.springframework.boot</groupId>
							<artifactId>spring-boot-autoconfigure-processor</artifactId>
						</path>
					</annotationProcessorPaths>
				</configuration>
			</plugin>
		</plugins>
	</build>
</project>
----

Với Gradle, dependency nên được khai báo trong configuration `annotationProcessor`, như ví dụ sau:

[source,gradle]
----
dependencies {
	annotationProcessor "org.springframework.boot:spring-boot-autoconfigure-processor"
}
----



[[features.developing-auto-configuration.custom-starter.starter-module]]
=== Starter Module

Starter thực chất là một jar rỗng.
Mục đích duy nhất là cung cấp các dependency cần thiết để làm việc với library.
Bạn có thể xem nó như một opinionated view về những gì cần thiết để bắt đầu.

Không đưa ra assumption về project nơi starter được thêm vào.
Nếu library bạn đang auto-configure thường cần starter khác, hãy đề cập cả chúng.
Việc cung cấp một tập _default_ dependency phù hợp có thể khó nếu số optional dependency lớn, vì bạn nên tránh include dependency không cần thiết cho cách dùng điển hình của library.
Nói cách khác, bạn không nên include optional dependency.

NOTE: Dù theo cách nào, starter phải tham chiếu trực tiếp hoặc gián tiếp tới core Spring Boot starter (`spring-boot-starter`), không cần thêm nếu starter phụ thuộc vào starter khác.
Nếu một project được tạo chỉ với custom starter của bạn, core feature của Spring Boot vẫn được cung cấp nhờ sự hiện diện của core starter.
