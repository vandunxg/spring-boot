[[build-image]]
= Packaging OCI Images

Plugin có thể tạo một https://github.com/opencontainers/image-spec[OCI image] từ jar hoặc war file bằng https://buildpacks.io[Cloud Native Buildpacks] (CNB).
Có thể build image bằng task `bootBuildImage`.

NOTE: Vì lý do security, image được build và run bằng non-root user.
Xem {url-buildpacks-docs}/reference/spec/platform-api/#users[CNB specification] để biết thêm chi tiết.

Task tự động được tạo khi apply `java` hoặc `war` plugin và là một instance của {apiref-gradle-plugin-boot-build-image}[`BootBuildImage`].

[[build-image.docker-daemon]]
== Docker Daemon

Task `bootBuildImage` cần access tới Docker daemon.
Task sẽ inspect local Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration files] để determine current https://docs.docker.com/engine/context/working-with-contexts/[context] và dùng connection information của context để communicate với Docker daemon.
Nếu không determine được current context hoặc context không có connection information, task sẽ dùng default local connection.
Điều này hoạt động với https://docs.docker.com/install/[Docker Engine] trên mọi supported platform mà không cần configuration.

Có thể set environment variables để configure `bootBuildImage` dùng alternative local hoặc remote connection:

|===
| Environment variable | Mô tả

| DOCKER_CONFIG
| Location của Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration files] dùng để determine current context (default `$HOME/.docker`)

| DOCKER_CONTEXT
| Name của một https://docs.docker.com/engine/context/working-with-contexts/[context] dùng để retrieve host information từ Docker CLI configuration files (override `DOCKER_HOST`)

| DOCKER_HOST
| URL chứa host và port Docker daemon, ví dụ `tcp://192.168.99.100:2376`

| DOCKER_TLS_VERIFY
| Enable secure HTTPS protocol khi được set thành `1` (optional)

| DOCKER_CERT_PATH
| Path tới certificate và key files cho HTTPS (required nếu `DOCKER_TLS_VERIFY=1`, bị ignore nếu không)
|===

Docker daemon connection information cũng có thể được cung cấp bằng các `docker` properties trong plugin configuration:

|===
| Property | Mô tả

| `context`
| Name của https://docs.docker.com/engine/context/working-with-contexts/[context] dùng để retrieve host information từ Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration files]

| `host`
| URL chứa host và port Docker daemon, ví dụ `tcp://192.168.99.100:2376`

| `tlsVerify`
| Enable secure HTTPS protocol khi set `true` (optional)

| `certPath`
| Path tới certificate/key file cho HTTPS (required nếu `tlsVerify` là `true`, ignore nếu không)

| `bindHostToBuilder`
| Khi `true`, value của property `host` sẽ được cung cấp cho container được tạo cho CNB builder (optional)
|===

Để biết thêm chi tiết, xem xref:packaging-oci-image.adoc#build-image.examples.docker[examples].

[[build-image.docker-registry]]
== Docker Registry

Nếu Docker image được specify bởi property `builder` hoặc `runImage` được store trong private Docker image registry cần authentication, credentials có thể được cung cấp bằng các properties `docker.builderRegistry`.

Nếu generated Docker image được publish tới Docker image registry, credentials có thể được cung cấp bằng các properties `docker.publishRegistry`.

Các properties được cung cấp cho user authentication hoặc identity token authentication.
Tham khảo documentation của Docker registry đang dùng để biết thêm về các supported authentication methods.

Bảng sau tóm tắt các properties available cho `docker.builderRegistry` và `docker.publishRegistry`:

|===
| Property | Mô tả

| `username`
| Username của Docker image registry user. Required cho user authentication.

| `password`
| Password của Docker image registry user. Required cho user authentication.

| `url`
| Address của Docker image registry. Optional cho user authentication.

| `email`
| E-mail address của Docker image registry user. Optional cho user authentication.

| `token`
| Identity token của Docker image registry user. Required cho token authentication.
|===

Để biết thêm chi tiết, xem xref:packaging-oci-image.adoc#build-image.examples.docker[examples].

[NOTE]
====
Nếu không cung cấp credentials, plugin đọc existing Docker configuration file của user, thường ở `$HOME/.docker/config.json`, để determine authentication methods.
Dựa trên các methods này, plugin sẽ cố cung cấp authentication credentials cho requested image.

Plugin hỗ trợ:

- *Credential Helpers*: External tools được configure trong Docker configuration file để cung cấp credentials cho các registry cụ thể. Ví dụ, các tool như `osxkeychain` hoặc `ecr-login` handle authentication cho một số registry.
- *Credential Store*: Default fallback mechanism để store và retrieve credentials một cách an toàn, ví dụ `desktop` cho Docker Desktop.
- *Static Credentials*: Credentials được store trực tiếp trong Docker configuration file dưới section `auths`.
====

[[build-image.customization]]
== Image Customizations

Plugin invoke {url-buildpacks-docs}/for-app-developers/concepts/builder/[builder] để orchestrate việc generate image.
Builder include nhiều {url-buildpacks-docs}/for-app-developers/concepts/buildpack/[buildpacks] có thể inspect application để influence generated image.
Mặc định plugin chọn builder image.
Image name được derive từ project properties.

Task properties có thể dùng để configure cách builder operate trên project.
Bảng sau tóm tắt các properties available và default values:

|===
| Property | Command-line option | Mô tả | Default value

| `builder`
| `--builder`
| Name của builder image cần dùng.
| `paketobuildpacks/builder-noble-java-tiny:latest`

| `trustBuilder`
| `--trustBuilder`
| Có treat builder là {url-buildpacks-docs}/for-platform-operators/how-to/integrate-ci/pack/concepts/trusted_builders/#what-is-a-trusted-builder[trusted] hay không.
| `true` nếu builder là một trong `paketobuildpacks/builder-noble-java-tiny`, `paketobuildpacks/builder-jammy-java-tiny`, `paketobuildpacks/builder-jammy-tiny`, `paketobuildpacks/builder-jammy-base`, `paketobuildpacks/builder-jammy-full`, `paketobuildpacks/builder-jammy-buildpackless-tiny`, `paketobuildpacks/builder-jammy-buildpackless-base`, `paketobuildpacks/builder-jammy-buildpackless-full`, `gcr.io/buildpacks/builder`, `heroku/builder`; nếu không là `false`.

| `imagePlatform`
| `--imagePlatform`
a|Platform (operating system và architecture) của builder, run và buildpack images được pull.
Phải dạng `OS[/architecture[/variant]]` như `linux/amd64`, `linux/arm64` hoặc `linux/arm/v5`.
Tham khảo documentation của builder để determine các OS và architecture options available.
| Không có default value, nghĩa là dùng host machine platform.

| `runImage`
| `--runImage`
| Name của run image cần dùng.
| Không có default value; dùng run image được specify trong Builder metadata.

| `imageName`
| `--imageName`
| javadoc:org.springframework.boot.buildpack.platform.docker.type.ImageReference#of(java.lang.String)[Image name] cho generated image.
| `docker.io/library/${project.name}:${project.version}`

| `pullPolicy`
| `--pullPolicy`
| javadoc:org.springframework.boot.buildpack.platform.build.PullPolicy[Policy] dùng để determine khi nào pull builder và run images từ registry.
Các giá trị được chấp nhận là `ALWAYS`, `NEVER` và `IF_NOT_PRESENT`.
| `ALWAYS`

| `environment`
| `--environment`
| Environment variables sẽ được pass tới builder.
| Empty.

| `buildpacks`
|
a|Các buildpack mà builder sẽ dùng khi build image.
Chỉ các buildpack được specify mới được dùng, override các buildpack mặc định được include trong builder.
Buildpack references phải ở một trong các dạng sau:

* Buildpack trong builder - `[urn:cnb:builder:]<buildpack ID>[@<version>]`
* Buildpack trong một directory trên file system - `[file://]<path>`
* Buildpack trong gzipped tar (.tgz) file - `[file://]<path>/<file name>`
* Buildpack trong OCI image - `[docker://]<host>/<repo>[:<tag>][@<digest>]`
| None, nghĩa là builder sẽ dùng các buildpack được include trong nó.

| `bindings`
|
a|https://docs.docker.com/storage/bind-mounts/[Volume bind mounts] cần được mount vào builder container khi build image.
Bindings sẽ được pass unparsed và unvalidated tới Docker khi create builder container.
Bindings phải ở một trong các dạng sau:

* `<host source path>:<container destination path>[:<options>]`
* `<host volume name>:<container destination path>[:<options>]`

Trong đó, `<options>` có thể gồm:

* `ro` để mount volume ở chế độ read-only trong container
* `rw` để mount volume ở chế độ readable và writable trong container
* `volume-opt=key=value` để specify các key-value pairs gồm tên option và value của nó
|

| `network`
| `--network`
| https://docs.docker.com/network/#network-drivers[Network driver] mà builder container sẽ được configure để dùng.
Value được cung cấp sẽ được pass unvalidated tới Docker khi create builder container.
|

| `cleanCache`
| `--cleanCache`
| Có clean cache trước khi build hay không.
| `false`

| `verboseLogging`
|
| Enable verbose logging của builder operations.
| `false`

| `publish`
| `--publishImage`
| Có publish generated image tới Docker registry hay không.
| `false`

| `tags`
|
| List một hoặc nhiều additional tags cần apply cho generated image.
Values phải là các *full* image references.
Xem xref:packaging-oci-image.adoc#build-image.customization.tags[tags section].
|

| `buildWorkspace`
|
| Temporary workspace mà builder và buildpacks dùng để store files trong quá trình image building.
Value có thể là named volume hoặc bind mount location.
| Named volume trong Docker daemon, có name được derive từ image name.

| `buildCache`
|
| Cache chứa các layers do buildpacks tạo và được image building process sử dụng.
Value có thể là named volume hoặc bind mount location.
| Named volume trong Docker daemon, có name được derive từ image name.

| `launchCache`
|
| Cache chứa các layers do buildpacks tạo và được image launching process sử dụng.
Value có thể là named volume hoặc bind mount location.
| Named volume trong Docker daemon, có name được derive từ image name.

| `createdDate`
| `--createdDate`
| Date dùng để set field `Created` trong metadata của generated image.
Value phải ở ISO 8601 instant format hoặc là `now` để dùng current date/time.
| Fixed date cho phép {url-buildpacks-docs}/for-app-developers/concepts/reproducibility/[build reproducibility].

| `applicationDirectory`
| `--applicationDirectory`
| Path tới directory mà application contents sẽ được upload vào builder image.
Application contents cũng sẽ ở location này trong generated image.
| `/workspace`

| `securityOptions`
| `--securityOptions`
| https://docs.docker.com/reference/cli/docker/container/run/#security-opt[Security options] apply cho builder container, dưới dạng array các string values.
| `["label=disable"]` trên Linux/macOS, `[]` trên Windows

|===

NOTE: Plugin detect target Java compatibility của project bằng property `targetCompatibility` của JavaPlugin.
Khi dùng default Paketo builder và buildpacks, plugin instruct buildpacks install cùng Java version.
Có thể override như trong xref:packaging-oci-image.adoc#build-image.examples.builder-configuration[builder configuration].

NOTE: Default builder `paketobuildpacks/builder-noble-java-tiny:latest` chứa một reduced set các system libraries và không include shell.
Các application cần shell để chạy start script, như khi {url-gradle-docs-application-plugin}[`application` plugin] được apply để generate distribution zip archive, hoặc depend vào system library không present, nên override `runImage` để dùng image có shell và broader set các system libraries như `paketobuildpacks/ubuntu-noble-run:latest`.

[[build-image.customization.tags]]
=== Tags Format

Value của option `tags` phải là *full* image reference.
Accepted format là `[domainHost:port/][path/]name[:tag][@digest]`.

Nếu thiếu domain, default `docker.io`.
Nếu thiếu path, default `library`.
Nếu thiếu tag, default `latest`.

Một số examples:

* `my-image` dẫn tới image reference `docker.io/library/my-image:latest`
* `my-repository/my-image` dẫn tới image reference `docker.io/my-repository/my-image:latest`
* `example.com/my-repository/my-image:1.0.0` được dùng nguyên như vậy

[[build-image.examples.docker.colima]]
==== Docker Configuration cho Colima

Plugin có thể communicate với Docker daemon do https://github.com/abiosoft/colima[Colima] cung cấp.
Có thể set environment variable `DOCKER_HOST` bằng command sau:

[source,shell,subs="verbatim,attributes"]
----
$ export DOCKER_HOST=$(docker context inspect colima -f '{{.Endpoints.docker.Host}}')
----
