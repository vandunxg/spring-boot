[[packaging-executable]]
= Packaging Executable Archives

Plugin có thể tạo executable archive (jar file và war file) chứa mọi dependency của application và có thể chạy bằng `java -jar`.

[[packaging-executable.jars]]
== Packaging Executable Jars

Executable jar có thể build bằng task `bootJar`.
Task tự động được tạo khi `java` plugin apply và là instance {apiref-gradle-plugin-boot-jar}[`BootJar`].
Task `assemble` tự động configure depend vào `bootJar` nên chạy `assemble` hoặc `build` cũng chạy `bootJar`.

[[packaging-executable.wars]]
== Packaging Executable Wars

Executable war có thể build bằng task `bootWar`.
Task tự động tạo khi `war` plugin apply và là instance {apiref-gradle-plugin-boot-war}[`BootWar`].
Task `assemble` tự động configure depend vào `bootWar` nên chạy `assemble` hoặc `build` cũng chạy `bootWar`.

[[packaging-executable.configuring.layered-archives]]
=== Packaging Layered Jar hoặc War

Mặc định task `bootJar` build archive chứa application class và dependency lần lượt trong `BOOT-INF/classes` và `BOOT-INF/lib`.
Tương tự `bootWar` build archive chứa application class trong `WEB-INF/classes` và dependency trong `WEB-INF/lib` và `WEB-INF/lib-provided`.
Khi cần build Docker image từ content jar, hữu ích khi tách các directory này thêm để write vào distinct layer.

Layered jar dùng cùng layout với regular boot packaged jar nhưng include additional metadata file mô tả từng layer.

Mặc định các layer sau được define:

* `dependencies` cho non-project dependency có version không chứa `SNAPSHOT`.
* `spring-boot-loader` cho jar loader class.
* `snapshot-dependencies` cho non-project dependency có version chứa `SNAPSHOT`.
* `application` cho project dependency, application class và resource.

Order layer quan trọng vì determine khả năng previous layer được cache khi application change.
Default order là `dependencies`, `spring-boot-loader`, `snapshot-dependencies`, `application`.
Content ít khả năng change nên add trước, sau đó layer dễ change hơn.

==== Custom Layers Configuration

Tùy application, có thể muốn tune cách layer tạo và thêm layer mới.

Có thể làm bằng configuration mô tả cách jar/war tách thành layer và order layer.

[tabs]
======

+
[source,groovy,indent=0,subs="verbatim,attributes"]
----
include::example$packaging/boot-jar-layered-custom.gradle[tags=layered]
----
Kotlin::
+
[source,kotlin,indent=0,subs="verbatim,attributes"]
----
include::example$packaging/boot-jar-layered-custom.gradle.kts[tags=layered]
----
======

DSL `layered` define bằng ba phần:

* Closure `application` define cách application class/resource layer.
* Closure `dependencies` define cách dependency layer.
* Method `layerOrder` define order layer write.

Nested closure `intoLayer` dùng trong section `application` và `dependencies` để claim content cho layer.
Closure evaluate theo order define từ trên xuống.
Content chưa được closure trước claim vẫn available cho closure sau.

Closure `intoLayer` claim content bằng nested call `include` và `exclude`.
Closure `application` dùng Ant-style path matching cho include/exclude parameter.
Section `dependencies` dùng pattern `group:artifact[:version]`.
Nó cũng có method `includeProjectDependencies()` và `excludeProjectDependencies()` để include/exclude project dependency.

Nếu không gọi `include`, mọi content chưa được closure trước claim được xét.

Nếu không gọi `exclude`, không apply exclusion.

Trong closure `dependencies` của ví dụ trên, `intoLayer` đầu claim mọi project dependency cho layer `application`.
`intoLayer` tiếp theo claim mọi SNAPSHOT dependency cho layer `snapshot-dependencies`.
`intoLayer` thứ ba và cuối claim mọi thứ còn lại, tức dependency không phải project dependency hoặc SNAPSHOT, cho layer `dependencies`.

Closure `application` có rule tương tự.
Đầu tiên claim content `org/springframework/boot/loader/**` cho layer `spring-boot-loader`.
Sau đó claim class/resource còn lại cho layer `application`.

NOTE: Order closure `intoLayer` được add thường khác order layer write.
Vì vậy method `layerOrder` luôn phải được gọi và _phải_ cover mọi layer reference bởi call `intoLayer`.
