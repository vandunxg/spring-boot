[[packaging-executable]]
= Packaging Executable Archives

Plugin có thể tạo các executable archive (jar file và war file) chứa mọi dependency của application và có thể chạy bằng `java -jar`.

[[packaging-executable.jars]]
== Packaging Executable Jars

Executable jar có thể được build bằng task `bootJar`.
Task này tự động được tạo khi `java` plugin được apply và là một instance của {apiref-gradle-plugin-boot-jar}[`BootJar`].
Task `assemble` tự động được configure để depend on task `bootJar`, nên chạy `assemble` (hoặc `build`) cũng sẽ chạy task `bootJar`.

[[packaging-executable.wars]]
== Packaging Executable Wars

Executable war có thể được build bằng task `bootWar`.
Task này tự động được tạo khi `war` plugin được apply và là một instance của {apiref-gradle-plugin-boot-war}[`BootWar`].
Task `assemble` tự động được configure để depend on task `bootWar`, nên chạy `assemble` (hoặc `build`) cũng sẽ chạy task `bootWar`.

[[packaging-executable.configuring.layered-archives]]
=== Packaging Layered Jar hoặc War

Mặc định, task `bootJar` build archive chứa các application class và dependency lần lượt trong `BOOT-INF/classes` và `BOOT-INF/lib`.
Tương tự, `bootWar` build archive chứa các application class trong `WEB-INF/classes` và dependency trong `WEB-INF/lib` và `WEB-INF/lib-provided`.
Khi cần build Docker image từ content của jar, việc có thể tách các directory này thêm để write vào các layer riêng biệt sẽ rất hữu ích.

Layered jar dùng cùng layout với regular boot packaged jar nhưng include một additional metadata file mô tả từng layer.

Mặc định các layer sau được define:

* `dependencies` cho non-project dependency có version không chứa `SNAPSHOT`.
* `spring-boot-loader` cho jar loader class.
* `snapshot-dependencies` cho non-project dependency có version chứa `SNAPSHOT`.
* `application` cho project dependency, application class và resource.

Order của layer quan trọng vì nó determine khả năng các layer trước đó được cache khi một phần application thay đổi.
Default order là `dependencies`, `spring-boot-loader`, `snapshot-dependencies`, `application`.
Content ít khả năng change nên được add trước, sau đó là các layer dễ change hơn.

----
Kotlin::
+
[source,kotlin,indent=0,subs="verbatim,attributes"]
----
include::example$packaging/boot-jar-layered-custom.gradle.kts[tags=layered]
----
======

DSL `layered` được define bằng ba phần:

* Closure `application` define cách application class và resource được layer.
* Closure `dependencies` define cách dependency được layer.
* Method `layerOrder` define order các layer được write.

Các nested closure `intoLayer` được dùng trong section `application` và `dependencies` để claim content cho một layer.
Các closure được evaluate theo order chúng được define, từ trên xuống dưới.
Mọi content chưa được closure trước đó claim vẫn available cho các closure tiếp theo xem xét.

Closure `intoLayer` claim content bằng các call `include` và `exclude` lồng nhau.
Closure `application` dùng Ant-style path matching cho các include/exclude parameter.
Section `dependencies` dùng pattern `group:artifact[:version]`.
Section này cũng có các method `includeProjectDependencies()` và `excludeProjectDependencies()` để include/exclude project dependency.

Nếu không gọi `include`, mọi content chưa được closure trước đó claim sẽ được xem xét.

Nếu không gọi `exclude`, không có exclusion nào được apply.

Trong closure `dependencies` của ví dụ trên, `intoLayer` đầu tiên sẽ claim mọi project dependency cho layer `application`.
`intoLayer` tiếp theo sẽ claim mọi SNAPSHOT dependency cho layer `snapshot-dependencies`.
`intoLayer` thứ ba và cuối cùng sẽ claim mọi thứ còn lại, tức dependency không phải project dependency hoặc SNAPSHOT, cho layer `dependencies`.

Closure `application` có rule tương tự.
Đầu tiên, closure này claim content `org/springframework/boot/loader/**` cho layer `spring-boot-loader`.
Sau đó, nó claim các class và resource còn lại cho layer `application`.

NOTE: Order các closure `intoLayer` được add thường khác với order các layer được write.
Vì vậy, method `layerOrder` luôn phải được gọi và _phải_ cover mọi layer được reference bởi các call `intoLayer`.
