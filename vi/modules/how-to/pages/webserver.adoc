[[howto.webserver]]
= Embedded Web Servers

Mỗi Spring Boot web application bao gồm embedded web server.
Feature này dẫn tới nhiều câu hỏi how-to, gồm cách thay embedded server và cách configure embedded server.
Phần này trả lời các câu hỏi đó.

[[howto.webserver.use-another]]
== Dùng Web Server khác

Nhiều Spring Boot starter include default embedded container.

* Với servlet stack application, `spring-boot-starter-web` include Tomcat thông qua `spring-boot-starter-tomcat`, nhưng có thể dùng `spring-boot-starter-jetty` thay thế.
* Với reactive stack application, `spring-boot-starter-webflux` include Reactor Netty thông qua `spring-boot-starter-reactor-netty`, nhưng có thể dùng `spring-boot-starter-tomcat` hoặc `spring-boot-starter-jetty` thay thế.

Khi switch sang HTTP server khác, cần swap default dependency với dependency cần dùng.
Để hỗ trợ, Spring Boot cung cấp starter riêng cho từng HTTP server được hỗ trợ.

Ví dụ exclude Tomcat và include Jetty cho Spring MVC:

[tabs]
======

Maven::
+
[source,xml]
----
<dependency>
	<groupId>org.springframework.boot</groupId>
	<artifactId>spring-boot-starter-webmvc</artifactId>
	<exclusions>
		<!-- Exclude the Tomcat dependency -->
		<exclusion>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-tomcat</artifactId>
		</exclusion>
	</exclusions>
</dependency>
<!-- Use Jetty instead -->
<dependency>
	<groupId>org.springframework.boot</groupId>
	<artifactId>spring-boot-starter-jetty</artifactId>
</dependency>
----
+

Gradle::
+
[source,gradle]
----
dependencies {
	implementation('org.springframework.boot:spring-boot-starter-webmvc') {
		// Exclude the Tomcat dependency
		exclude group: 'org.springframework.boot', module: 'spring-boot-starter-tomcat'
	}
	// Use Jetty instead
	implementation "org.springframework.boot:spring-boot-starter-jetty"
}
----
+
======

Nếu tạo war file, có thể dùng approach tương tự nhưng phải indicate provided dependency:

[tabs]
======

Maven::
+
[source,xml]
----
<dependency>
	<groupId>org.springframework.boot</groupId>
	<artifactId>spring-boot-starter-webmvc</artifactId>
	<exclusions>
		<!-- Exclude the Tomcat dependency -->
		<exclusion>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-tomcat</artifactId>
		</exclusion>
	</exclusions>
</dependency>
<!-- Use Jetty instead -->
<dependency>
	<groupId>org.springframework.boot</groupId>
	<artifactId>spring-boot-starter-jetty</artifactId>
	<scope>provided</scope>
</dependency>
----
+

Gradle::
+
[source,gradle]
----
dependencies {
	implementation('org.springframework.boot:spring-boot-starter-webmvc') {
		// Exclude the Tomcat dependency
		exclude group: 'org.springframework.boot', module: 'spring-boot-starter-tomcat'
	}
	// Use Jetty instead
	implementation "org.springframework.boot:spring-boot-starter-jetty"
	providedRuntime "org.springframework.boot:spring-boot-starter-jetty-runtime"
}
----
+
======

[[howto.webserver.disable]]
== Disable Web Server

Nếu classpath chứa các thành phần cần để start web server, Spring Boot tự động start nó.
Để disable behavior này, configure javadoc:org.springframework.boot.WebApplicationType[] trong `application.properties`:

[configprops,yaml]
----
spring:
  main:
    web-application-type: "none"
----

[[howto.webserver.change-port]]
== Thay đổi HTTP Port

Trong standalone application, main HTTP port mặc định là `8080` nhưng có thể set bằng configprop:server.port[], ví dụ trong `application.properties` hoặc System property.
Nhờ relaxed binding của value javadoc:org.springframework.core.env.Environment[], cũng có thể dùng configprop:server.port[format=envvar], ví dụ OS environment variable.

Để tắt hoàn toàn HTTP endpoint nhưng vẫn tạo javadoc:org.springframework.web.context.WebApplicationContext[], dùng `server.port=-1`; cách này đôi khi hữu ích cho testing.

Chi tiết xem xref:reference:web/servlet.adoc#web.servlet.embedded-container.customizing[Customizing Embedded Servlet Containers] trong phần "Spring Boot Features", hoặc class javadoc:org.springframework.boot.web.server.autoconfigure.ServerProperties[].

[[howto.webserver.use-random-port]]
== Dùng Random Unassigned HTTP Port

Để scan free port bằng OS native nhằm tránh clash, dùng `server.port=0`.

[[howto.webserver.enable-response-compression]]
== Enable HTTP Response Compression

HTTP response compression được hỗ trợ bởi Jetty, Tomcat và Reactor Netty.
Có thể enable trong `application.properties`:

[configprops,yaml]
----
server:
  compression:
    enabled: true
----

Mặc định response phải dài ít nhất 2048 byte mới được compress.
Configure bằng configprop:server.compression.min-response-size[].

Mặc định response chỉ compress nếu content type thuộc một trong các type:

* `text/html`
* `text/xml`
* `text/plain`
* `text/css`
* `text/javascript`
* `application/javascript`
* `application/json`
* `application/xml`

Để configure mime type được compress và replace default, set configprop:server.compression.mime-types[].
Để giữ default và thêm mime type, set configprop:server.compression.additional-mime-types[].

[[howto.webserver.configure-ssl]]
== Configure SSL

SSL có thể configure declaratively bằng các property `+server.ssl.*+`, thường trong `application.properties` hoặc `application.yaml`.
Xem javadoc:org.springframework.boot.web.server.Ssl[] để biết detail mọi property được hỗ trợ.

Ví dụ set SSL property bằng Java KeyStore file:

[configprops,yaml]
----
server:
  port: 8443
  ssl:
    key-store: "classpath:keystore.jks"
    key-store-password: "secret"
    key-password: "another-secret"
----

Dùng configuration như ví dụ trên nghĩa là application không còn support plain HTTP connector tại port 8080.
Spring Boot không support configure cả HTTP connector và HTTPS connector qua `application.properties`.
Nếu muốn có cả hai, cần configure một connector programmatically.
Khuyến nghị dùng `application.properties` configure HTTPS vì HTTP connector dễ configure programmatically hơn.

[[howto.webserver.configure-ssl.pem-files]]
=== Dùng PEM-encoded files

Có thể dùng PEM-encoded file thay Java KeyStore file.
Nên dùng PKCS#8 key file khi có thể.
PEM-encoded PKCS#8 key file bắt đầu bằng header `-----BEGIN PRIVATE KEY-----` hoặc `-----BEGIN ENCRYPTED PRIVATE KEY-----`.

Nếu file ở format khác, ví dụ PKCS#1 (`-----BEGIN RSA PRIVATE KEY-----`) hoặc SEC 1 (`-----BEGIN EC PRIVATE KEY-----`), có thể convert sang PKCS#8 bằng OpenSSL:

[source,shell,subs="verbatim,attributes"]
----
openssl pkcs8 -topk8 -nocrypt -in <input file> -out <output file>
----

Ví dụ set SSL property bằng PEM-encoded certificate và private key file:

[configprops,yaml]
----
server:
  port: 8443
  ssl:
    certificate: "classpath:my-cert.crt"
    certificate-private-key: "classpath:my-cert.key"
    trust-certificate: "classpath:ca-cert.crt"
----

[[howto.webserver.configure-ssl.bundles]]
=== Dùng SSL Bundles

Ngoài ra SSL trust material có thể configure trong xref:reference:features/ssl.adoc[SSL bundle] và apply vào web server:

[configprops,yaml]
----
server:
  port: 8443
  ssl:
    bundle: "example"
----

[NOTE]
====
Property `server.ssl.bundle` không thể combine với discrete Java KeyStore hoặc PEM property option dưới `server.ssl`.

Các property configprop:server.ssl.ciphers[], configprop:server.ssl.enabled-protocols[], configprop:server.ssl.protocol[] cũng bị ignore khi dùng bundle.
Các property này nên được define bằng `spring.ssl.bundle.<type>.<name>.options`.
====

[[howto.webserver.configure-ssl.sni]]
=== Configure Server Name Indication

Tomcat và Netty có thể configure để dùng unique SSL trust material cho từng host name nhằm hỗ trợ Server Name Indication (SNI).
SNI configuration không được support với Jetty, nhưng Jetty có thể https://eclipse.dev/jetty/documentation/jetty-12/operations-guide/index.html#og-protocols-ssl-sni[tự động setup SNI] nếu cung cấp nhiều certificate.

Giả sử đã configure xref:reference:features/ssl.adoc[SSL bundle] tên `web`, `web-alt1` và `web-alt2`, configuration sau assign từng bundle cho host name mà embedded web server phục vụ:

[configprops,yaml]
----
server:
  port: 8443
  ssl:
    bundle: "web"
    server-name-bundles:
      - server-name: "alt1.example.com"
        bundle: "web-alt1"
      - server-name: "alt2.example.com"
        bundle: "web-alt2"
----

Bundle specify bằng `server.ssl.bundle` được dùng cho default host và cho mọi client không support SNI.
Default bundle này phải được configure nếu có bất kỳ `server.ssl.server-name-bundles` nào.

[[howto.webserver.configure-http2]]
== Configure HTTP/2

Có thể enable HTTP/2 support trong Spring Boot application bằng configprop:server.http2.enabled[].
Cả `h2` (HTTP/2 over TLS) và `h2c` (HTTP/2 over TCP) được hỗ trợ.
Để dùng `h2`, SSL cũng phải enable.
Khi SSL không enable, `h2c` được dùng.
Ví dụ có thể dùng `h2c` khi application xref:webserver.adoc#howto.webserver.use-behind-a-proxy-server[chạy sau proxy server] thực hiện TLS termination.

[[howto.webserver.configure-http2.tomcat]]
=== HTTP/2 với Tomcat

Spring Boot mặc định ship Tomcat 11.0.x hỗ trợ `h2c` và `h2` out of the box.
Ngoài ra có thể dùng `libtcnative` cho `h2` nếu library và dependency được install trên host OS.

Library directory phải available trên JVM library path nếu chưa có.
Có thể dùng JVM argument như `-Djava.library.path=/usr/local/opt/tomcat-native/lib`.
Xem thêm {url-tomcat-docs}/apr.html[official Tomcat documentation].

[[howto.webserver.configure-http2.jetty]]
=== HTTP/2 với Jetty

Để support HTTP/2, Jetty cần dependency `org.eclipse.jetty.http2:jetty-http2-server`.
Dùng `h2c` không cần dependency khác.
Để dùng `h2`, cũng cần chọn một trong các dependency sau tùy deployment:

* `org.eclipse.jetty:jetty-alpn-java-server` để dùng JDK built-in support.
* `org.eclipse.jetty:jetty-alpn-conscrypt-server` và https://www.conscrypt.org/[Conscrypt library].

[[howto.webserver.configure-http2.netty]]
=== HTTP/2 với Reactor Netty

`spring-boot-webflux-starter` mặc định dùng Reactor Netty làm server.
Reactor Netty hỗ trợ `h2c` và `h2` out of the box.
Để có optimal runtime performance, server cũng hỗ trợ `h2` với native library.
Để enable, application cần additional dependency.

Spring Boot manage version cho "uber jar" `io.netty:netty-tcnative-boringssl-static` chứa native library cho mọi platform.
Developer có thể chỉ import required dependency bằng classifier; xem https://netty.io/wiki/forked-tomcat-native.html[Netty official documentation].

== Thêm Servlet, Filter hoặc Listener vào Application

Trong servlet stack application, tức dùng `spring-boot-starter-web`, có hai cách thêm javadoc:jakarta.servlet.Servlet[], javadoc:jakarta.servlet.Filter[], javadoc:jakarta.servlet.ServletContextListener[] và listener khác Servlet API hỗ trợ:

[[howto.webserver.add-servlet-filter-listener.spring-bean]]
=== Thêm Servlet, Filter hoặc Listener bằng Spring Bean

Để thêm javadoc:jakarta.servlet.Servlet[], javadoc:jakarta.servlet.Filter[] hoặc servlet `*Listener` bằng Spring bean, phải cung cấp definition javadoc:org.springframework.context.annotation.Bean[format=annotation].
Cách này hữu ích khi muốn inject configuration hoặc dependency.
Tuy nhiên phải rất cẩn thận để không gây eager initialization quá nhiều bean khác vì chúng phải install vào container rất sớm trong application lifecycle.
Ví dụ không nên để chúng depend vào javadoc:javax.sql.DataSource[] hoặc JPA configuration.
Có thể workaround bằng cách initialize bean lazily khi lần đầu được dùng thay vì lúc initialization.

Với filter và servlet, cũng có thể thêm mapping và init parameter bằng javadoc:org.springframework.boot.web.servlet.FilterRegistrationBean[] hoặc javadoc:org.springframework.boot.web.servlet.ServletRegistrationBean[] thay vì hoặc bổ sung underlying component.
Cũng có thể dùng javadoc:org.springframework.boot.web.servlet.ServletRegistration[format=annotation] và javadoc:org.springframework.boot.web.servlet.FilterRegistration[format=annotation] làm annotation-based alternative cho ServletRegistrationBean và FilterRegistrationBean.

[NOTE]
====
Nếu không specify `dispatcherType` trên filter registration, `REQUEST` được dùng.
Điều này align với default dispatcher type của servlet specification.
====

Giống Spring bean khác, có thể define order của servlet filter bean; xem xref:reference:web/servlet.adoc#web.servlet.embedded-container.servlets-filters-listeners.beans[].

[[howto.webserver.configure-access-logs]]
== Configure Access Logging

Access log có thể configure cho Tomcat và Jetty qua namespace tương ứng.

Ví dụ setting sau log access trên Tomcat với {url-tomcat-docs}/config/valve.html#Access_Logging[custom pattern]:

[configprops,yaml]
----
server:
  tomcat:
    basedir: "my-tomcat"
    accesslog:
      enabled: true
      pattern: "%t %a %r %s (%D microseconds)"
----

NOTE: Default location của log là directory `logs` relative với Tomcat base directory.
Mặc định `logs` là temporary directory, nên có thể muốn fix Tomcat base directory hoặc dùng absolute path cho log.
Trong ví dụ trên, log available tại `my-tomcat/logs` relative với application working directory.

Access logging cho Jetty configure như sau:

[configprops,yaml]
----
server:
  jetty:
    accesslog:
      enabled: true
      filename: "/var/log/jetty-access.log"
----

Mặc định log redirect tới javadoc:java.lang.System#err[].
Chi tiết xem Jetty documentation.

[[howto.webserver.use-behind-a-proxy-server]]
== Chạy sau Front-end Proxy Server

Nếu application chạy sau proxy, load balancer hoặc trên cloud, request information như host, port, scheme có thể thay đổi trên đường đi.
Application có thể chạy trên `10.10.10.10:8080` nhưng HTTP client chỉ nên thấy `example.org`.

Có hai tập HTTP header intermediary có thể dùng để cung cấp information về original request:

1. Well-known header `"X-Forwarded-*"` như `"X-Forwarded-Host"`, `"X-Forwarded-Port"`, `"X-Forwarded-Proto"`, `"X-Forwarded-For"`.
2. Header `"Forwarded"` được define bởi https://tools.ietf.org/html/rfc7239[RFC7239 "Forwarded Headers"].

Bước đầu developer cần kiểm tra tập header nào được proxy, load balancer hoặc cloud platform hỗ trợ.
Dù RFC7239 là standard, adoption khá thấp và well-known header `"X-Forwarded-*"` có lẽ là loại cần dùng.
Sau đó có thể configure application đọc header và tự động dùng information khi tạo link và gửi cho client trong HTTP 302 response, JSON document hoặc HTML page.

Nếu web server support tập HTTP header cần dùng, set `server.forward-headers-strategy` thành `NATIVE` là lựa chọn tốt:

|===
| Server | Support | Xem thêm

| Tomcat
| `"X-Forwarded-*"`
| xref:how-to:webserver.adoc#howto.webserver.use-behind-a-proxy-server.tomcat[]

| Jetty
| `"X-Forwarded-*"`, `"Forwarded"`
| xref:how-to:webserver.adoc#howto.webserver.use-behind-a-proxy-server.jetty[]

| Reactor Netty
| `"X-Forwarded-*"`, `"Forwarded"`
| xref:how-to:webserver.adoc#howto.webserver.use-behind-a-proxy-server.reactor-netty[]
|===

Nếu chưa đủ, Spring Framework cung cấp {url-spring-framework-docs}/web/webmvc/filters.html#filters-forwarded-headers[ForwardedHeaderFilter] cho Spring MVC app và {url-spring-framework-docs}/web/webflux/reactive-spring.html#webflux-forwarded-headers[ForwardedHeaderTransformer] cho WebFlux app.
Dùng chúng bằng cách set configprop:server.forward-headers-strategy[] thành `FRAMEWORK` và chọn variant phù hợp bằng configprop:spring.mvc.forwarded-headers.header-format[] hoặc configprop:spring.webflux.forwarded-headers.header-format[].

NOTE: Nếu application chạy javadoc:org.springframework.boot.cloud.CloudPlatform#enum-constant-summary[trên supported Cloud Platform], property configprop:server.forward-headers-strategy[] default là `NATIVE`.
Trường hợp khác default là `NONE`.

[[howto.webserver.use-behind-a-proxy-server.tomcat]]
=== Customize Proxy Configuration của Tomcat

Nếu dùng Tomcat, có thể configure thêm tên header dùng để carry "forwarded" information:

[configprops,yaml]
----
server:
  tomcat:
    remoteip:
      remote-ip-header: "x-your-remote-ip-header"
      protocol-header: "x-your-protocol-header"
----

Tomcat cũng được configure với regular expression match internal proxy được trust.
Xem xref:appendix:application-properties/index.adoc#application-properties.server.server.tomcat.remoteip.internal-proxies[configprop:server.tomcat.remoteip.internal-proxies[] trong appendix] để biết default value.
Customize valve configuration bằng entry trong `application.properties`:

[configprops,yaml]
----
server:
  tomcat:
    remoteip:
      internal-proxies: "192\\.168\\.\\d{1,3}\\.\\d{1,3}"
----

NOTE: Có thể trust mọi proxy bằng cách set `internal-proxies` rỗng, nhưng không nên làm vậy trong production.

TIP: Nếu dùng Tomcat, terminate SSL ở proxy, và đã set configprop:server.tomcat.servlet.use-relative-redirects[] thành `false`, thì configprop:server.tomcat.servlet.redirect-context-root[] cũng nên set `false`.
Điều này cho phép header `X-Forwarded-Proto` được honor trước khi redirect.
Khi dùng relative redirect, default của Tomcat, context root redirect không mang scheme nên không có gì để header correct.

Có thể kiểm soát hoàn toàn configuration javadoc:org.apache.catalina.valves.RemoteIpValve[] của Tomcat bằng cách tắt automatic one, set `server.forward-headers-strategy=NONE`, rồi thêm valve instance mới qua bean javadoc:org.springframework.boot.web.server.WebServerFactoryCustomizer[].

[[howto.webserver.use-behind-a-proxy-server.jetty]]
=== Customize Proxy Configuration của Jetty

Nếu dùng Jetty, có thể configure type của header carry "forwarded" information.
Mặc định dùng format `"X-Forwarded-*"`, nhưng có thể opt in standard RFC variant:

[configprops,yaml]
----
server:
  jetty:
    forwarded-headers:
      header-format: "standard"
----

Với option cụ thể hơn, có thể tắt forwarded configuration bằng `server.forward-headers-strategy=NONE` rồi trực tiếp dùng javadoc:org.eclipse.jetty.server.ForwardedRequestCustomizer[] để thay HTTP configuration.

== Enable MBean Registry của Tomcat

MBean registry của embedded Tomcat mặc định disable.
Điều này giảm memory footprint của Tomcat.
Nếu muốn dùng Tomcat MBean, ví dụ để Micrometer expose metric, phải enable bằng configprop:server.tomcat.mbeanregistry.enabled[]:

[configprops,yaml]
----
server:
  tomcat:
    mbeanregistry:
      enabled: true
----
