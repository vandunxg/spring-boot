[[howto.application.failure-analyzer]]
== Tạo FailureAnalyzer riêng

javadoc:org.springframework.boot.diagnostics.FailureAnalyzer[] là cách hiệu quả để intercept một exception khi startup và chuyển nó thành message dễ đọc, được wrap trong javadoc:org.springframework.boot.diagnostics.FailureAnalysis[].
Spring Boot cung cấp analyzer như vậy cho các exception liên quan đến application context, JSR-303 validation và nhiều trường hợp khác.
Bạn cũng có thể tạo analyzer riêng.

javadoc:org.springframework.boot.diagnostics.AbstractFailureAnalyzer[] là extension tiện lợi của javadoc:org.springframework.boot.diagnostics.FailureAnalyzer[], kiểm tra xem exception cần xử lý có chứa một exception type cụ thể hay không.
Bạn có thể extend class này để implementation của mình chỉ có cơ hội xử lý exception khi exception type đó thực sự xuất hiện.
Nếu vì bất kỳ lý do nào bạn không thể xử lý exception, hãy trả về `null` để implementation khác có cơ hội xử lý.

Implementation của javadoc:org.springframework.boot.diagnostics.FailureAnalyzer[] phải được register trong `META-INF/spring.factories`.
Ví dụ sau register `ProjectConstraintViolationFailureAnalyzer`:

[source,properties]
----
org.springframework.boot.diagnostics.FailureAnalyzer=\
com.example.ProjectConstraintViolationFailureAnalyzer
----

NOTE: Nếu cần access javadoc:org.springframework.beans.factory.BeanFactory[] hoặc javadoc:org.springframework.core.env.Environment[], hãy khai báo chúng dưới dạng constructor argument trong implementation javadoc:org.springframework.boot.diagnostics.FailureAnalyzer[].

[[howto.application.troubleshoot-auto-configuration]]
== Xử lý sự cố Auto-configuration

Auto-configuration của Spring Boot cố gắng hết mức để "`làm đúng`", nhưng đôi khi vẫn xảy ra lỗi và khó xác định nguyên nhân.

Một javadoc:org.springframework.boot.autoconfigure.condition.ConditionEvaluationReport[] rất hữu ích có sẵn trong mọi Spring Boot javadoc:org.springframework.context.ApplicationContext[].
Bạn có thể xem report này khi enable logging output ở mức `DEBUG`.
Nếu dùng `spring-boot-actuator` (xem phần xref:actuator.adoc[]), endpoint `conditions` cũng render report dưới dạng JSON.
Dùng endpoint này để debug application và xem feature nào đã được Spring Boot thêm vào runtime (và feature nào chưa được thêm).

Nhiều câu hỏi khác có thể được giải đáp bằng cách xem source code và API documentation.
Khi đọc code, hãy nhớ các quy tắc kinh nghiệm sau:

* Tìm các class có tên `+*AutoConfiguration+` và đọc source của chúng.
  Đặc biệt chú ý các annotation `+@Conditional*+` để biết chúng enable feature nào và trong điều kiện nào.
  Thêm `--debug` vào command line hoặc System property `-Ddebug` để nhận log trên console về tất cả quyết định auto-configuration được đưa ra trong application.
  Với application đang chạy đã enable actuator, xem endpoint `conditions` (`/actuator/conditions` hoặc JMX tương đương) để có cùng thông tin.
* Tìm các class có javadoc:org.springframework.boot.context.properties.ConfigurationProperties[format=annotation] (như javadoc:org.springframework.boot.web.server.autoconfigure.ServerProperties[]) và đọc các external configuration option có sẵn từ đó.
  Annotation javadoc:org.springframework.boot.context.properties.ConfigurationProperties[format=annotation] có attribute `name` đóng vai trò prefix cho external property.
  Vì vậy javadoc:org.springframework.boot.web.server.autoconfigure.ServerProperties[] có `prefix="server"` và các configuration property là `server.port`, `server.address` cùng những property khác.
  Trong application đang chạy đã enable actuator, xem endpoint `configprops`.
* Tìm các chỗ sử dụng method `bind` trên javadoc:org.springframework.boot.context.properties.bind.Binder[] để explicit lấy configuration value từ javadoc:org.springframework.core.env.Environment[] theo cơ chế relaxed binding.
  Method này thường được dùng cùng một prefix.
* Tìm các annotation javadoc:org.springframework.beans.factory.annotation.Value[format=annotation] bind trực tiếp vào javadoc:org.springframework.core.env.Environment[].
* Tìm các annotation javadoc:org.springframework.boot.autoconfigure.condition.ConditionalOnExpression[format=annotation] để bật và tắt feature theo các SpEL expression, thường được evaluate với các placeholder đã được resolve từ javadoc:org.springframework.core.env.Environment[].

[[howto.application.customize-the-environment-or-application-context]]
== Tùy chỉnh Environment hoặc ApplicationContext trước khi start

javadoc:org.springframework.boot.SpringApplication[] có các implementation javadoc:org.springframework.context.ApplicationListener[] và javadoc:org.springframework.context.ApplicationContextInitializer[] được dùng để apply customization cho context hoặc environment.
Spring Boot load một số customization như vậy từ `META-INF/spring.factories` để sử dụng nội bộ.
Có nhiều cách register additional customization:

* Programmatically, theo từng application, bằng cách gọi method `addListeners` và `addInitializers` trên javadoc:org.springframework.boot.SpringApplication[] trước khi run.
* Declaratively, cho mọi application, bằng cách thêm `META-INF/spring.factories` rồi package một jar file mà tất cả application sử dụng làm library.

javadoc:org.springframework.boot.SpringApplication[] gửi một số javadoc:org.springframework.test.context.event.ApplicationEvents[] đặc biệt tới các listener (một số event được gửi ngay cả trước khi context được tạo), sau đó cũng register các listener đó cho những event được javadoc:org.springframework.context.ApplicationContext[] publish.
Xem xref:reference:features/spring-application.adoc#features.spring-application.application-events-and-listeners[] trong phần "`Spring Boot Features`" để biết đầy đủ danh sách.

Cũng có thể customize javadoc:org.springframework.core.env.Environment[] trước khi application context được refresh bằng cách sử dụng javadoc:org.springframework.boot.EnvironmentPostProcessor[].
Mỗi implementation phải được register trong `META-INF/spring.factories`, như ví dụ sau:

[source]
----
org.springframework.boot.EnvironmentPostProcessor=com.example.YourEnvironmentPostProcessor
----

Implementation có thể load các file tùy ý và thêm chúng vào javadoc:org.springframework.core.env.Environment[].
Ví dụ sau load một YAML configuration file từ classpath:

include-code::MyEnvironmentPostProcessor[]

TIP: javadoc:org.springframework.core.env.Environment[] đã được chuẩn bị sẵn với tất cả property source thông thường mà Spring Boot load theo mặc định.
Vì vậy, có thể lấy location của file từ environment.
Ví dụ trên thêm property source `custom-resource` vào cuối list, để một key được định nghĩa ở bất kỳ location thông thường nào khác được ưu tiên.
Custom implementation có thể định nghĩa order khác.

CAUTION: Mặc dù việc sử dụng javadoc:org.springframework.context.annotation.PropertySource[format=annotation] trên javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] có vẻ là cách thuận tiện để load custom resource vào javadoc:org.springframework.core.env.Environment[], chúng tôi không khuyến nghị cách này.
Các property source như vậy chỉ được thêm vào javadoc:org.springframework.core.env.Environment[] khi application context đang được refresh.
Thời điểm đó quá muộn để configure một số property như `+logging.*+` và `+spring.main.*+`, vốn được đọc trước khi bắt đầu refresh.

[[howto.application.non-web-application]]
== Tạo non-web application

Không phải mọi Spring application đều phải là web application (hoặc web service).
Nếu muốn execute một đoạn code trong method `main` nhưng vẫn bootstrap Spring application để setup infrastructure cần dùng, bạn có thể sử dụng các feature của javadoc:org.springframework.boot.SpringApplication[].
javadoc:org.springframework.boot.SpringApplication[] thay đổi class javadoc:org.springframework.context.ApplicationContext[] tùy theo việc nó xác định có cần web application hay không.
Việc đầu tiên bạn có thể làm để hỗ trợ là loại các server-related dependency (như servlet API) khỏi classpath.
Nếu không thể làm vậy (ví dụ chạy hai application từ cùng code base), bạn có thể explicit gọi `setWebApplicationType(WebApplicationType.NONE)` trên instance javadoc:org.springframework.boot.SpringApplication[] hoặc set property `applicationContextClass` (thông qua Java API hoặc external properties).
Application code muốn chạy dưới dạng business logic có thể được implement bằng javadoc:org.springframework.boot.CommandLineRunner[] và đưa vào context dưới dạng một Bean definition javadoc:org.springframework.context.annotation.Bean[format=annotation].
