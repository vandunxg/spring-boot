[[howto.spring-mvc]]
= Spring MVC

Spring Boot có một số starter bao gồm Spring MVC.
Lưu ý rằng một số starter có dependency vào Spring MVC thay vì include trực tiếp Spring MVC.
Phần này trả lời các câu hỏi phổ biến về Spring MVC và Spring Boot.



[[howto.spring-mvc.write-json-rest-service]]
== Viết JSON REST Service

Bất kỳ Spring javadoc:org.springframework.web.bind.annotation.RestController[format=annotation] nào trong một Spring Boot application cũng mặc định render JSON response miễn là Jackson 3 có trên classpath, như trong ví dụ sau:

include-code::MyController[]

Miễn là `MyThing` có thể được Jackson 3 serialize (đúng với một POJO hoặc Groovy object thông thường), `http://localhost:8080/thing` sẽ mặc định cung cấp JSON representation của nó.
Lưu ý rằng trong browser, đôi khi bạn có thể thấy XML response vì browser thường gửi các accept header ưu tiên XML.



[[howto.spring-mvc.write-xml-rest-service]]
== Viết XML REST Service

Nếu Jackson XML extension (`jackson-dataformat-xml`) có trên classpath, bạn có thể dùng extension này để render XML response.
Ví dụ trước đó mà chúng ta dùng cho JSON cũng sẽ hoạt động.
Để dùng Jackson XML renderer, hãy thêm dependency sau vào project:

[source,xml]
----
<dependency>
	<groupId>tools.jackson.dataformat</groupId>
	<artifactId>jackson-dataformat-xml</artifactId>
</dependency>
----

Nếu Jackson XML extension không available nhưng JAXB available, XML có thể được render với requirement bổ sung là `MyThing` phải được annotate bằng javadoc:jakarta.xml.bind.annotation.XmlRootElement[format=annotation], như trong ví dụ sau:

include-code::MyThing[]

Bạn cần đảm bảo JAXB library là một phần của project, chẳng hạn bằng cách thêm:

[source,xml]
----
<dependency>
	<groupId>org.glassfish.jaxb</groupId>
	<artifactId>jaxb-runtime</artifactId>
</dependency>
----

NOTE: Để server render XML thay vì JSON, bạn có thể phải gửi header `Accept: text/xml` (hoặc dùng browser).



[[howto.spring-mvc.customize-jackson-jsonmapper]]
== Tùy chỉnh Jackson JsonMapper

Bạn có thể configure javadoc:tools.jackson.databind.json.JsonMapper[] bằng environment.
Jackson cung cấp một bộ on/off feature phong phú để configure nhiều khía cạnh trong quá trình processing.
Các feature này được mô tả trong một số enum (trong Jackson), ánh xạ tới các property trong environment:

|===
| Enum | Property | Values

| javadoc:tools.jackson.databind.cfg.DateTimeFeature[]
| `spring.jackson.datatype.datetime.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.databind.cfg.EnumFeature[]
| `spring.jackson.datatype.enum.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.databind.cfg.JsonNodeFeature[]
| `spring.jackson.datatype.json-node.<feature_name>`
| `true`, `false`

| javadoc:com.fasterxml.jackson.annotation.JsonInclude$Include[]
| configprop:spring.jackson.default-property-inclusion[]
| `always`, `non_null`, `non_absent`, `non_default`, `non_empty`

| javadoc:tools.jackson.databind.DeserializationFeature[]
| `spring.jackson.deserialization.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.core.json.JsonReadFeature[]
| `spring.jackson.json.read.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.core.json.JsonWriteFeature[]
| `spring.jackson.json.write.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.databind.MapperFeature[]
| `spring.jackson.mapper.<feature_name>`
| `true`, `false`

| javadoc:tools.jackson.databind.SerializationFeature[]
| `spring.jackson.serialization.<feature_name>`
| `true`, `false`
|===

Ví dụ, để enable pretty print, hãy set `spring.jackson.serialization.indent_output=true`.
Lưu ý rằng nhờ xref:reference:features/external-config.adoc#features.external-config.typesafe-configuration-properties.relaxed-binding[relaxed binding], case của `indent_output` không cần khớp với case của enum constant tương ứng là `INDENT_OUTPUT`.

Configuration dựa trên environment này được apply vào auto-configured javadoc:tools.jackson.databind.json.JsonMapper$Builder[] bean và áp dụng cho mọi mapper được tạo bằng builder, bao gồm cả auto-configured javadoc:tools.jackson.databind.json.JsonMapper[] bean.

Để hỗ trợ migration cho một application trước đây dùng Jackson 2, auto-configured `JsonMapper` có thể được configure để dùng các default gần nhất có thể với những default Spring Boot từng dùng cho Jackson 2.
Để enable các default này, hãy set configprop:spring.jackson.use-jackson2-defaults[] thành `true`.

javadoc:tools.jackson.databind.json.JsonMapper$Builder[] của context có thể được customize bằng một hoặc nhiều javadoc:org.springframework.boot.jackson.autoconfigure.JsonMapperBuilderCustomizer[] bean.
Các customizer bean có thể được order (customizer của Boot có order bằng 0), cho phép áp dụng customization bổ sung cả trước và sau customization của Boot.
Ngoài ra, `JsonFactory` được builder sử dụng và mapper mà nó tạo ra có thể được customize bằng một hoặc nhiều javadoc:org.springframework.boot.jackson.autoconfigure.JsonFactoryBuilderCustomizer[] bean.
Bạn cũng có thể dùng nhiều property `spring.jackson.factory` để configure factory.

Mọi bean có type javadoc:tools.jackson.databind.JacksonModule[] đều được tự động register với auto-configured javadoc:tools.jackson.databind.json.JsonMapper$Builder[] và được áp dụng cho mọi javadoc:tools.jackson.databind.json.JsonMapper[] instance mà builder tạo ra.
Điều này cung cấp một cơ chế application-wide để contribute custom module khi bạn thêm feature mới vào application.

Theo mặc định, mọi module tham gia cơ chế Java `ServiceLoader` đều được tìm thấy và thêm vào auto-configured javadoc:tools.jackson.databind.json.JsonMapper$Builder[].
Để disable behavior này, hãy set configprop:spring.jackson.find-and-add-modules[] thành `false`.

Nếu muốn replace hoàn toàn javadoc:tools.jackson.databind.json.JsonMapper[] mặc định, hãy define một javadoc:org.springframework.context.annotation.Bean[format=annotation] có type đó hoặc, nếu thích builder-based approach, hãy define một javadoc:tools.jackson.databind.json.JsonMapper$Builder[] javadoc:org.springframework.context.annotation.Bean[format=annotation].
Khi define javadoc:tools.jackson.databind.json.JsonMapper[] bean, nên đánh dấu bean đó bằng javadoc:org.springframework.context.annotation.Primary[format=annotation], vì auto-configured javadoc:tools.jackson.databind.json.JsonMapper[] mà bean này replace cũng là javadoc:org.springframework.context.annotation.Primary[format=annotation].
Lưu ý rằng trong cả hai trường hợp, việc này sẽ disable toàn bộ auto-configuration của javadoc:tools.jackson.databind.json.JsonMapper[].

Nếu bạn cung cấp bất kỳ javadoc:org.springframework.context.annotation.Bean[format=annotation] nào có type javadoc:org.springframework.http.converter.json.JacksonJsonHttpMessageConverter[], chúng sẽ replace giá trị mặc định trong MVC configuration.
Bạn cũng có thể declare các javadoc:org.springframework.boot.http.converter.autoconfigure.ServerHttpMessageConvertersCustomizer[] bean để thêm converter hoặc override một default converter cụ thể, như được mô tả trong xref:reference:web/servlet.adoc#web.servlet.spring-mvc.message-converters[].

Xem section xref:spring-mvc.adoc#howto.spring-mvc.customize-responsebody-rendering[] và source code {code-spring-boot-webmvc-src}/autoconfigure/WebMvcAutoConfiguration.java[`WebMvcAutoConfiguration`] để biết thêm chi tiết.



[[howto.spring-mvc.customize-responsebody-rendering]]
== Tùy chỉnh @ResponseBody Rendering

Spring dùng javadoc:org.springframework.http.converter.HttpMessageConverters[] để render javadoc:org.springframework.web.bind.annotation.ResponseBody[format=annotation] (hoặc các response từ javadoc:org.springframework.web.bind.annotation.RestController[format=annotation]).
Bạn có thể contribute thêm converter bằng cách thêm bean có type phù hợp vào Spring Boot context.
Nếu bean bạn thêm có type vốn đã được include theo mặc định (chẳng hạn javadoc:org.springframework.http.converter.json.JacksonJsonHttpMessageConverter[] cho JSON conversion), bean đó sẽ replace giá trị mặc định.
Để kiểm soát nhiều hơn, hãy declare các javadoc:org.springframework.boot.http.converter.autoconfigure.ServerHttpMessageConvertersCustomizer[] bean, cho phép bạn chọn thêm converter trước các converter mặc định hoặc override một default converter cụ thể.
Các converter được client sử dụng được configure riêng bằng các javadoc:org.springframework.boot.http.converter.autoconfigure.ClientHttpMessageConvertersCustomizer[] bean.

Như trong normal MVC usage, bất kỳ javadoc:org.springframework.web.servlet.config.annotation.WebMvcConfigurer[] bean nào bạn cung cấp cũng có thể contribute converter bằng cách override method `configureMessageConverters`.
Tuy nhiên, khác với normal MVC, bạn chỉ cần cung cấp các converter bổ sung cần thiết (vì Spring Boot dùng cùng mechanism để contribute các converter mặc định của mình).
Cuối cùng, nếu opt out khỏi default Spring Boot MVC configuration bằng cách cung cấp configuration riêng với javadoc:org.springframework.web.servlet.config.annotation.EnableWebMvc[format=annotation], bạn có thể hoàn toàn tự kiểm soát và thực hiện mọi việc thủ công bằng `getMessageConverters` từ javadoc:org.springframework.web.servlet.config.annotation.WebMvcConfigurationSupport[].

Xem source code {code-spring-boot-webmvc-src}/autoconfigure/WebMvcAutoConfiguration.java[`WebMvcAutoConfiguration`] để biết thêm chi tiết.



[[howto.spring-mvc.multipart-file-uploads]]
== Xử lý Multipart File Uploads

Spring Boot sử dụng servlet 5 javadoc:jakarta.servlet.http.Part[] API để hỗ trợ upload file.
Theo mặc định, Spring Boot configure Spring MVC với maximum size là 1MB cho mỗi file và maximum 10MB file data trong một request.
Bạn có thể override các giá trị này, location nơi intermediate data được lưu (chẳng hạn directory `/tmp`), và threshold mà sau đó data được flush xuống disk bằng các property được expose trong class javadoc:org.springframework.boot.servlet.autoconfigure.MultipartProperties[].
Ví dụ, nếu muốn chỉ định rằng file không bị giới hạn, hãy set property configprop:spring.servlet.multipart.max-file-size[] thành `-1`.

Multipart support hữu ích khi bạn muốn nhận multipart encoded file data dưới dạng parameter được annotate bằng javadoc:org.springframework.web.bind.annotation.RequestParam[format=annotation], có type javadoc:org.springframework.web.multipart.MultipartFile[], trong controller handler method của Spring MVC.

Xem source {code-spring-boot-servlet-src}/autoconfigure/MultipartAutoConfiguration.java[`MultipartAutoConfiguration`] để biết thêm chi tiết.

NOTE: Bạn nên dùng built-in support của container cho multipart upload thay vì thêm dependency như Apache Commons File Upload.



[[howto.spring-mvc.switch-off-dispatcherservlet]]
== Tắt Spring MVC DispatcherServlet

Theo mặc định, mọi content được serve từ root của application (`/`).
Nếu muốn map tới một path khác, bạn có thể configure như sau:

[configprops,yaml]
----
spring:
  mvc:
    servlet:
      path: "/mypath"
----

Nếu có additional servlet, bạn có thể declare một javadoc:org.springframework.context.annotation.Bean[format=annotation] có type javadoc:jakarta.servlet.Servlet[] hoặc javadoc:org.springframework.boot.web.servlet.ServletRegistrationBean[] cho mỗi servlet, và Spring Boot sẽ transparently register chúng với container.
Cũng có thể dùng javadoc:org.springframework.boot.web.servlet.ServletRegistration[format=annotation] làm annotation-based alternative cho javadoc:org.springframework.boot.web.servlet.ServletRegistrationBean[].
Vì các servlet được register theo cách đó, chúng có thể được map vào một sub-context của javadoc:org.springframework.web.servlet.DispatcherServlet[] mà không invoke nó.

Việc tự configure javadoc:org.springframework.boot.webmvc.autoconfigure.DispatcherServletPath[] là unusual, nhưng nếu thực sự cần làm vậy, bạn cũng phải cung cấp một javadoc:org.springframework.context.annotation.Bean[format=annotation] có type javadoc:org.springframework.boot.webmvc.autoconfigure.DispatcherServletPath[] để cung cấp path của custom javadoc:org.springframework.web.servlet.DispatcherServlet[].



[[howto.spring-mvc.switch-off-default-configuration]]
== Tắt Default MVC Configuration

Cách dễ nhất để hoàn toàn kiểm soát MVC configuration là cung cấp javadoc:org.springframework.context.annotation.Configuration[format=annotation] của riêng bạn với annotation javadoc:org.springframework.web.servlet.config.annotation.EnableWebMvc[format=annotation].

[[howto.spring-mvc.customize-view-resolvers]]
== Tùy chỉnh ViewResolvers

javadoc:org.springframework.web.servlet.ViewResolver[] là một core component của Spring MVC, chuyển đổi view name trong javadoc:org.springframework.stereotype.Controller[format=annotation] thành các implementation thực tế của javadoc:org.springframework.web.servlet.View[].
Lưu ý rằng view resolver chủ yếu được dùng trong UI application, thay vì REST-style service (javadoc:org.springframework.web.servlet.View[] không được dùng để render javadoc:org.springframework.web.bind.annotation.ResponseBody[format=annotation]).
Có nhiều implementation của javadoc:org.springframework.web.servlet.ViewResolver[] để lựa chọn, và bản thân Spring không opinionated về việc bạn nên dùng implementation nào.
Mặt khác, Spring Boot cài đặt một hoặc hai resolver cho bạn, tùy thuộc vào những gì nó tìm thấy trên classpath và trong application context.
javadoc:org.springframework.web.servlet.DispatcherServlet[] sử dụng tất cả resolver mà nó tìm thấy trong application context, thử từng resolver theo thứ tự cho tới khi có result.
Nếu thêm resolver của riêng mình, bạn phải lưu ý order và vị trí mà resolver được thêm vào.

javadoc:org.springframework.boot.webmvc.autoconfigure.WebMvcAutoConfiguration[] thêm các javadoc:org.springframework.web.servlet.ViewResolver[] bean sau vào context của bạn:

* Một javadoc:org.springframework.web.servlet.view.InternalResourceViewResolver[] có tên '`defaultViewResolver`'.
  Resolver này tìm các physical resource có thể được render bằng `DefaultServlet` (bao gồm static resource và JSP page, nếu bạn sử dụng chúng).
  Resolver áp dụng prefix và suffix cho view name, sau đó tìm một physical resource có path đó trong servlet context (cả hai giá trị mặc định đều rỗng nhưng có thể cấu hình từ bên ngoài thông qua `spring.mvc.view.prefix` và `spring.mvc.view.suffix`).
  Bạn có thể override resolver này bằng cách cung cấp một bean cùng type.
* Một javadoc:org.springframework.web.servlet.view.BeanNameViewResolver[] có tên '`beanNameViewResolver`'.
  Đây là một thành phần hữu ích trong view resolver chain và tìm mọi bean có cùng name với javadoc:org.springframework.web.servlet.View[] đang được resolve.
  Bạn không cần phải override hoặc replace resolver này.
* Một javadoc:org.springframework.web.servlet.view.ContentNegotiatingViewResolver[] có tên '`viewResolver`' chỉ được thêm nếu *thực sự có* các bean type javadoc:org.springframework.web.servlet.View[].
  Đây là một composite resolver, delegate tới tất cả resolver khác và cố gắng tìm một match với HTTP header '`Accept`' do client gửi.
  Có một https://spring.io/blog/2013/06/03/content-negotiation-using-views[blog về javadoc:org.springframework.web.servlet.view.ContentNegotiatingViewResolver[]] hữu ích mà bạn có thể đọc để tìm hiểu thêm; bạn cũng có thể xem source code để biết chi tiết.
  Bạn có thể switch off javadoc:org.springframework.web.servlet.view.ContentNegotiatingViewResolver[] được auto-configure bằng cách define một bean có tên '`viewResolver`'.
* Nếu dùng Thymeleaf, bạn cũng có một javadoc:org.thymeleaf.spring6.view.ThymeleafViewResolver[] có tên '`thymeleafViewResolver`'.
  Resolver này tìm resource bằng cách bao quanh view name bằng prefix và suffix.
  Prefix là `spring.thymeleaf.prefix`, còn suffix là `spring.thymeleaf.suffix`.
  Giá trị mặc định của prefix và suffix lần lượt là '`classpath:/templates/`' và '`.html`'.
  Bạn có thể override javadoc:org.thymeleaf.spring6.view.ThymeleafViewResolver[] bằng cách cung cấp một bean có cùng name.
* Nếu dùng FreeMarker, bạn cũng có một javadoc:org.springframework.web.servlet.view.freemarker.FreeMarkerViewResolver[] có tên '`freeMarkerViewResolver`'.
  Resolver này tìm resource trong một loader path (được externalize thành `spring.freemarker.templateLoaderPath` và có giá trị mặc định là '`classpath:/templates/`') bằng cách bao quanh view name bằng prefix và suffix.
  Prefix được externalize thành `spring.freemarker.prefix`, còn suffix được externalize thành `spring.freemarker.suffix`.
  Giá trị mặc định của prefix là rỗng và suffix là '`.ftlh`'.
  Bạn có thể override javadoc:org.springframework.web.servlet.view.freemarker.FreeMarkerViewResolver[] bằng cách cung cấp một bean có cùng name.
  FreeMarker variables có thể được customize bằng cách define một bean có type javadoc:org.springframework.boot.freemarker.autoconfigure.FreeMarkerVariablesCustomizer[].
* Nếu dùng Groovy templates (thực tế là nếu `groovy-templates` có trên classpath), bạn cũng có một javadoc:org.springframework.web.servlet.view.groovy.GroovyMarkupViewResolver[] có tên '`groovyMarkupViewResolver`'.
  Resolver này tìm resource trong một loader path bằng cách bao quanh view name bằng prefix và suffix (được externalize thành `spring.groovy.template.prefix` và `spring.groovy.template.suffix`).
  Giá trị mặc định của prefix và suffix lần lượt là '`classpath:/templates/`' và '`.tpl`'.
  Bạn có thể override javadoc:org.springframework.web.servlet.view.groovy.GroovyMarkupViewResolver[] bằng cách cung cấp một bean có cùng name.
* Nếu dùng Mustache, bạn cũng có một javadoc:org.springframework.boot.mustache.servlet.view.MustacheViewResolver[] có tên '`mustacheViewResolver`'.
  Resolver này tìm resource bằng cách bao quanh view name bằng prefix và suffix.
  Prefix là `spring.mustache.prefix`, còn suffix là `spring.mustache.suffix`.
  Giá trị mặc định của prefix và suffix lần lượt là '`classpath:/templates/`' và '`.mustache`'.
  Bạn có thể override javadoc:org.springframework.boot.mustache.servlet.view.MustacheViewResolver[] bằng cách cung cấp một bean có cùng name.

Để biết thêm chi tiết, xem các section sau:

* {code-spring-boot-webmvc-src}/autoconfigure/WebMvcAutoConfiguration.java[`WebMvcAutoConfiguration`]
* {code-spring-boot-thymeleaf-src}/autoconfigure/ThymeleafAutoConfiguration.java[`ThymeleafAutoConfiguration`]

[[howto.spring-mvc.customize-whitelabel-error-page]]
== Tùy chỉnh '`whitelabel`' Error Page

Spring Boot cài đặt một '`whitelabel`' error page mà bạn thấy trong browser client nếu gặp server error (machine client consume JSON và các media type khác nên nhận được response hợp lý với error code chính xác).

NOTE: Set configprop:spring.web.error.whitelabel.enabled[] thành `false` để tắt default error page.
Việc này khôi phục default của servlet container mà bạn đang sử dụng.
Lưu ý rằng Spring Boot vẫn cố gắng resolve error view, vì vậy bạn có lẽ nên thêm error page riêng thay vì disable hoàn toàn.

Việc override error page bằng page riêng phụ thuộc vào templating technology bạn sử dụng.
Ví dụ, nếu dùng Thymeleaf, bạn có thể thêm template `error.html`.
Nếu dùng FreeMarker, bạn có thể thêm template `error.ftlh`.
Nhìn chung, bạn cần một javadoc:org.springframework.web.servlet.View[] resolve với name là `error` hoặc một javadoc:org.springframework.stereotype.Controller[format=annotation] handle path `/error`.
Trừ khi bạn đã replace một phần default configuration, bạn sẽ tìm thấy một javadoc:org.springframework.web.servlet.view.BeanNameViewResolver[] trong javadoc:org.springframework.context.ApplicationContext[], vì vậy một javadoc:org.springframework.context.annotation.Bean[format=annotation] có tên `error` là một cách để thực hiện việc đó.
Xem {code-spring-boot-webmvc-src}/autoconfigure/error/ErrorMvcAutoConfiguration.java[`ErrorMvcAutoConfiguration`] để biết thêm các option.

Xem thêm section về xref:reference:web/servlet.adoc#web.servlet.spring-mvc.error-handling[] để biết chi tiết cách register handler trong servlet container.
