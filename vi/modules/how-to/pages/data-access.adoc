== Configure Custom DataSource

Để configure javadoc:javax.sql.DataSource[] riêng, define bean javadoc:org.springframework.context.annotation.Bean[format=annotation] type đó trong configuration.
Spring Boot reuse javadoc:javax.sql.DataSource[] ở mọi nơi cần, gồm database initialization.
Nếu cần externalize một số setting, có thể bind javadoc:javax.sql.DataSource[] vào environment (xem xref:reference:features/external-config.adoc#features.external-config.typesafe-configuration-properties.third-party-configuration[]).

Ví dụ define data source trong bean:

include-code::custom/MyDataSourceConfiguration[]

Ví dụ define data source bằng property:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:h2:mem:mydb"
    username: "sa"
    pool-size: 30
----

Giả sử `SomeDataSource` có regular JavaBean property cho URL, username và pool size, các setting này tự động bind trước khi javadoc:javax.sql.DataSource[] available cho component khác.

Spring Boot cũng cung cấp utility builder class javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] có thể dùng tạo một trong các standard data source nếu có trên classpath.
Builder detect loại cần dùng dựa trên thứ available trên classpath.
Nó cũng auto-detect driver dựa trên JDBC URL.

Ví dụ tạo data source bằng javadoc:org.springframework.boot.jdbc.DataSourceBuilder[]:

include-code::builder/MyDataSourceConfiguration[]

Để chạy app với DataSource đó, chỉ cần connection information.
Pool-specific setting cũng có thể cung cấp.
Xem implementation sẽ dùng tại runtime để biết thêm detail.

Ví dụ define JDBC data source bằng property:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

Tuy nhiên có một vấn đề do return type javadoc:javax.sql.DataSource[] của method.
Điều này hide actual type của connection pool, nên không generate configuration property metadata cho custom DataSource và IDE không có auto-completion.
Để giải quyết, dùng method `type(Class)` của builder để specify type DataSource cần build và update return type của method.

Tiếc là basic setup này không hoạt động vì Hikari không có property `url`.
Thay vào đó nó có property `jdbc-url`, nghĩa là phải rewrite configuration:

[configprops%novalidate,yaml]
----
app:
  datasource:
    jdbc-url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

Để giải quyết vấn đề này, dùng javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[]; class này handle translation từ `url` sang `jdbc-url`.
Có thể initialize javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] từ state của bất kỳ object DataSourceProperties nào bằng method `initializeDataSourceBuilder()`.
Có thể inject DataSourceProperties mà Spring Boot tự động tạo, nhưng như vậy configuration bị split giữa `+spring.datasource.*+` và `+app.datasource.*+`.

Setup này tương đương những gì Spring Boot mặc định làm, ngoại trừ pool type được specify trong code và setting expose thành property `app.datasource.configuration.*`.
DataSourceProperties xử lý translation `url` sang `jdbc-url`, nên có thể configure:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    configuration:
      maximum-pool-size: 30
----

Lưu ý vì custom configuration specify trong code rằng Hikari phải được dùng, `app.datasource.type` không có effect.

Như mô tả trong xref:reference:data/sql.adoc#data.sql.datasource.connection-pool[], DataSourceBuilder hỗ trợ nhiều connection pool khác nhau.
Để dùng pool khác Hikari, thêm nó vào classpath, dùng `type(Class)` để specify pool class và update return type của Bean method cho match.
Điều này cũng cung cấp configuration property metadata cho specific connection pool được chọn.

TIP: Spring Boot expose Hikari-specific setting tại `spring.datasource.hikari`.
Ví dụ này dùng sub-namespace generic hơn là `configuration` vì ví dụ không hỗ trợ nhiều datasource implementation.

[[howto.data-access.spring-data-repositories]]
== Dùng Spring Data Repositories

Spring Data có thể tạo implementation của interface javadoc:org.springframework.data.repository.Repository[] với nhiều flavor.
Spring Boot xử lý tất cả miễn các implementation Repository nằm trong một trong các xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[auto-configuration package], thường là package hoặc sub-package của main application class annotate javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] hoặc javadoc:org.springframework.boot.autoconfigure.EnableAutoConfiguration[format=annotation].

Với nhiều application, chỉ cần đặt đúng Spring Data dependency trên classpath.
Có `spring-boot-starter-data-jpa` cho JPA, `spring-boot-starter-data-mongodb` cho MongoDB và nhiều starter khác cho supported technology.
Để bắt đầu, tạo repository interface để handle object javadoc:jakarta.persistence.Entity[format=annotation].

Spring Boot xác định location của Repository implementation bằng cách scan xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[auto-configuration package].
Để kiểm soát nhiều hơn, dùng annotation `@Enable…Repositories` từ Spring Data.

Để biết thêm về Spring Data, xem {url-spring-data-site}[Spring Data project page].

[[howto.data-access.jpa-properties]]
== Configure JPA Properties

Spring Data JPA đã cung cấp một số vendor-independent configuration option, như SQL logging, và Spring Boot expose các option đó cùng một số option khác cho Hibernate dưới dạng external configuration property.
Một số được auto-detect tùy context nên thường không cần set.

`spring.jpa.hibernate.ddl-auto` là case đặc biệt vì default khác nhau tùy runtime condition.
Nếu dùng embedded database và không schema manager nào như Liquibase hoặc Flyway handle DataSource, default là `create-drop`.
Các case khác default `none`.

Dialect được dùng do JPA provider detect.
Nếu muốn tự set dialect, set configprop:spring.jpa.database-platform[].

Common option:

[configprops,yaml]
----
spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: "com.example.MyPhysicalNamingStrategy"
    show-sql: true
----

Ngoài ra mọi property trong `+spring.jpa.properties.*+` được pass-through như regular JPA property, bỏ prefix, khi local javadoc:jakarta.persistence.EntityManagerFactory[] được tạo.

[WARNING]
====
Cần đảm bảo name define dưới `+spring.jpa.properties.*+` match chính xác những gì JPA provider mong đợi.
Spring Boot không thực hiện relaxed binding cho các entry này.

Ví dụ nếu muốn configure Hibernate batch size phải dùng `+spring.jpa.properties.hibernate.jdbc.batch_size+`.
Nếu dùng form khác như `batchSize` hoặc `batch-size`, Hibernate không apply setting.
====

TIP: Nếu cần advanced customization cho Hibernate property, cân nhắc register bean javadoc:org.springframework.boot.hibernate.autoconfigure.HibernatePropertiesCustomizer[] được invoke trước khi tạo EntityManagerFactory.
Nó có precedence hơn mọi thứ auto-configuration apply.

[[howto.data-access.configure-hibernate-naming-strategy]]
== Configure Hibernate Naming Strategy

Hibernate dùng {url-hibernate-docs}#naming[hai naming strategy khác nhau] để map name từ object model sang database name tương ứng.
Fully qualified class name của physical và implicit strategy implementation có thể configure bằng property `spring.jpa.hibernate.naming.physical-strategy` và `spring.jpa.hibernate.naming.implicit-strategy`.
Ngoài ra nếu bean javadoc:org.hibernate.boot.model.naming.ImplicitNamingStrategy[] hoặc javadoc:org.hibernate.boot.model.naming.PhysicalNamingStrategy[] available trong application context, Hibernate tự động configure dùng chúng.

Mặc định Spring Boot configure physical naming strategy bằng javadoc:org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy[].
Với strategy này, mọi dấu chấm replace bằng underscore và camel casing cũng replace bằng underscore.
Ngoài ra mặc định mọi table name generate lowercase.
Ví dụ entity `TelephoneNumber` map tới table `telephone_number`.
Nếu schema cần mixed-case identifier, define custom bean CamelCaseToUnderscoresNamingStrategy:

include-code::spring/MyHibernateConfiguration[]

Nếu thích default của Hibernate, set property:

[configprops,yaml]
----
spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
----

Hoặc configure bean:

[[howto.data-access.use-spring-data-jpa-and-mongo-repositories]]
== Dùng Spring Data JPA và Mongo Repositories

Spring Data JPA và Spring Data Mongo đều có thể tự động tạo implementation javadoc:org.springframework.data.repository.Repository[].
Nếu cả hai có trên classpath, có thể cần thêm configuration để nói Spring Boot repository nào cần tạo.
Cách explicit nhất là dùng standard annotation javadoc:org.springframework.data.jpa.repository.config.EnableJpaRepositories[format=annotation] và javadoc:org.springframework.data.mongodb.repository.config.EnableMongoRepositories[format=annotation], đồng thời cung cấp location của Repository interface.

Cũng có flag `+spring.data.*.repositories.enabled+` và `+spring.data.*.repositories.type+` để bật/tắt auto-configured repository trong external configuration.
Ví dụ hữu ích khi muốn tắt Mongo repository nhưng vẫn dùng auto-configured javadoc:org.springframework.data.mongodb.core.MongoTemplate[].

Cùng obstacle và feature tồn tại cho các auto-configured Spring Data repository type khác như Elasticsearch, Redis, v.v.
Để làm việc với chúng, đổi annotation name và flag tương ứng.
