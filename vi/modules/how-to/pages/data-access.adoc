[[howto.data-access]]
= Data Access

Spring Boot cung cấp một số starter để làm việc với data source.
Phần này giải đáp các câu hỏi liên quan đến việc đó.



[[howto.data-access.configure-custom-datasource]]
== Configure một DataSource tùy chỉnh

Để configure javadoc:javax.sql.DataSource[] của riêng mình, hãy define một javadoc:org.springframework.context.annotation.Bean[format=annotation] có type đó trong configuration.
Spring Boot sẽ reuse javadoc:javax.sql.DataSource[] của bạn ở bất cứ nơi nào cần, bao gồm cả database initialization.
Nếu cần externalize một số setting, bạn có thể bind javadoc:javax.sql.DataSource[] với environment (xem xref:reference:features/external-config.adoc#features.external-config.typesafe-configuration-properties.third-party-configuration[]).

Ví dụ sau cho biết cách define một data source trong một bean:

include-code::custom/MyDataSourceConfiguration[]

Ví dụ sau cho biết cách define một data source bằng cách set các property của nó:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:h2:mem:mydb"
    username: "sa"
    pool-size: 30
----

Giả sử `SomeDataSource` có các JavaBean property thông thường cho URL, username và pool size, các setting này sẽ được bind tự động trước khi javadoc:javax.sql.DataSource[] được cung cấp cho các component khác.

Spring Boot cũng cung cấp một utility builder class có tên javadoc:org.springframework.boot.jdbc.DataSourceBuilder[], có thể dùng để tạo một trong các data source tiêu chuẩn (nếu data source đó có trên classpath).
Builder có thể detect data source nào cần dùng dựa trên những gì có sẵn trên classpath.
Builder cũng auto-detect driver dựa trên JDBC URL.

Ví dụ sau cho biết cách tạo một data source bằng javadoc:org.springframework.boot.jdbc.DataSourceBuilder[]:

include-code::builder/MyDataSourceConfiguration[]

Để chạy app với javadoc:javax.sql.DataSource[] đó, tất cả những gì bạn cần là connection information.
Bạn cũng có thể cung cấp các pool-specific setting.
Hãy kiểm tra implementation sẽ được dùng tại runtime để biết thêm chi tiết.

Ví dụ sau cho biết cách define một JDBC data source bằng cách set các property:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

Tuy nhiên, có một điểm cần lưu ý do return type của method là javadoc:javax.sql.DataSource[].
Điều này che đi actual type của connection pool, nên không có configuration property metadata nào được generate cho javadoc:javax.sql.DataSource[] tùy chỉnh của bạn và IDE cũng không cung cấp auto-completion.
Để xử lý vấn đề này, hãy dùng method `type(Class)` của builder để specify type của javadoc:javax.sql.DataSource[] cần được build, đồng thời update return type của method.
Ví dụ sau cho biết cách tạo javadoc:com.zaxxer.hikari.HikariDataSource[] bằng javadoc:org.springframework.boot.jdbc.DataSourceBuilder[]:

include-code::simple/MyDataSourceConfiguration[]

Đáng tiếc là basic setup này không hoạt động vì Hikari không có property `url`.
Thay vào đó, Hikari có property `jdbc-url`, nghĩa là bạn phải rewrite configuration như sau:

[configprops%novalidate,yaml]
----
app:
  datasource:
    jdbc-url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

Để xử lý vấn đề này, hãy dùng javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[]; class này sẽ handle việc dịch `url` thành `jdbc-url`.
Bạn có thể initialize javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] từ state của bất kỳ object javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[] nào bằng method `initializeDataSourceBuilder()` của object đó.
Bạn có thể inject javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[] mà Spring Boot tự động tạo, nhưng như vậy configuration của bạn sẽ bị chia giữa `+spring.datasource.*+` và `+app.datasource.*+`.
Để tránh điều này, hãy define một javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[] tùy chỉnh với configuration properties prefix tùy chỉnh, như trong ví dụ sau:

include-code::configurable/MyDataSourceConfiguration[]

Setup này tương đương với những gì Spring Boot thực hiện cho bạn theo mặc định, ngoại trừ việc type của pool được specify trong code và các setting của nó được expose thành các property `app.datasource.configuration.*`.
javadoc:org.springframework.boot.jdbc.autoconfigure.DataSourceProperties[] xử lý việc dịch `url` thành `jdbc-url`, nên bạn có thể configure như sau:

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    configuration:
      maximum-pool-size: 30
----

Lưu ý rằng vì custom configuration specify trong code việc phải dùng Hikari, `app.datasource.type` sẽ không có effect.

Như được mô tả trong xref:reference:data/sql.adoc#data.sql.datasource.connection-pool[], javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] hỗ trợ một số connection pool khác nhau.
Để dùng một pool khác Hikari, hãy thêm pool đó vào classpath, dùng method `type(Class)` để specify pool class cần dùng, rồi update return type của javadoc:org.springframework.context.annotation.Bean[format=annotation] method cho phù hợp.
Việc này cũng cung cấp configuration property metadata cho connection pool cụ thể mà bạn đã chọn.

TIP: Spring Boot sẽ expose các setting dành riêng cho Hikari tại `spring.datasource.hikari`.
Ví dụ này dùng một sub namespace generic hơn là `configuration` vì ví dụ không hỗ trợ nhiều datasource implementation.

Xem xref:reference:data/sql.adoc#data.sql.datasource[] và class {code-spring-boot-jdbc-src}/autoconfigure/DataSourceAutoConfiguration.java[`DataSourceAutoConfiguration`] để biết thêm chi tiết.

[[howto.data-access.spring-data-repositories]]
== Dùng Spring Data Repositories

Spring Data có thể tạo implementation cho các interface javadoc:org.springframework.data.repository.Repository[] thuộc nhiều flavor khác nhau.
Spring Boot handle tất cả việc đó cho bạn, miễn là các implementation javadoc:org.springframework.data.repository.Repository[] nằm trong một trong các xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[auto-configuration package], thường là package của main application class (hoặc một sub-package của package đó), nơi được annotate bằng javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] hoặc javadoc:org.springframework.boot.autoconfigure.EnableAutoConfiguration[format=annotation].

Với nhiều application, tất cả những gì bạn cần là đặt đúng Spring Data dependency trên classpath.
Có `spring-boot-starter-data-jpa` cho JPA, `spring-boot-starter-data-mongodb` cho Mongodb và nhiều starter khác cho các technology được hỗ trợ.
Để bắt đầu, hãy tạo một số repository interface để handle các object javadoc:jakarta.persistence.Entity[format=annotation].

Spring Boot xác định location của các implementation javadoc:org.springframework.data.repository.Repository[] bằng cách scan xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[auto-configuration package].
Để kiểm soát nhiều hơn, hãy dùng các annotation `@Enable…Repositories` từ Spring Data.

Để biết thêm về Spring Data, xem {url-spring-data-site}[trang project Spring Data].

[[howto.data-access.jpa-properties]]
== Configure JPA Properties

Spring Data JPA đã cung cấp một số configuration option không phụ thuộc vendor (chẳng hạn option cho SQL logging), còn Spring Boot expose các option đó và thêm một số option cho Hibernate dưới dạng external configuration property.
Một số option được auto-detect tùy theo context, nên bạn thường không cần set chúng.

`spring.jpa.hibernate.ddl-auto` là một trường hợp đặc biệt vì nó có các default khác nhau tùy theo điều kiện runtime.
Nếu dùng embedded database và không có schema manager nào (chẳng hạn Liquibase hoặc Flyway) handle javadoc:javax.sql.DataSource[], property này mặc định là `create-drop`.
Trong mọi trường hợp khác, property này mặc định là `none`.

JPA provider sẽ detect dialect cần dùng.
Nếu muốn tự set dialect, hãy set configprop:spring.jpa.database-platform[] property.

Các option thường được set nhất được minh họa trong ví dụ sau:

[configprops,yaml]
----
spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: "com.example.MyPhysicalNamingStrategy"
    show-sql: true
----

Ngoài ra, mọi property trong `+spring.jpa.properties.*+` đều được pass through như các JPA property thông thường (sau khi bỏ prefix) khi local javadoc:jakarta.persistence.EntityManagerFactory[] được tạo.

[WARNING]
====
Bạn cần đảm bảo các name được define dưới `+spring.jpa.properties.*+` match chính xác với những name mà JPA provider của bạn mong đợi.
Spring Boot sẽ không cố thực hiện bất kỳ dạng relaxed binding nào cho các entry này.

Ví dụ, nếu muốn configure batch size của Hibernate, bạn phải dùng `+spring.jpa.properties.hibernate.jdbc.batch_size+`.
Nếu dùng các form khác, chẳng hạn `batchSize` hoặc `batch-size`, Hibernate sẽ không apply setting đó.
====

TIP: Nếu cần advanced customization cho Hibernate property, hãy cân nhắc register một javadoc:org.springframework.boot.hibernate.autoconfigure.HibernatePropertiesCustomizer[] bean; bean này sẽ được invoke trước khi tạo javadoc:jakarta.persistence.EntityManagerFactory[].
Customization này được ưu tiên hơn mọi thứ được auto-configuration apply.



[[howto.data-access.configure-hibernate-naming-strategy]]
== Configure Hibernate Naming Strategy

Hibernate dùng {url-hibernate-docs}#naming[hai naming strategy khác nhau] để map name từ object model sang database name tương ứng.
Có thể configure fully qualified class name của physical strategy implementation và implicit strategy implementation bằng cách set lần lượt các property `spring.jpa.hibernate.naming.physical-strategy` và `spring.jpa.hibernate.naming.implicit-strategy`.
Ngoài ra, nếu các bean javadoc:org.hibernate.boot.model.naming.ImplicitNamingStrategy[] hoặc javadoc:org.hibernate.boot.model.naming.PhysicalNamingStrategy[] có trong application context, Hibernate sẽ tự động được configure để dùng chúng.

Theo mặc định, Spring Boot configure physical naming strategy bằng javadoc:org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy[].
Với strategy này, mọi dấu chấm đều được thay bằng underscore và camel casing cũng được thay bằng underscore.
Ngoài ra, theo mặc định, mọi table name đều được generate ở dạng lowercase.
Ví dụ, một entity `TelephoneNumber` được map tới table `telephone_number`.
Nếu schema yêu cầu mixed-case identifier, hãy define một javadoc:org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy[] bean tùy chỉnh, như trong ví dụ sau:

include-code::spring/MyHibernateConfiguration[]

Nếu muốn dùng default của Hibernate, hãy set property sau:

[configprops,yaml]
----
spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
----

Hoặc bạn có thể configure bean sau:

include-code::standard/MyHibernateConfiguration[]

Xem {code-spring-boot-hibernate-src}/autoconfigure/HibernateJpaAutoConfiguration.java[`HibernateJpaAutoConfiguration`] và {code-spring-boot-jpa-src}/autoconfigure/JpaBaseConfiguration.java[`JpaBaseConfiguration`] để biết thêm chi tiết.

[[howto.data-access.use-spring-data-jpa-and-mongo-repositories]]
== Dùng Spring Data JPA và Mongo Repositories

Spring Data JPA và Spring Data Mongo đều có thể tự động tạo các implementation javadoc:org.springframework.data.repository.Repository[] cho bạn.
Nếu cả hai cùng có trên classpath, bạn có thể phải thực hiện thêm configuration để cho Spring Boot biết cần tạo repository nào.
Cách explicit nhất là dùng các annotation Spring Data chuẩn javadoc:org.springframework.data.jpa.repository.config.EnableJpaRepositories[format=annotation] và javadoc:org.springframework.data.mongodb.repository.config.EnableMongoRepositories[format=annotation], đồng thời cung cấp location của các javadoc:org.springframework.data.repository.Repository[] interface.

Ngoài ra còn có các flag (`+spring.data.*.repositories.enabled+` và `+spring.data.*.repositories.type+`) để bạn bật hoặc tắt các repository được auto-configure trong external configuration.
Việc này hữu ích, chẳng hạn khi bạn muốn tắt Mongo repository nhưng vẫn dùng javadoc:org.springframework.data.mongodb.core.MongoTemplate[] được auto-configure.

Cùng vấn đề và các feature tương tự cũng tồn tại với những loại Spring Data repository khác được auto-configure (Elasticsearch, Redis và các loại khác).
Để làm việc với chúng, hãy thay đổi tên annotation và flag tương ứng.



[[howto.data-access.customize-spring-data-web-support]]
== Customize Spring Data Web Support

Spring Data cung cấp web support giúp đơn giản hóa việc dùng Spring Data repository trong một web application.
Spring Boot cung cấp các property trong namespace `spring.data.web` để customize configuration của web support.
Lưu ý rằng nếu đang dùng Spring Data REST, bạn phải dùng các property trong namespace `spring.data.rest` thay thế.



[[howto.data-access.exposing-spring-data-repositories-as-rest]]
== Expose Spring Data Repository thành REST Endpoint

Spring Data REST có thể expose các implementation javadoc:org.springframework.data.repository.Repository[] thành REST endpoint cho bạn,
miễn là Spring MVC đã được enable cho application.

Spring Boot expose một tập hợp property hữu ích (từ namespace `spring.data.rest`) để customize javadoc:org.springframework.data.rest.core.config.RepositoryRestConfiguration[].
Nếu cần cung cấp thêm customization, bạn nên dùng một javadoc:org.springframework.data.rest.webmvc.config.RepositoryRestConfigurer[] bean.

NOTE: Nếu không specify order trên custom javadoc:org.springframework.data.rest.webmvc.config.RepositoryRestConfigurer[] của mình, nó sẽ chạy sau configurer mà Spring Boot dùng internally.
Nếu cần specify order, hãy đảm bảo order đó lớn hơn 0.



[[howto.data-access.configure-a-component-that-is-used-by-jpa]]
== Configure một Component được JPA sử dụng

Nếu muốn configure một component mà JPA sử dụng, bạn cần đảm bảo component đó được initialize trước JPA.
Khi component được auto-configure, Spring Boot sẽ xử lý việc này cho bạn.
Ví dụ, khi Flyway được auto-configure, Hibernate được configure để depend on Flyway, nhờ đó Flyway có cơ hội initialize database trước khi Hibernate cố gắng dùng database.

Nếu tự configure một component, bạn có thể dùng một subclass của javadoc:org.springframework.boot.jpa.autoconfigure.EntityManagerFactoryDependsOnPostProcessor[] như một cách thuận tiện để setup các dependency cần thiết.
Ví dụ, nếu dùng Hibernate Search với Elasticsearch làm index manager, mọi javadoc:jakarta.persistence.EntityManagerFactory[] bean phải được configure để depend on bean `elasticsearchClient`, như trong ví dụ sau:

include-code::ElasticsearchEntityManagerFactoryDependsOnPostProcessor[]



[[howto.data-access.configure-jooq-with-multiple-datasources]]
== Configure jOOQ với hai DataSource

Nếu cần dùng jOOQ với nhiều data source, bạn nên tạo javadoc:org.jooq.DSLContext[] riêng cho từng data source.
Xem {code-spring-boot-jooq-src}/autoconfigure/JooqAutoConfiguration.java[`JooqAutoConfiguration`] để biết thêm chi tiết.

TIP: Cụ thể, javadoc:org.springframework.boot.jooq.autoconfigure.ExceptionTranslatorExecuteListener[] và javadoc:org.springframework.boot.jooq.autoconfigure.SpringTransactionProvider[] có thể được reuse để cung cấp các feature tương tự như auto-configuration khi làm việc với một javadoc:javax.sql.DataSource[] duy nhất.
