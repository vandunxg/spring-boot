[[howto.deployment.cloud]]
= Deploy lên Cloud

Executable jar của Spring Boot đã sẵn sàng cho hầu hết cloud PaaS (Platform-as-a-Service) provider phổ biến.
Các provider này thường yêu cầu bạn "`bring your own container`".
Chúng quản lý application process, không chỉ Java application, nên cần một intermediary layer để adapt _application của bạn_ với khái niệm running process của _cloud_.

Hai cloud provider phổ biến, Heroku và Cloud Foundry, dùng approach "`buildpack`".
Buildpack wrap deployed code bằng mọi thứ cần để _start_ application.
Đó có thể là JDK và một lần gọi `java`, embedded web server hoặc full-fledged application server.
Buildpack có thể plug-in, nhưng lý tưởng là bạn chỉ cần thực hiện ít customization nhất có thể.
Điều này giảm footprint của functionality không nằm trong quyền kiểm soát của bạn.
Nó giảm divergence giữa development và production environment.

Lý tưởng nhất, application, giống như Spring Boot executable jar, đã package mọi thứ cần để chạy bên trong nó.

Trong phần này, chúng ta xem cần làm gì để đưa xref:tutorial:first-application/index.adoc[application đã phát triển] trong phần "`Getting Started`" lên Cloud và chạy.

[[howto.deployment.cloud.security]]
== Các lưu ý về Security

Chỉ nên enable support cho xref:how-to:webserver.adoc#howto.webserver.use-behind-a-proxy-server[forwarded headers] khi application nhận traffic từ trusted HTTP proxy và chỉ directly accessible từ trusted network.
Khi chạy trên cloud platform, forwarded headers được enable tự động.
Điều này dựa trên assumption rằng platform sẽ đảm bảo từng application instance chỉ directly accessible từ trusted network.
Nếu platform cụ thể của bạn không đảm bảo điều đó, hãy set configprop:server.forward-headers-strategy[] thành `none`.

[[howto.deployment.cloud.cloud-foundry]]
== Cloud Foundry

Cloud Foundry cung cấp các default buildpack được sử dụng nếu không specify buildpack khác.
https://github.com/cloudfoundry/java-buildpack[Java buildpack] của Cloud Foundry hỗ trợ rất tốt cho Spring application, bao gồm Spring Boot.
Bạn có thể deploy standalone executable jar application cũng như application được package theo kiểu traditional dưới dạng `.war`.

Sau khi build application, chẳng hạn bằng `mvn clean package`, và đã https://docs.cloudfoundry.org/cf-cli/install-go-cli.html[install command line tool `cf`], hãy deploy application bằng command `cf push`, thay path bằng compiled `.jar`.
Hãy đảm bảo bạn đã https://docs.cloudfoundry.org/cf-cli/getting-started.html#login[login bằng command line client `cf`] trước khi push application.
Dòng sau minh họa việc dùng command `cf push` để deploy application:

[source,shell]
----
$ cf push acloudyspringtime -p target/demo-0.0.1-SNAPSHOT.jar
----

NOTE: Trong ví dụ trên, `acloudyspringtime` được thay cho value bạn cung cấp cho `cf` làm tên application.

Xem https://docs.cloudfoundry.org/cf-cli/getting-started.html#push[tài liệu về `cf push`] để biết thêm các option.
Nếu có file Cloud Foundry https://docs.cloudfoundry.org/devguide/deploy-apps/manifest.html[`manifest.yml`] trong cùng directory, file đó cũng được xem xét.

[[howto.deployment.cloud.cloud-foundry.binding-to-services]]
=== Binding tới Service

Mặc định, metadata về running application cũng như service connection information được expose cho application dưới dạng environment variable, ví dụ `$VCAP_SERVICES`.
Architecture decision này xuất phát từ bản chất polyglot của Cloud Foundry: bất kỳ language và platform nào cũng có thể được hỗ trợ dưới dạng buildpack.
Process-scoped environment variable không phụ thuộc language.

Environment variable không phải lúc nào cũng tạo thành API dễ dùng nhất, nên Spring Boot tự động extract và flatten data thành các property có thể access thông qua abstraction javadoc:org.springframework.core.env.Environment[], như trong ví dụ sau:

include-code::MyBean[]

Mọi Cloud Foundry property đều có prefix `vcap`.
Bạn có thể dùng các property `vcap` để access application information, chẳng hạn public URL của application, và service information, chẳng hạn database credential.
Xem API documentation của javadoc:org.springframework.boot.cloud.CloudFoundryVcapEnvironmentPostProcessor[] để biết đầy đủ detail.

TIP: Project https://github.com/pivotal-cf/java-cfenv/[Java CFEnv] phù hợp hơn cho các task như configure DataSource.

[[howto.deployment.cloud.kubernetes]]
== Kubernetes

Spring Boot auto-detect Kubernetes deployment environment bằng cách check environment để tìm các variable `"*_SERVICE_HOST"` và `"*_SERVICE_PORT"`.
Bạn có thể override detection bằng configuration property configprop:spring.main.cloud-platform[].

Spring Boot giúp bạn xref:reference:features/spring-application.adoc#features.spring-application.application-availability[manage state của application] và export state đó bằng xref:reference:actuator/endpoints.adoc#actuator.endpoints.kubernetes-probes[HTTP Kubernetes Probes thông qua Actuator].

[[howto.deployment.cloud.kubernetes.container-lifecycle]]
=== Vòng đời Container trên Kubernetes

Khi Kubernetes delete một application instance, shutdown process involve nhiều subsystem đồng thời: shutdown hook, unregister service, remove instance khỏi load-balancer...
Vì shutdown processing diễn ra song song, và do nature của distributed system, có một khoảng thời gian traffic vẫn có thể được route tới một pod đã bắt đầu shutdown processing.

Bạn có thể configure một sleep execution trong preStop handler để tránh request được route tới một pod đã bắt đầu shutdown.
Sleep này phải đủ lâu để các request mới ngừng được route tới pod, và duration sẽ thay đổi tùy deployment.
Delay phải ít nhất bằng thời gian dài nhất cần để xử lý một in-flight request.
Bạn không nên chỉ dựa vào Spring Boot graceful shutdown period, vì platform sẽ không nhận được liveness data trong thời gian app đang shutdown.

Nếu đang dùng Kubernetes 1.32 trở lên, bạn có thể configure preStop handler bằng PodSpec trong pod configuration file như sau:

[source,yaml]
----
spec:
  containers:
  - name: "example-container"
    image: "example-image"
    lifecycle:
      preStop:
        sleep:
          seconds: 10
----

Nếu chưa dùng Kubernetes 1.32, bạn có thể dùng command `exec` để invoke `sleep`.

[source,yaml]
----
spec:
  containers:
  - name: "example-container"
    image: "example-image"
    lifecycle:
      preStop:
        exec:
          command: ["sh", "-c", "sleep 10"]
----

NOTE: Container cần có shell để cách này hoạt động.

Sau khi pre-stop hook hoàn tất, SIGTERM sẽ được gửi tới container và xref:reference:web/graceful-shutdown.adoc[graceful shutdown] sẽ bắt đầu, cho phép mọi in-flight request còn lại hoàn tất.

NOTE: Khi Kubernetes gửi SIGTERM tới pod, nó chờ một khoảng thời gian được gọi là termination grace period, mặc định là 30 giây.
Nếu các container vẫn chạy sau grace period, chúng sẽ nhận SIGKILL và bị force remove.
Nếu pod mất hơn 30 giây để shutdown, có thể vì bạn đã tăng configprop:spring.lifecycle.timeout-per-shutdown-phase[], hãy đảm bảo tăng termination grace period bằng cách set option `terminationGracePeriodSeconds` trong Pod YAML.

[[howto.deployment.cloud.heroku]]
== Heroku

Heroku là một PaaS platform phổ biến khác.
Để customize Heroku build, bạn cung cấp một `Procfile` chứa command cần thiết để deploy application.
Heroku assign một `port` cho Java application rồi đảm bảo routing tới external URI hoạt động.

Bạn phải configure application listen trên đúng port.
Ví dụ sau là `Procfile` cho starter REST application:

[source]
----
web: java -Dserver.port=$PORT -jar target/demo-0.0.1-SNAPSHOT.jar
----

Spring Boot làm cho các argument `-D` available dưới dạng property có thể access từ một instance Spring javadoc:org.springframework.core.env.Environment[].
Configuration property `server.port` được truyền tới embedded Tomcat hoặc Jetty instance, sau đó instance này sử dụng port khi startup.
Environment variable `$PORT` được Heroku PaaS assign cho application.

Như vậy là đủ để deploy.
Deployment workflow phổ biến nhất cho Heroku là `git push` code lên production, như trong ví dụ sau:

[source,shell]
----
$ git push heroku main

[[howto.deployment.cloud.aws]]
== Amazon Web Services (AWS)

Amazon Web Services cung cấp một số option phù hợp để chạy Spring Boot-based application dưới dạng container, traditional web application (war) hoặc self-contained executable jar file.
Các option phổ biến bao gồm:

* Amazon Elastic Container Service (ECS)
* AWS Elastic Beanstalk

[[howto.deployment.cloud.aws.ecs]]
=== Amazon Elastic Container Service (ECS)

https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html[Amazon ECS developer guide chính thức] cung cấp overview toàn diện về các feature của platform và bao gồm https://docs.aws.amazon.com/AmazonECS/latest/developerguide/getting-started.html[getting started guide] hướng dẫn các bước cần thiết để các container chạy.

NOTE: Spring Boot application có thể được package trong Docker container bằng technique được mô tả trong xref:reference:packaging/container-images/index.adoc[].

Ngoài developer guide, AWS cũng cung cấp https://docs.aws.amazon.com/AmazonECS/latest/developerguide/create-container-image.html[topical guide] để deploy containerized Java service trên Amazon ECS bằng AWS Fargate.

TIP: Spring Boot auto-detect AWS ECS deployment environment bằng variable `AWS_EXECUTION_ENV`.
Bạn có thể override detection bằng configprop:spring.main.cloud-platform[].

Như được mô tả trong https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/create_deploy_Java.html[Elastic Beanstalk Java guide] chính thức, có hai option chính để deploy Java application.
Có thể dùng "`Tomcat Platform`" hoặc "`Java SE platform`".

[[howto.deployment.cloud.aws.beanstalk.tomcat-platform]]

Option này áp dụng cho Spring Boot project tạo ra war file.
Hãy làm theo official guide và https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/tomcat-quickstart.html[Java on Tomcat tutorial].

NOTE: Cách tạo deployable war cho Spring Boot application được mô tả trong xref:deployment/traditional-deployment.adoc[].

[[howto.deployment.cloud.aws.beanstalk.java-se-platform]]
==== Dùng Java SE Platform

Option này áp dụng cho Spring Boot project tạo ra jar file và chạy embedded web container.
Hãy làm theo official guide và https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/java-quickstart.html[Java tutorial].
Ngoài ra còn có các community tutorial, chẳng hạn https://www.baeldung.com/spring-boot-deploy-aws-beanstalk[tutorial này].

[[howto.deployment.cloud.boxfuse]]
== CloudCaptain và Amazon Web Services

https://cloudcaptain.sh/[CloudCaptain] hoạt động bằng cách biến Spring Boot executable jar hoặc war thành một minimal VM image có thể deploy nguyên trạng lên VirtualBox hoặc AWS.
CloudCaptain có deep integration với Spring Boot và dùng information từ Spring Boot configuration file để tự động configure port và health check URL.
CloudCaptain dùng information này cho cả image nó tạo lẫn mọi resource nó provision, chẳng hạn instance, security group và elastic load balancer.

Sau khi tạo https://console.cloudcaptain.sh[CloudCaptain account], connect account đó với AWS account, install phiên bản mới nhất của CloudCaptain Client và đảm bảo application đã được build bằng Maven hoặc Gradle, chẳng hạn `mvn clean package`, bạn có thể deploy Spring Boot application lên AWS bằng command tương tự sau:

[source,shell]
----
$ boxfuse run myapp-1.0.jar -env=prod
----

Xem https://cloudcaptain.sh/docs/commandline/run.html[documentation `boxfuse run`] để biết thêm các option.
Nếu có file https://cloudcaptain.sh/docs/commandline/#configuration[`boxfuse.conf`] trong current directory, file đó sẽ được xem xét.

TIP: Mặc định, CloudCaptain activate Spring profile có tên `boxfuse` khi startup.
Nếu executable jar hoặc war chứa file https://cloudcaptain.sh/docs/payloads/springboot.html#configuration[`application-boxfuse.properties`], CloudCaptain base configuration trên các property trong file đó.

[[howto.deployment.cloud.google]]
== Google Cloud

Google Cloud có một số option để launch Spring Boot application.
Có lẽ App Engine là option dễ bắt đầu nhất, nhưng bạn cũng có thể chạy Spring Boot trong container với Container Engine hoặc trên virtual machine với Compute Engine.

Để deploy app đầu tiên lên App Engine standard environment, hãy làm theo https://codelabs.developers.google.com/codelabs/cloud-app-engine-springboot#0[tutorial này].

Ngoài ra, App Engine Flex yêu cầu bạn tạo file `app.yaml` để mô tả các resource app cần.
Thông thường, bạn đặt file này trong `src/main/appengine`, và file này sẽ tương tự file sau:

[source,yaml]
----
service: "default"

runtime: "java17"
env: "flex"

handlers:
- url: "/.*"
  script: "this field is required, but ignored"

manual_scaling:
  instances: 1

health_check:
  enable_health_check: false

env_variables:
  ENCRYPT_KEY: "your_encryption_key_here"
----

Bạn có thể deploy app, chẳng hạn bằng Maven plugin, bằng cách thêm project ID vào build configuration như trong ví dụ sau:

[source,xml]
----
<plugin>
	<groupId>com.google.cloud.tools</groupId>
	<artifactId>appengine-maven-plugin</artifactId>
	<version>2.4.4</version>
	<configuration>
		<project>myproject</project>
	</configuration>
</plugin>
----

Sau đó deploy bằng `mvn appengine:deploy` (bạn cần authenticate trước, nếu không build sẽ fail).
