[[build-image]]
= Packaging OCI Images

Plugin có thể tạo https://github.com/opencontainers/image-spec[OCI image] từ jar hoặc war file bằng https://buildpacks.io/[Cloud Native Buildpacks] (CNB).
Image có thể build trên command line bằng goal `build-image`.
Goal này đảm bảo package lifecycle đã chạy trước khi image được tạo.

NOTE: Vì security, image build và run bằng non-root user.
Xem {url-buildpacks-docs}/reference/spec/platform-api/#users[CNB specification] để biết thêm.

Cách dễ nhất để bắt đầu là invoke `mvn spring-boot:build-image` trên project.
Có thể automate việc tạo image mỗi khi phase `package` được invoke:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$packaging-oci-image/pom.xml[tags=packaging-oci-image]
----

NOTE: Dùng `build-image-no-fork` khi bind goal vào package lifecycle.
Goal này tương tự `build-image` nhưng không fork lifecycle để đảm bảo `package` đã chạy.
Trong phần còn lại, `build-image` dùng để chỉ cả goal `build-image` hoặc `build-image-no-fork`.

TIP: Dù buildpack chạy từ xref:packaging.adoc[executable archive], không cần execute goal `repackage` trước vì executable archive được tự động tạo nếu cần.
Khi `build-image` repackage application, nó apply cùng setting với goal `repackage`, tức dependency có thể exclude bằng option exclude.
Module `spring-boot-devtools` và `spring-boot-docker-compose` mặc định tự động exclude; control bằng property `excludeDevtools` và `excludeDockerCompose`.
Cũng lưu ý optional dependency mặc định không include.
Nếu define các module này optional, cũng cần set `includeOptional` thành `true`.

[[build-image.docker-daemon]]
== Docker Daemon

Goal `build-image` cần access Docker daemon.
Goal inspect local Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration file] để determine current https://docs.docker.com/engine/context/working-with-contexts/[context] và dùng connection information của context communicate với Docker daemon.
Nếu không determine được current context hoặc context không có connection information, goal dùng default local connection.
Điều này hoạt động với https://docs.docker.com/install/[Docker Engine] trên mọi supported platform mà không cần configuration.

Environment variable có thể set để configure `build-image` dùng alternative local hoặc remote connection:

|===
| Environment variable | Mô tả

| DOCKER_CONFIG
| Location Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration file] dùng determine current context (default `$HOME/.docker`)

| DOCKER_CONTEXT
| Name của https://docs.docker.com/engine/context/working-with-contexts/[context] dùng retrieve host information từ Docker CLI configuration file (override `DOCKER_HOST`)

| DOCKER_HOST
| URL chứa host và port của Docker daemon, ví dụ `tcp://192.168.99.100:2376`

| DOCKER_TLS_VERIFY
| Enable secure HTTPS protocol khi set `1` (optional)

| DOCKER_CERT_PATH
| Path tới certificate và key file cho HTTPS (required nếu `DOCKER_TLS_VERIFY=1`, ignore nếu không)
|===

Docker daemon connection information cũng có thể cung cấp bằng parameter `docker` trong plugin configuration:

|===
| Parameter | Mô tả

| `context`
| Name của https://docs.docker.com/engine/context/working-with-contexts/[context] dùng retrieve host information từ Docker CLI https://docs.docker.com/engine/reference/commandline/cli/#configuration-files[configuration file]

| `host`
| URL chứa host và port Docker daemon, ví dụ `tcp://192.168.99.100:2376`

| `tlsVerify`
| Enable secure HTTPS protocol khi set `true` (optional)

| `certPath`
| Path tới certificate/key file cho HTTPS (required nếu `tlsVerify` là `true`, ignore nếu không)

| `bindHostToBuilder`
| Khi `true`, value của property `host` được cung cấp cho container tạo cho CNB builder (optional)
|===

Chi tiết xem xref:build-image.adoc#build-image.examples.docker[examples].

[[build-image.docker-registry]]
== Docker Registry

Nếu Docker image specify bởi parameter `builder` hoặc `runImage` lưu trong private Docker image registry cần authentication, authentication credential có thể cung cấp bằng parameter `docker.builderRegistry`.

Nếu generated Docker image sẽ publish tới Docker image registry, authentication credential có thể cung cấp bằng parameter `docker.publishRegistry`.

Có parameter cho user authentication hoặc identity token authentication.
Xem documentation của Docker registry đang dùng để biết supported authentication method.

Parameter available cho `docker.builderRegistry` và `docker.publishRegistry`:

|===
| Parameter | Mô tả

| `username`
| Username cho Docker image registry user. Required cho user authentication.

| `password`
| Password cho Docker image registry user. Required cho user authentication.

| `url`
| Address Docker image registry. Optional cho user authentication.

| `email`
| E-mail address Docker image registry user. Optional cho user authentication.

| `token`
| Identity token Docker image registry user. Required cho token authentication.
|===

Chi tiết xem xref:build-image.adoc#build-image.examples.docker[examples].

[NOTE]
====
Nếu không cung cấp credential, plugin đọc existing Docker configuration file của user, thường tại `$HOME/.docker/config.json`, để determine authentication method.
Dùng các method này, plugin cố cung cấp authentication credential cho requested image.

Plugin hỗ trợ các authentication method:

- *Credential Helpers*: External tool configure trong Docker configuration file cung cấp credential cho specific registry. Ví dụ `osxkeychain` hoặc `ecr-login` handle authentication cho một số registry.
- *Credential Store*: Default fallback mechanism lưu/retrieve credential an toàn, ví dụ `desktop` cho Docker Desktop.
- *Static Credentials*: Credential lưu trực tiếp trong Docker configuration file dưới section `auths`.
====

[[build-image.customization]]
== Image Customizations

Plugin invoke {url-buildpacks-docs}/for-app-developers/concepts/builder/[builder] để orchestrate generation của image.
Builder include nhiều {url-buildpacks-docs}/for-app-developers/concepts/buildpack/[buildpack] có thể inspect application để influence generated image.
Mặc định plugin chọn builder image.
Name của generated image derive từ project property.

Parameter `image` cho phép configure builder và cách nó operate trên project.
Các parameter available và default:

[cols="1,4,1"]
|===
| Parameter / (User Property)| Mô tả | Default value

| `builder` +
(`spring-boot.build-image.builder`)
| Name builder image dùng.
| `paketobuildpacks/builder-noble-java-tiny:latest`

| `trustBuilder` +
(`spring-boot.build-image.trustBuilder`)
| Có treat builder là {url-buildpacks-docs}/for-platform-operators/how-to/integrate-ci/pack/concepts/trusted_builders/#what-is-a-trusted-builder[trusted] hay không.
| `true` nếu builder thuộc một trong `paketobuildpacks/builder-noble-java-tiny`, `paketobuildpacks/builder-jammy-java-tiny`, `paketobuildpacks/builder-jammy-tiny`, `paketobuildpacks/builder-jammy-base`, `paketobuildpacks/builder-jammy-full`, `paketobuildpacks/builder-jammy-buildpackless-tiny`, `paketobuildpacks/builder-jammy-buildpackless-base`, `paketobuildpacks/builder-jammy-buildpackless-full`, `gcr.io/buildpacks/builder`, `heroku/builder`; nếu không là `false`.

| `imagePlatform` +
(`spring-boot.build-image.imagePlatform`)
a|Platform (operating system và architecture) của builder, run, buildpack image được pull.
Phải ở form `OS[/architecture[/variant]]` như `linux/amd64`, `linux/arm64` hoặc `linux/arm/v5`.
Xem documentation builder đang dùng để determine available image OS/architecture option.
| Không default value, nghĩa là dùng platform host machine.

| `runImage` +
(`spring-boot.build-image.runImage`)
| Name run image dùng.
| Không default; dùng run image specify trong Builder metadata.

| `name` +
(`spring-boot.build-image.imageName`)
| javadoc:org.springframework.boot.buildpack.platform.docker.type.ImageName#of(java.lang.String)[Image name] cho generated image.
| `docker.io/library/` +
`${project.artifactId}:${project.version}`

| `pullPolicy` +
(`spring-boot.build-image.pullPolicy`)
| javadoc:org.springframework.boot.buildpack.platform.build.PullPolicy[Policy] determine khi nào pull builder/run image từ registry.
Accept value `ALWAYS`, `NEVER`, `IF_NOT_PRESENT`.
| `ALWAYS`

| `env`
| Environment variable pass tới builder.
|

| `buildpacks`
a|Buildpack builder dùng khi build image.
Chỉ specified buildpack được dùng, override default buildpack include trong builder.
Buildpack reference phải ở một trong form:

* Buildpack trong builder - `[urn:cnb:builder:]<buildpack ID>[@<version>]`
* Buildpack trong directory filesystem - `[file://]<path>`
* Buildpack trong gzipped tar (.tgz) file - `[file://]<path>/<file name>`
* Buildpack trong OCI image - `[docker://]<host>/<repo>[:<tag>][@<digest>]`
| None, nghĩa là builder dùng buildpack include trong nó.

| `bindings`
a|https://docs.docker.com/storage/bind-mounts/[Volume bind mount] mount vào builder container khi build image.
Binding pass unparsed/unvalidated tới Docker khi create builder container.
Binding phải dạng:

* `<host source path>:<container destination path>[:<options>]`
* `<host volume name>:<container destination path>[:<options>]`

Trong đó `<options>` có thể gồm:

* `ro` mount volume read-only.
* `rw` mount volume readable/writable.
* `volume-opt=key=value` specify key-value option.
|

| `network` + (`spring-boot.build-image.network`)
| https://docs.docker.com/network/#network-drivers[Network driver] builder container dùng.
Value pass unvalidated tới Docker.
|

| `cleanCache` + (`spring-boot.build-image.cleanCache`)
| Có clean cache trước build hay không.
| `false`

| `verboseLogging`
| Enable verbose logging của builder operation.
| `false`

| `publish` + (`spring-boot.build-image.publish`)
| Có publish generated image tới Docker registry hay không.
| `false`

| `tags`
| Một hoặc nhiều additional tag apply cho generated image.
Value phải là *full* image reference.
Xem xref:build-image.adoc#build-image.customization.tags[tags section].
|

| `buildWorkspace`
| Temporary workspace builder/buildpack dùng store file trong image build.
Value có thể là named volume hoặc bind mount location.
| Named volume trong Docker daemon, name derive từ image name.

| `buildCache`
| Cache chứa layer do buildpack tạo và image build process dùng.
Value có thể named volume hoặc bind mount location.
| Named volume trong Docker daemon, name derive từ image name.

| `launchCache`
| Cache chứa layer do buildpack tạo và image launch process dùng.
Value có thể named volume hoặc bind mount location.
| Named volume trong Docker daemon, name derive từ image name.

| `createdDate` +
(`spring-boot.build-image.createdDate`)
| Date dùng set field `Created` trong metadata generated image.
Value phải ISO 8601 instant format hoặc `now` để dùng current date/time.
| Fixed date enable {url-buildpacks-docs}/for-app-developers/concepts/reproducibility/[build reproducibility].

| `applicationDirectory` +
(`spring-boot.build-image.applicationDirectory`)
| Path tới directory application content upload vào builder image.
Application content cũng ở location này trong generated image.
| `/workspace`

| `securityOptions`
| https://docs.docker.com/reference/cli/docker/container/run/#security-opt[Security option] apply cho builder container, array string.
| `["label=disable"]` trên Linux/macOS, `[]` trên Windows

|===

NOTE: Plugin detect target Java compatibility của project bằng compiler plugin configuration hoặc property `maven.compiler.target`.
Khi dùng default Paketo builder/buildpack, plugin instruct buildpack install cùng Java version.
Có thể override behavior như trong xref:build-image.adoc#build-image.examples.builder-configuration[builder configuration].

Chi tiết xem xref:build-image.adoc#build-image.examples[examples].

[[build-image.customization.tags]]
=== Tags Format

Value cung cấp cho option `tags` phải là *full* image reference.
Accepted format: `[domainHost:port/][path/]name[:tag][@digest]`.

Nếu domain thiếu, default `docker.io`.
Nếu path thiếu, default `library`.
Nếu tag thiếu, default `latest`.

Ví dụ:

* `my-image` -> `docker.io/library/my-image:latest`
* `my-repository/my-image` -> `docker.io/my-repository/my-image:latest`
* `example.com/my-repository/my-image:1.0.0` dùng nguyên.
