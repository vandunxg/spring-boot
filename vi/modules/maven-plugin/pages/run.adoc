[[run]]
= Running your Application with Maven

Plugin có goal `run` dùng launch application từ command line:

[source,shell]
----
$ mvn spring-boot:run
----

Application argument có thể specify bằng parameter `arguments`; xem xref:run.adoc#run.examples.using-application-arguments[using application arguments].

Application execute trong forked process nên set property trên command line không ảnh hưởng application.
Nếu cần specify JVM argument, ví dụ debugging, dùng parameter `jvmArguments`; xem xref:run.adoc#run.examples.debug[Debug the application].
Cũng có explicit support cho xref:run.adoc#run.examples.system-properties[system properties] và xref:run.adoc#run.examples.environment-variables[environment variables].

Vì enable profile khá phổ biến, có dedicated property `profiles` là shortcut cho `-Dspring-boot.run.jvmArguments="-Dspring.profiles.active=dev"`; xem xref:run.adoc#run.examples.specify-active-profiles[Specify active profiles].

Spring Boot `devtools` là module cải thiện development-time experience khi làm Spring Boot application.
Để enable, thêm dependency:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$running/devtools-pom.xml[tags=devtools]
----

Khi `devtools` chạy, nó detect change khi recompile application và tự động refresh.
Điều này hoạt động cho cả resource và code.

Devtools cũng có thể configure chỉ refresh browser khi static resource thay đổi, ignore code change.
Để làm vậy, disable devtools code-change restart bằng property sau:

[configprops%novalidate,yaml]
----
spring:
  devtools:
    restart:
      enabled: false
----

Trước `devtools`, plugin mặc định hỗ trợ hot refresh resource; feature này giờ disable để ưu tiên solution trên.
Có thể restore bất kỳ lúc nào bằng configuration:

[source,xml,subs="verbatim,attributes"]
----
include::example$running/hot-refresh-pom.xml[tags=hot-refresh]
----

Khi `addResources` enable, mọi directory `src/main/resources` được thêm vào application classpath khi chạy application và duplicate trong classes output bị remove.
Điều này cho phép hot refresh resource, rất hữu ích khi develop web application.
Ví dụ có thể làm việc trên HTML, CSS hoặc JavaScript và thấy change ngay mà không recompile application.
Nó cũng giúp front-end developer làm việc mà không cần download/install Java IDE.

NOTE: Side effect của feature này là filtering resource ở build time không hoạt động.

Để consistent với goal `repackage`, goal `run` build classpath sao cho dependency bị exclude trong plugin configuration cũng bị exclude khỏi classpath.
Chi tiết xem xref:packaging.adoc#packaging.examples.exclude-dependency[dedicated example].

Đôi khi hữu ích khi chạy test variant của application.
Ví dụ nếu muốn xref:reference:features/dev-services.adoc#features.dev-services.testcontainers.at-development-time[dùng Testcontainers tại development time] hoặc dùng test stub.
Dùng goal `test-run` với nhiều feature và configuration option giống `run`.

=== Debug Application

Goal `run` và `test-run` chạy application trong forked process.
Nếu cần debug, thêm JVM argument cần để enable remote debugging.
Configuration sau suspend process cho tới khi debugger join port 5005:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$running/debug-pom.xml[tags=debug]
----

Argument này cũng có thể specify trên command line:

[source,shell]
----
$ mvn spring-boot:run -Dspring-boot.run.jvmArguments=-agentlib:jdwp=transport=dt_socket,server=y,suspend=y,address=*:5005
----

[[run.examples.system-properties]]
=== Dùng System Properties

System property có thể specify bằng attribute `systemPropertyVariables`.
Ví dụ set `property1` thành `test` và `property2` thành 42:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$running/system-properties-pom.xml[tags=system-properties]
----

Nếu value rỗng hoặc không define, tức `<my-property/>`, system property được set với empty String.
Maven trim value specify trong POM nên không thể specify System property cần bắt đầu hoặc kết thúc bằng space qua mechanism này; dùng `jvmArguments` thay thế.

Mọi Maven variable type String có thể pass làm system property.
Attempt pass Maven variable type khác, ví dụ `List` hoặc `URL`, khiến variable expression được pass literal, không evaluate.

Parameter `jvmArguments` có precedence hơn system property define bằng mechanism trên.
Ví dụ sau value `property1` là `overridden`:

[source,shell]
----
$ mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Dproperty1=overridden"
----

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$running/environment-variables-pom.xml[tags=environment-variables]
----

Nếu value rỗng hoặc không define, tức `<MY_ENV/>`, env variable được set empty String.
Maven trim value trong POM nên không thể specify env variable cần bắt đầu/kết thúc bằng space.

Mọi Maven variable type String có thể pass làm system property.
Attempt pass type khác như `List` hoặc `URL` khiến variable expression được pass literal, không evaluate.

Environment variable define theo cách này có precedence hơn existing value.

[[run.examples.using-application-arguments]]
=== Dùng Application Arguments

Application argument có thể specify bằng attribute `arguments`.
Ví dụ set hai argument `property1` và `property2=42`:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$running/application-arguments-pom.xml[tags=application-arguments]
----

Trên command line, argument phân tách bằng space giống `jvmArguments`.
Nếu argument chứa space, nhớ quote.
Ví dụ sau có hai argument `property1` và `property2=Hello World`:

[source,shell]
----
$ mvn spring-boot:run -Dspring-boot.run.arguments="property1 'property2=Hello World'"
----
