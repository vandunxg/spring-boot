[[aot]]
= Xử lý Ahead-of-Time

Spring AOT là một process phân tích application tại build-time và tạo ra một version đã được optimize.
Đây là bước bắt buộc để chạy Spring `ApplicationContext` trong một native image.

NOTE: Để xem tổng quan về support cho GraalVM Native Images trong Spring Boot, xem xref:reference:packaging/native-image/index.adoc[tài liệu tham khảo].

Spring Boot Maven plugin cung cấp các goal có thể dùng để thực hiện AOT processing trên cả application code và test code.

== Xử lý Application

Để configure application sử dụng feature này, thêm một execution cho goal `process-aot`, như trong ví dụ sau:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$aot/pom.xml[tags=aot]
----

Vì `BeanFactory` được chuẩn bị đầy đủ tại build-time, các condition cũng được evaluate.
Điều này khác biệt đáng kể so với cách một regular Spring Boot application hoạt động tại runtime.
Ví dụ, nếu muốn opt-in hoặc opt-out một số feature, bạn cần configure environment được sử dụng tại build-time để thực hiện việc đó.
Vì lý do này, goal `process-aot` dùng chung một số property với xref:run.adoc[run goal].




[[aot.processing-applications.using-the-native-profile]]
=== Sử dụng Native Profile

Nếu sử dụng `spring-boot-starter-parent` làm `parent` của project, bạn có thể sử dụng profile `native` để rút gọn các step cần thiết nhằm build một native image.

Profile `native` cấu hình các nội dung sau:

* Thực thi `process-aot` khi Spring Boot Maven Plugin được áp dụng trên một project.
* Các setting phù hợp để xref:build-image.adoc[build-image] tạo ra một native image.
* Các default hợp lý cho {url-native-build-tools-docs-maven-plugin}[Native Build Tools Maven Plugin], cụ thể:
** Đảm bảo plugin sử dụng raw classpath, thay vì main jar file, vì plugin không hiểu repackaged jar format của chúng ta.
** Xác thực rằng có sẵn một phiên bản GraalVM phù hợp.
** Download third-party reachability metadata.

[WARNING]
====
Việc sử dụng raw classpath có nghĩa là native image không biết về `MANIFEST.MF` được generate.
Nếu cần đọc content của manifest trong native image, chẳng hạn để lấy implementation version của application, hãy configure option `classesDirectory` để sử dụng regular jar.
====

Để sử dụng profile `native`, một module đại diện cho một application nên define hai plugin, như trong ví dụ sau:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$aot-native/pom.xml[tags=aot-native]
----

Một project đơn có thể trigger việc tạo native image trên command line bằng xref:how-to:native-image/developing-your-first-application.adoc#howto.native-image.developing-your-first-application.buildpacks.maven[Cloud Native Buildpacks] hoặc xref:how-to:native-image/developing-your-first-application.adoc#howto.native-image.developing-your-first-application.native-build-tools.maven[Native Image Build Tools].

Để sử dụng profile `native` với một multi-module project, bạn có thể tạo một customization của profile để sử dụng phương pháp ưa thích.

Để bind Cloud Native Buildpacks trong phase `package`, thêm nội dung sau vào root POM của multi-module project:

[source,xml,indent=0,subs="verbatim,attributes"]
----

----

Ví dụ sau làm tương tự cho Native Build Tools:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$aot-native-profile-nbt/pom.xml[tags=profile]
----

Sau khi thực hiện các bước trên, bạn có thể build multi-module project và tạo native image trong các sub-module liên quan, như trong ví dụ sau:

[source,shell]
----
$ mvn package -Pnative
----

NOTE: Một sub-module "liên quan" là một module đại diện cho một Spring Boot application.

[[aot.processing-tests]]
== Xử lý Test

AOT engine có thể được áp dụng cho các JUnit 5 test sử dụng Spring Test Context Framework.
Các test đó được AOT engine process rồi execute trong một native image.

NOTE: Test không được process khi regular test bị skip bằng property `maven.test.skip`.

Giống như <<aot.processing-applications.using-the-native-profile,code production>>, `spring-boot-starter-parent` define một profile `nativeTest` có thể dùng để rút gọn các step cần thiết nhằm execute test trong một native image.

Profile `nativeTest` cấu hình các nội dung sau:

* Thực thi `process-test-aot` khi Spring Boot Maven Plugin được áp dụng trên một project.
* Thực thi `test` khi {url-native-build-tools-docs-maven-plugin}[Native Build Tools Maven Plugin] được áp dụng trên một project.
Execution này define các default hợp lý, cụ thể:
** Đảm bảo plugin sử dụng raw classpath, thay vì main jar file, vì plugin không hiểu repackaged jar format của chúng ta.
** Xác thực rằng có sẵn một phiên bản GraalVM phù hợp.
** Download third-party reachability metadata.

Để sử dụng profile `nativeTest`, một module đại diện cho một application nên define hai plugin, như trong ví dụ sau:

[source,xml,indent=0,subs="verbatim,attributes"]
----
include::example$aot-native/pom.xml[tags=aot-native]
----

Sau khi setup cho mỗi module cần feature này, bạn có thể build multi-module project và execute test trong một native image ở các sub-module liên quan, như trong ví dụ sau:

[source,shell]
----
$ mvn test -PnativeTest
----

NOTE: Cũng như application AOT processing, `BeanFactory` được chuẩn bị đầy đủ tại build-time.
