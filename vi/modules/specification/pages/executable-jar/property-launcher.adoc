= Các feature của PropertiesLauncher

javadoc:org.springframework.boot.loader.launch.PropertiesLauncher[] có một vài feature đặc biệt có thể được bật bằng các external properties (System property, environment variable, manifest entry hoặc `loader.properties`).
Bảng sau mô tả các property này:

|===
| Key | Mục đích

| `loader.path`
| Classpath phân tách bằng dấu phẩy, chẳng hạn `lib,$\{HOME}/app/lib`.
  Các entry đứng trước có precedence cao hơn, giống `-classpath` thông thường trên command line `javac`.

| `loader.home`
| Dùng để resolve các relative path trong `loader.path`.
  Ví dụ, với `loader.path=lib` thì `${loader.home}/lib` là một classpath location (cùng với mọi jar file trong directory đó).
  Property này cũng được dùng để locate một file `loader.properties`, như trong ví dụ `file:///opt/app`. Mặc định là `${user.dir}`.

| `loader.args`
| Các argument mặc định cho main method (phân tách bằng dấu cách).

| `loader.main`
| Tên của main class cần launch (ví dụ, `com.app.Application`).

| `loader.config.name`
| Tên của file properties (ví dụ, `launcher`).
  Mặc định là `loader`.

| `loader.config.location`
| Path tới file properties (ví dụ, `classpath:loader.properties`).
  Mặc định là `loader.properties`.

| `loader.system`
| Boolean flag cho biết mọi property có được thêm vào System properties hay không.
  Mặc định là `false`.
|===

Khi được chỉ định dưới dạng environment variable hoặc manifest entry, nên dùng các tên sau:

|===
| Key | Manifest entry | Environment variable

| `loader.path`
| `Loader-Path`
| `LOADER_PATH`

| `loader.home`
| `Loader-Home`
| `LOADER_HOME`

| `loader.args`
| `Loader-Args`
| `LOADER_ARGS`

| `loader.main`
| `Start-Class`
| `LOADER_MAIN`

| `loader.config.location`
| `Loader-Config-Location`
| `LOADER_CONFIG_LOCATION`

| `loader.system`
| `Loader-System`
| `LOADER_SYSTEM`
|===

TIP: Build plugins tự động move attribute `Main-Class` sang `Start-Class` khi uber jar được build.
Nếu dùng cách đó, hãy chỉ định tên class cần launch bằng attribute `Main-Class` và bỏ `Start-Class`.

Các quy tắc sau áp dụng khi làm việc với javadoc:org.springframework.boot.loader.launch.PropertiesLauncher[]:

* `loader.properties` được tìm trong `loader.home`, rồi tới gốc của classpath, rồi tới `classpath:/BOOT-INF/classes`.
  Location đầu tiên có file mang tên đó sẽ được dùng.
* `loader.home` là directory location của một properties file bổ sung (override default) chỉ khi `loader.config.location` không được chỉ định.
* `loader.path` có thể chứa các directory (được scan đệ quy để tìm jar và zip file), archive path, một directory bên trong archive được scan để tìm jar file (ví dụ, `dependencies.jar!/lib`), hoặc wildcard pattern (theo behavior mặc định của JVM).
  Archive path có thể relative so với `loader.home` hoặc ở bất kỳ đâu trong file system với prefix `jar:file:`.
* `loader.path` (nếu empty) mặc định là `BOOT-INF/lib` (nghĩa là một local directory hoặc một nested directory nếu chạy từ archive).
  Vì vậy, javadoc:org.springframework.boot.loader.launch.PropertiesLauncher[] behave như javadoc:org.springframework.boot.loader.launch.JarLauncher[] khi không có additional configuration.
* `loader.path` không thể được dùng để configure location của `loader.properties` (classpath dùng để search file này là JVM classpath khi javadoc:org.springframework.boot.loader.launch.PropertiesLauncher[] được launch).
* Placeholder replacement được thực hiện từ System properties và environment variables, cùng với chính properties file, trên mọi value trước khi sử dụng.
* Thứ tự search properties (khi có nhiều nơi để search) là environment variables, system properties, `loader.properties`, manifest của exploded archive, rồi tới archive manifest.
